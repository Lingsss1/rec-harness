# 推荐模型研究 Agent：对齐人类迭代 loop 的首版方案

日期：2026 年 11 月 3 日。状态：方法设计，尚未运行实验。

当前目标是跑通固定的研究过程：读取业务、上下文和代码，结合知识发现差距，提出可检验假说，分配预算做实验，再用结果指导下一轮。腾讯广告大赛是当前任务环境，具体数据与评价见 [任务方案](taac2025-research-loop-v1.md)。本方案描述 Agent 怎样研究。

实现基础采用 [Karpathy autoresearch 适配方案](karpathy-recommendation-autoresearch-v0.md)：保留单编码 Agent 的修改、实验和保留/回退循环，加入知识对照、诊断和归因；RecHarness 作为可复用组件来源。首版实现见 [运行入口](../examples/recommendation_autoresearch/README.md)，真实数据和研究效用留待服务器验收。

暂不实现 RSI，也不实现人的交互、审核、个人 taste 蒸馏或个人知识更新。个人知识可以作为可选的只读输入，没有该输入时流程照常运行。

## 1. 主流程

```text
输入：业务目标 + 数据/实验上下文 + 当前代码
                         ↓
查看模型结构、特征、训练与评价现状
                         ↓
检索相关 Paper/行业方案 + 可选个人知识 + Agent 场景经验
                         ↓
将当前实现和表现与适用经验对照，形成 diff 并诊断
                         ↓
判断收益可能性、证据缺口与代价，形成具体修改假说
                         ↓
选择实验，分配实现、训练、诊断与复验预算
                         ↓
实现/检查 → 运行实验 → 收集结果和分析
                         ↓
联合本轮和历史实验轨迹归因 → 保留/放弃/补证据
                         ↓
更新逐轮记录与待解问题 → 回到现状和 diff

研究阶段结束 → 归并 Agent 场景经验 → 后续研究检索使用
Paper/行业来源独立追新 → 新版本从后续轮次开始使用
```

每轮不必修改模型。信息不足时可以先补测量、做消融或复验；预算耗尽或没有值得验证的方向时结束研究阶段。

## 2. 输入和研究状态

| 输入 | 最少需要什么 | 用途 |
| --- | --- | --- |
| 业务 | 目标指标、约束、允许修改的范围、可确认的场景含义 | 定义什么算收益、什么不可改 |
| 上下文 | 数据划分、特征说明、评价协议、资源预算、历史实验及未解问题 | 判断经验是否适用，保证实验可比 |
| 代码 | 当前父版本、模型和特征处理、损失、训练/推理配置 | 确认模型实际做了什么 |
| 当前证据 | 指标、分组结果、训练曲线、已有诊断及运行错误 | 区分实现问题、效果问题和信息不足 |

首次运行先建立基线状态。后续每轮读取选定父版本及其证据；父版本选择先采用固定规则，例如优先选择满足约束且经确认的最佳版本，也允许为隔离原因回到已记录的其他版本。所有选择记录理由。

## 3. 三类知识如何组织和更新

| 知识 | 内容与用途 | 当前更新方式 |
| --- | --- | --- |
| Paper/行业知识 | 论文、公开方案、可信网站或作者的经验；作为方向与机制的参考 | 独立追新，按相关性、来源质量与领域关注度筛选；保留来源和版本。实验结果不改写外部原始主张 |
| 个人知识 | 人提供的业务判断、偏好、约束、经验与反例 | 当前仅可选只读快照。Agent 不修改，不实现审核与 taste 学习 |
| Agent 场景知识 | 在具体数据、模型和资源条件下，经实验形成的成功经验、失败反例与适用边界 | 研究阶段结束后慢速归并；每轮结果先进入实验记录，不立即变成长期经验 |

一次检索按当前问题选择相关内容，不将整个知识库全部塞入上下文。外部检索可以在研究中触发；本轮已使用的来源快照固定，后续更新另记版本。来源热度只帮助发现信息，不作为方法有效的证据。

经验统一围绕用户提出的四个字段组织：

```text
场景：任务、数据与模型条件，适用范围
方法：做了什么，作用于哪个推荐系统模块
收益：相对什么基线、什么指标、什么资源下的观测；未验证则留空
原因：机制解释，以及它是推测、相关证据还是干预实验支持
```

同时绑定来源/实验 ID 和反例。可按特征、序列、表示与融合、目标与采样、训练、检索等模块索引。同一方法在不同场景下结果相反时保留条件和冲突，不强行合并为一条通用结论。

人的明确约束优先于 Agent 推测。外部主张、个人判断、本地观测分别保留来源；约束不能替代效果证据。当前不提供任何 Agent 写入个人知识的路径。

## 4. 每一步具体做什么

| 步骤 | 读取 | 输出 | LLM 与程序分别负责什么 |
| --- | --- | --- | --- |
| ① 查看现状 | 业务约束、当前代码/配置、特征统计、指标与日志 | 当前模型画像、已知异常、缺失信息 | 程序提取可测统计；LLM 阅读代码与证据，解释结构和问题 |
| ② 检索经验 | 模型画像、当前问题、三类知识和实验索引 | 相关经验、适用条件、支持与反例、来源版本 | 程序检索和过滤；LLM 判断与本场景的关系 |
| ③ Diff 与诊断 | 当前状态、适用经验、历史实验 | 差距、竞争解释、关键证据缺口 | LLM 提出解释；程序运行已有诊断并返回测量，不把解释当结论 |
| ④ 判断并提出假说 | 差距、诊断结果、可改范围、剩余预算 | 一个主假说、具体改动、预期现象、证伪条件 | LLM 推理机制与实验方案；规则检查范围、可执行性与是否已有重复实验 |
| ⑤ 分配预算 | 假说、基线成本、所需对照与复验 | 实验计划、控制变量、资源额度、停止条件 | LLM 建议配置；程序核算预算并执行硬限制 |
| ⑥ 实验和分析 | 父代码、变更计划、固定评价协议 | 代码 diff、实际配置、权重/预测、指标、诊断、成本和失败日志 | LLM 辅助实现与解释；程序执行检查、训练、评分、统计和产物记录 |
| ⑦ 多轨迹归因 | 本轮结果、同类历史实验、反例和待解问题 | 假说支持状态、保留决策、下一轮补证据计划 | 程序对齐实验条件、汇总差异；LLM 比较解释并识别尚不能归因的部分 |
| ⑧ 进入下一轮 | 归因、可用候选、剩余预算 | 下一轮父版本、问题和可读证据；或阶段结束总结 | 固定规则约束保留和预算；LLM 选择值得继续研究的问题 |

“可能带来收益”是实验前的研究判断：适用条件是否满足、机制是否合理、现有证据是否足够、代价是否值得。它不等于已证明涨点，也不要求 LLM 编造收益数值。

Diff 不只是文本或代码差异。例如，“外部方案利用行为类型，而当前模型没有区分行为”是方法差距；“当前某类行为样本排名更差”是观测；“缺少行为条件导致这类样本变差”才是需要验证的解释。

## 5. 多轨迹归因怎样做

这里的轨迹以研究实验为单位：现状与知识 → 假说 → 代码/配置变更 → 运行结果 → 诊断 → 保留决定。工具调用日志保留为辅助证据，重点分析模型实验的差异。

1. **先分组再对比。** 根据任务/数据版本、评价协议、父版本、改动类型、训练预算组织轨迹；条件不同的结果不能直接相减。实现错误和任务效果分开记录。
2. **挑选有信息的轨迹。** 重点读重复出现的正例、幅度较大的负例、相互矛盾的结果，以及能区分解释的对照。完整实验账本保留所有失败与无收益记录，避免只总结成功。
3. **核查重复与噪声。** 同一祖先衍生的相近实验不能算成多份独立证据。“高频”需记录覆盖了哪些条件；“显著”需有噪声/重复实验支持，只有一次运行时表述为负向观测。
4. **提出下一步干预。** 例如改动同时增加参数量与引入行为信息，先补参数量匹配对照；若训练没有收敛，先核查训练公平性。对解释有分歧时优先做能区分解释的实验。
5. **分开记录效果与原因。** 保留一个有效候选不要求所有机制都已证实；未证实的原因继续标注未知。分组改善也不能单独证明因果。

归因输出必须能够改变下一轮行动，例如补某个对照、放弃某类假说、缩小适用条件或切换研究方向。

## 6. 逐轮反馈与慢速知识更新

| 状态 | 何时更新 | 下一轮如何使用 |
| --- | --- | --- |
| 实验账本与产物 | 每次实验结束立即追加，错误和无收益也记录 | 查询原始证据，避免重复试错 |
| 当前工作状态 | 每轮归因后更新 | 携带父版本、待解问题、证据缺口、下一步与剩余预算 |
| Agent 长期场景经验 | 一个研究阶段结束后归并 | 形成带条件、证据和反例的可检索经验 |

具体归并频率和粒度暂不定死。首版用“研究阶段结束”作为归并时点；阶段可以以预算用尽、方向研究完成或主动停止为结束条件。即使长期知识尚未更新，下一轮也能直接读取刚结束的实验。

暂不做基于实验的自动知识权重学习；先显式记录证据状态、适用条件、支持与反例。知识库结构、诊断工具、检索方式和整个流程保持固定。

## 7. 一条完整的示意迭代

以下是流程示意，没有对应已完成的腾讯赛题实验：

```text
现状：当前实现未显式区分行为类型，某行为分组的排名表现较差
读取：相关行业方案 + 既有场景经验 + 可选个人知识 + 当前统计/代码
Diff：外部方案有行为条件设计；当前实现缺少该机制
诊断：检查行为字段是否可靠、分组样本量及特征处理是否正确
假说：显式行为条件有助于区分不同反馈，改善相应分组及整体排名
替代解释：收益可能只是参数量增加；分组差异可能来自样本量
预算：先估算训练成本，预留基线、候选、匹配对照和必要复验额度
实验：从同一父版本构造候选与参数量匹配对照，保持评价协议一致
结果：读取整体/分组指标、训练动态、运行成本及历史相关实验
归因：若候选和匹配对照同幅改善，不能声称行为语义是主要原因
下一轮：围绕未区分开的解释追加实验，或转向其他信息缺口
阶段结束：将适用场景、具体方法、实测收益和原因状态归并为经验
```

## 8. 首版实现边界和验收

先用一个主研究 Agent 配合代码、训练、检索、评分与诊断工具运行。查看、提出、实现、检查、归因是流程职责，不要求部署多个独立 Agent。

当前实现范围是固定研究流程、知识读取、实验记录和阶段经验归并。人工审核界面、个人知识写入、个人 taste 学习、诊断工具演化、搜索策略自改和流程自改均留待后续。

跑通的最低要求是：基线和评价可复现，至少连续两轮真实研究，每轮的知识引用、diff、假说、实验、成本和结论可追溯；第二轮明确因上一轮证据改变了什么行动。阶段结束的经验可以追溯回原始实验。

这只能证明流程可执行。若要验证方法有价值，还需在相同起点与总资源下，与普通模型迭代以及去知识/去诊断条件比较；报告最终效果、达到同等效果的成本、失败实验成本，并在多次研究运行中检查稳定性。
