# 基于 Karpathy autoresearch 的推荐模型研究方案

日期：2026 年 11 月 3 日。任务为腾讯广告大赛 2025 初赛。首版已实现数据适配、训练、独立评价和基础/知识增强两种研究循环；运行说明见 [实现入口](../examples/recommendation_autoresearch/README.md)。本地使用合成原生格式数据执行 CPU 训练和进程协议验证，真实数据、GPU 及真实 LLM 研究效用留待服务器验收。

首版以 Karpathy autoresearch 的单 Agent 编码循环为主干，在每次编辑前加入知识对照与诊断，在实验后加入归因和跨轮证据。原有 RecHarness 的证据合同、检查和评分实现可按需复用，不作为主控制器。

## 1. 基础版本与继承边界

上游：[karpathy/autoresearch](https://github.com/karpathy/autoresearch)。本地参考副本为 `/Users/linghaoran/Documents/ChatGPT/benchmark/autoresearch-source`，读取时 commit 为 `228791fb499afffb54b46200aca536f79142f117`。此处使用该固定版本作设计依据，不宣称已建立可执行 fork。

原版通过 `program.md` 指导编码 Agent 修改 `train.py`，运行固定五分钟训练，读取 `val_bpb`，记录 `results.tsv` 并保留或回退。`prepare.py` 中的数据和评价保持固定。它允许 Agent 阅读论文和历史结果，也有复杂度方面的保留裁量；本方案不把“读论文”和“记录结果”本身视为新增能力。[原始指令](https://github.com/karpathy/autoresearch/blob/228791fb499afffb54b46200aca536f79142f117/program.md)

| 原版部分 | 推荐任务适配 |
| --- | --- |
| 单 Agent 自主编辑、实验和继续研究 | 保留，不要求四个独立角色或服务 |
| `program.md` 组织研究行为 | 保留，加入知识对照、诊断和归因要求；运行中固定，不自改 |
| `train.py` 承载可编辑训练代码 | 改为推荐模型、训练目标、训练负采样及推理实现；以明确文件清单控制范围 |
| `prepare.py` 固定任务与评价 | 保留职责边界：固定数据切分、目标构造、允许输入、候选池和评分 |
| 五分钟训练与 `val_bpb` | 替换为赛题指标和校准后的训练/检索/评分预算 |
| `results.tsv` 与 keep/discard/crash | 保留简表；增加原始证据、假说、诊断及解释，错误分数为空 |
| 从 incumbent 继续编辑 | 默认保留，机制对照使用独立副本，记录真实父版本 |

腾讯任务具体数据和评价依照 [任务方案](taac2025-research-loop-v1.md)。原版 GPT 训练代码和 tokenizer 不作为腾讯模型起点，模型从腾讯官方 baseline 适配。

## 2. 修改后的循环

```text
读取当前 incumbent 的代码、配置、指标和历史实验
                         ↓
检索 Paper/行业经验、可选个人知识和 Agent 场景经验
                         ↓
列出候选 diff：当前事实 vs 经验适用条件
                         ↓
检查已有证据；必要时先调用固定诊断工具补测量
                         ↓
比较候选方向，选一条主假说或一个补证据实验
                         ↓
冻结假说、证伪条件、控制变量、来源和预算
                         ↓
Agent 直接编辑候选代码 → 执行检查 → 训练/推理/独立评分
                         ↓
追加完整实验记录 → 程序按固定规则保留/放弃
                         ↓
Agent 对照历史轨迹归因，更新下一轮问题
                         ↓
从当前 incumbent 继续；研究阶段结束后归并场景经验
```

LLM 负责理解源码、筛选经验、解释差异、提出假说、编辑代码和归因；程序负责身份与范围检查、测量、执行、评分、预算及保留规则。证据引用合法不等于解释正确。

## 3. 首版新增的四项能力

### 3.1 经验检索与适用性对照

先使用少量人工整理的公开经验卡，不先开发复杂知识图。经验卡包含场景、方法、作者报告收益、原因、适用条件、来源版本与反例；作者收益与本地结果分开。

每轮根据模型状态、失败现象和当前研究模块检索相关条目，同时查本地失败和无收益记录。仅有模型引用字符串时，标记来源未核验；不得当成已读取的正文。Paper 独立追新，本轮来源快照固定。个人知识仅可选只读。

### 3.2 结构化 diff 与诊断

每个候选差距至少记录：

```text
当前事实及证据位置
经验主张、来源和适用条件
条件匹配：满足 / 不满足 / 未知 / 冲突
对应本地现象与历史反证
竞争解释及尚缺证据
最便宜的区分性测量或实验
预估成本、优先级理由及本轮是否选择
```

不要求诊断完所有原因才允许探索。证据不足但机会明确时可以探索，标记其不确定性。若存在任务/评分/数据错误，先修复基线，不把修复算成模型方法收益。

首批诊断围绕一个案例接入：目标与随机非目标广告的分差、目标完整候选排名、ANN 对照精确检索的差异、训练动态及分组结果。使用同一固定开发查询与一致的模型打分规则；查询可以抽样，排名候选池不因此缩小。诊断开销计费，结论不能仅靠 Agent 自报。

### 3.3 实验与结果合同

每轮在运行前冻结一个主假说、具体改动、比较对象、必要对照、预期现象、证伪条件和预算。实现后检查实际代码 diff 是否符合声明；机制对照必须检查其确实隔离了所称因素。

`results.tsv` 提供速览，逐实验目录保留完整资料：

| 记录 | 内容 |
| --- | --- |
| `design.json` | 状态摘要、候选 diff、来源引用、选择理由、假说、控制变量和预算 |
| `diagnostics.json` | 测量定义、输入/模型身份、观测、成本和限制 |
| `execution.json` | 父/候选身份、代码差异、实际配置、命令、种子、产物和状态 |
| `metrics.json` | 独立评分、分组样本量、资源与协议身份；失败不伪造分数 |
| `analysis.md` | 效果与机制分开、竞争解释、历史对照和下一轮行动 |

首版实现将这些职责落为逐 trial 的 `context.json`、`design.json`、`code.diff`、`receipt.json`，逐 seed 的训练/推理回执和 `metrics.json`，以及增强模式的 `diagnostics.json`、`analysis.json`。记录与实际候选、checkpoint、预测及独立评分绑定。

### 3.4 跨轮反馈和阶段归并

所有实验包含失败、无收益和对照，完成即追加证据，下一轮可以读取。归因时先检查任务、父版本、协议和训练预算是否可比，再汇总重复正例、负例和矛盾；相似谱系不冒充独立重复。

每轮解释保持 provisional/unknown。研究阶段结束时，将“场景＋方法＋收益＋原因”及证据和反例归并到 Agent 场景知识。Paper 原始主张和个人知识不由实验覆盖。

## 4. 对原版预算与保留规则的明确调整

五分钟不直接迁移。先校准基线训练、建索引、全候选检索和评分成本，再冻结每候选资源上限与总研究预算，失败、诊断、归因对照和复验均计入成本。快速试跑可检查工程问题，不用于断言完整训练收益。

首版默认采用资源约束下的任务分数改进作为候选保留依据，确认规则和重复种子在校准后冻结。开发证据用于提出假说；确认调用限次并记录；最终留出评价仅在研究提交冻结后执行。归因实验应采用可对齐的训练设置，另报告相同资源下的实用效果。

原版“近似同分但更简单也可以保留”的裁量暂不纳入自动保留，保持可执行规则清楚。模型是否保留与机制是否得到支持分开记录。不直接继承无限运行要求；停止于总预算、已声明结束条件或用户中止。

实验使用专属目录保存 incumbent、候选和对照。回退仅作用于该研究的候选状态，不能对用户共享工作目录执行破坏性 Git 回退。即使候选被放弃，其代码和结果仍保留。

## 5. 最小实施顺序和比较方式

1. **赛题适配。** 冻结腾讯 baseline、数据和本地评价，跑通一次真实基线及重复校准。
2. **普通 autoresearch。** 单 Agent 直接编辑，执行同一训练/评价，记录并 keep/discard，连续运行两轮。
3. **加入知识对照。** 接入初始经验卡和结构化 diff，记录选择及暂缓理由。
4. **加入诊断与归因。** 先跑通负采样案例；按必要性执行对照，下一轮必须引用前轮证据。
5. **阶段归并。** 实验结束汇总经验，并验证后续研究能追溯其原始依据。

验证研究方法时，对照应为“同一腾讯任务适配下的普通 autoresearch”，共享模型起点、Agent 模型、执行器、评价、预算和保留规则；再比较加入知识、诊断后的增量。普通组仍允许自主分析日志和公开检索，具体工具权限事先声明。若要单独归因结构化 diff 的价值，需让各组看到相同的外部资料，并记录实际阅读内容。

对比最终留出效果、达到同等效果的成本、失败成本及多次研究稳定性。不能将超过原始 GPT 任务或旧 NextItNet 框架作为方法有效的证据。

## 6. 当前交付

已提供 [Agent 指令](../examples/recommendation_autoresearch/program.md)、[运行说明与配置](../examples/recommendation_autoresearch/README.md) 和 `python -m recevobench.taac` 入口。基础模式支持候选编辑、真实训练、精确全候选检索、独立评分、保留/回退、失败计费和恢复；增强模式加入 Agent 动态检索计划、BM25＋语义向量混合召回、显式关联反例补齐、Agent 适用性判断、diff 与描述性诊断及阶段经验导出。检索后端可替换，不做 GraphRAG；完整协议见上述运行说明。

当前 gate 用于结束审计，最终模型由 feedback 选择；真实编码 Agent 通过用户配置的 argv 接入。尚未实现 ANN、在线来源追新、自动生成归因对照、阶段经验的跨场景归并或容器隔离。这些能力不作为首版已完成的验收声明。
