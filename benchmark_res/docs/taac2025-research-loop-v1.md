# 腾讯广告大赛 2025 固定研究流程方案

日期：2026 年 11 月 3 日。已确定采用 2025 腾讯广告算法大赛初赛 TencentGR-1M；千级长序列不再是要求。首版已实现固定研究 loop，见 [运行说明](../examples/recommendation_autoresearch/README.md)。本地执行合成数据 CPU 训练与集成测试，真实服务器验收后续进行；不做 RSI 模块或可插拔框架。

## 1 任务和评价口径

任务是给定用户侧信息、广告行为历史和可用多模态特征，预测下一次点击的广告，从官方候选广告池返回 Top-10。使用初赛的曝光/点击定义，不引入复赛转化加权规则，也不改造成 CTR 二分类。

初赛数据的历史最长为 100 个广告行为，官方候选池为 660,000 个广告。主分数为：

```text
Score = 0.31 × HitRate@10 + 0.69 × NDCG@10
```

同时报告两个分项。检索覆盖整个指定候选池，允许与赛事一致的 ANN 流程；不能改成 99 个随机干扰物品的评价。采用单模型研究，不使用模型集成。以上任务、指标与单模型约束依据 [官方赛题论文](https://arxiv.org/html/2604.04976)；数据来自 [TencentGR-1M 官方发布](https://huggingface.co/datasets/TAAC2025/TencentGR-1M)。

本地复现实验沿用赛题目标与指标，但原赛事隐藏答案和线上榜单服务不被假定仍可用。自行建立的开发/确认/最终留出结果统一称为本地结果，不能称为原赛事榜单复现。

## 2 共同起点和允许的迭代

起点使用 [官方 baseline](https://github.com/TencentAdvertisingAlgorithmCompetition/baseline_2025)，不再使用 NextItNet 或 KuaiRand HSTU 起点。冻结官方代码与必要兼容补丁后，所有对照从同一版本开始。

当前公开代码采用 SASRec 风格结构。其参数入口包含 hidden=32、1 block、1 head、dropout=0.2、学习率 0.001、3 epochs、batch=2048，默认多模态特征为 81；代码的 maxlen=101 与数据 100 条行为及用户 token 的构造需一并核对，不能解释成新的千级历史要求。[官方参数入口](https://github.com/TencentAdvertisingAlgorithmCompetition/baseline_2025/blob/main/main.py)

论文描述的训练目标与当前公开代码存在口径差异：论文写 InfoNCE，而 `main.py` 使用 BCE。首个 baseline 结果以实际冻结代码为准，二者不得合并成同一实验版本。将 BCE 换为 InfoNCE 可以是一项候选实验，不能预先作为已获得收益。[论文训练目标](https://arxiv.org/html/2604.04976#S4.SS1)、[公开训练代码](https://github.com/TencentAdvertisingAlgorithmCompetition/baseline_2025/blob/main/main.py)

迭代范围按赛题展开：序列骨干、行为与时间编码、稀疏/多模态融合、损失和负采样、优化与正则、单模型推理和检索。读取数据范围、目标、候选池及评分公式固定；每次修改记录来源、实现和成本。

官方小模型用于起步与链路核验。验证研究方法时，需要确认它的训练有效性，并用相同初始配置和预算对比研究流程，不能仅用“增大网络后超过很弱的基线”证明知识或诊断有效。

## 3 公开数据与执行前审计

公开数据包含 `seq`、`user_feat`、`item_feat`、`candidate`、`indexer.pkl` 和多个多模态 embedding。首次可按官方默认加载特征 81；其他公开 embedding 按研究需要使用并记录实际数据与准备成本，不要求先下载全部约 137 GB 数据。[官方数据结构](https://huggingface.co/datasets/TAAC2025/TencentGR-1M)

正式运行前完成以下审计：

| 检查 | 验收要求 |
| --- | --- |
| 数据版本 | 冻结实际文件清单、revision、字节数和 hash；不能把用户数 1M 当成行为条数 |
| ID 映射 | 分清原始 ID、重映射 ID、retrieval ID，完成回映射与覆盖检查 |
| Schema | 核对候选列名、cold-start 字段、稀疏值类型及缺失值；不猜测匿名特征的业务含义 |
| 行为与时间 | 检查曝光/点击顺序、时间戳、重复广告，以及目标曝光之后的信息是否进入输入 |
| 多模态特征 | 核对 ID 对齐、缺失与零向量比例、维度和各组覆盖率 |
| 训练/推理一致性 | 检查 token 构造、checkpoint、参数、特征集合与检索回映射一致 |
| 本地路径与产物 | 去除宿主硬编码路径，配置显式注入；保留推理中间产物与评测证据 |

公开 `eval.py` 调用推理后主要写出用户和 Top-10 结果，并非完整的本地带答案评分器。现有推理代码与 HF 数据的列名、字段约定也需要兼容性核验。必要的工程修复单独记录为基线适配，不计作研究贡献。[提交入口](https://github.com/TencentAdvertisingAlgorithmCompetition/baseline_2025/blob/main/eval.py)、[推理代码](https://github.com/TencentAdvertisingAlgorithmCompetition/baseline_2025/blob/main/infer.py)

## 4 本地评价如何对应赛题

优先核对官方是否提供独立查询与答案包；若具备，保持其定义并在独立评价服务中封存。只有公开历史序列时，需先落实本地 query/answer 构造，才能开展带分数的研究 loop。

本地协议须满足：目标是点击广告；输入在对应目标曝光前截断；未来曝光、点击、时间和目标类型不进入输入；官方候选池不缩小。不能简单把点击前所有行为作为历史，因为其中可能已经包含目标曝光。

采用用户哈希分组的 train/feedback/gate/final，默认比例 85/5/5/5，固定哈希盐和用户清单。训练用户提供训练监督，留出用户仅提供其允许的历史输入与特征；首版 feedback 用于诊断、提案及逐轮选择，gate 和 final 在提交冻结、关闭研究后用于结束审计。比例属于本地研究设计，不冒充赛事原始切分。逐轮 gate 确认作为后续扩展，当前不声明已实现。

如果要从历史序列重建标签，可在固定时间/位置切点之后选择第一个点击，并核验该点击对应的曝光：只有曝光归属可明确恢复、曝光位于切点之后且目标在官方候选池内时才生成查询。历史严格早于目标曝光；多重曝光归属不清或目标缺失的样本不猜测，事先排除并报告原因、数量和覆盖率。字段不足以可靠恢复时，本地评价前置条件不通过，不能用训练损失或任意 next-item 替代竞赛目标。

这一步必须在模型对比前确定，并保存各组样本量、曝光/点击与目标覆盖审计。任何重建方式均标记为本地复现协议，分数不与原榜单数字直接比较。

本地评分器接收独立训练/推理产物，检查用户、候选 ID、Top-10 长度和重复项，再计算官方加权分数。数据不变时所有候选使用同一查询和候选集合；不能按模型是否命中筛选评价用户。ANN 属于提交系统的一部分，记录索引参数、耗时与其相对精确检索的召回审计。

## 5 公开方案如何成为知识库

知识来源分为三类：

1. 官方任务、数据、基线与规则，作为当前任务的事实与边界。
2. 获奖报告和参赛者公开代码，作为外部方法、适用条件及作者报告的证据。
3. 当前研究自己的训练、对照、失败与归因，作为本地证据。

第一批来源为官方论文第 7 节的方案总结，以及 [Chocay 的公开实验记录](https://github.com/Chocay/Tencent_Algo2025)、[Y_TencentGR 的公开实现](https://github.com/YYYYXL1004/Y_TencentGR)。作者成绩和排名保留为自报来源，不作为本地效果或代码已复现的证明。旧比赛代码与当前 Parquet baseline 的差异需记录。

每条经验按以下格式组织：

```text
来源与版本
观测到的问题
优化方法及机制
适用条件与代价
作者报告的实验与限制
当前模型与该方法的 diff
可检验假说和反例
本地实验引用与结论状态
```

已准备四张 [初始经验卡](../outputs/taac2025-research-loop-design-20261103/knowledge-seed.jsonl)，分别覆盖排序目标、行为条件、时间信息和特征融合，均标记为外部待验证，没有填入本地收益。

优先提取行为语义、时间、模态融合、负采样、长尾和冷启动等问题的条件化经验。多项同时修改的公开方案不能被拆成多个已经证实的独立收益。特征匿名时只陈述可见类型和统计，不把某个编号擅自解释为价格、性别或商业价值。

知识读取和更新遵循 [Agent 研究方法](agent-research-loop-v0.md)：Paper/行业来源独立追新，每轮使用的来源版本固定，本地实验不改写外部原始主张。个人知识当前仅作为可选只读快照，不实现人的交互、审核或个人知识更新。实验账本逐轮追加，Agent 场景经验在研究阶段结束后慢速归并；这里只积累内容与实验证据，不演化知识组织机制。

## 6 固定研究 loop

以下是通用 [Agent 研究方法](agent-research-loop-v0.md) 在本赛题上的执行过程，具体步骤的输入、输出、LLM 与程序职责以方法文档为准。实现主干采用 [Karpathy autoresearch 适配](karpathy-recommendation-autoresearch-v0.md)，通过固定指令组织单 Agent 编码研究。

```text
读取赛题、当前模型、数据与训练现状
                     ↓
检索相关公开方案、个人知识与本地正负例
                     ↓
对照当前实现与可见表现，形成 diff
                     ↓
提出竞争解释、修改假说与证伪条件
                     ↓
选择一项主实验，预留训练与诊断预算
                     ↓
实现 → 审查 → 训练 → 候选池检索 → 独立评分
                     ↓
归因与保留决策，记录失败和无收益
                     ↓
更新逐轮记录与工作状态，提出下一轮补证据问题

研究阶段结束后，归并长期场景经验
```

首版采用一个主研究 Agent 配合工具。Researcher 提出问题与实验、Experiment 实现、Reviewer 检查实际改动、Analyst 归因并总结，这些表示流程职责，不要求四个独立 Agent；检查步骤不依赖人工审核。程序负责评分、预算、产物冻结和恢复。角色提示、诊断工具、上下文装载及流程在一次研究中固定。

每轮先列出最多三个竞争解释，再选择一个主要假说。机制归因需要时增加一个匹配对照，其他方向留在假说池。不同候选从本轮父代码分别构造；默认独立初始化训练，共享 seed 和训练协议，额外训练及失败计费。使用 warm start 必须事先声明并记录父权重与累计训练，不能把它的额外训练伪装成结构收益。

每轮至少留下以下材料：

| 材料 | 必要内容 |
| --- | --- |
| 现状与 diff | 实际代码、数据/训练现象、知识来源及适用条件 |
| 假说与实验 | 预期改变、竞争解释、证伪结果、控制变量及预算 |
| 实现与执行 | 代码 diff、配置、权重、日志、检索索引和预测 |
| 结果 | HR@10、NDCG@10、组合分数、分组样本量和资源 |
| 归因与继承 | 哪些解释得到支持、哪些仍未知、是否保留、下一步及待归并经验 |

首版候选保留依据 feedback 开发分数与资源约束，结束后在 gate/final 审计所选模型；原因解释单独标注证据状态。一项修改涨点不自动证明所声称的机制。对模态缺失、行为类型或历史长度分组的结论，需采用训练前固定或事先声明的分组，避免按结果挑用户。

## 7 首批实施与验收

第一步是数据、基线和本地排名评价闭环。固定官方默认结构和特征 81，确认训练、全候选检索、评分与恢复，并完成同配置多 seed 校准。未经核验不预先填写模型收益、GPU 时长或最小显著收益门槛。

第二步是连续两轮研究。每轮一个主假说及必要对照，第二轮必须说明怎样使用第一轮的结果。首轮可以选择复现一项公开方法，但不提前规定哪项一定有效；论文/代码的矛盾或工程错误应先作为基线审计解决。

第三步是研究价值初验。将完整研究 loop 与去知识、去诊断条件做同起点、同资源比较。分别报告公开方法复现收益、自主提出的改进、失败成本和诊断是否改变行动。此时仍不启用 RSI。

每个候选的训练长度、可用资源、正式评分次数和最终确认 seed 在基线校准后冻结。赛事原来的 GPU 配额和每日提交限制属于历史平台规则，不宣称本地硬件完全复现；本地采用明确的 GPU 秒、wall time、token 与评分次数上限，所有对照一致。训练损失可频繁查看，最终留出分数不能反过来指导研究。

验收要求：真实数据和模型结果、可追溯知识引用、可检验假说、实际候选/对照、独立排名评分、跨轮反馈、完整成本和失败记录。只跑角色对话、只降低训练 loss 或只复制公开榜单成绩，不算研究 loop 验收通过。
