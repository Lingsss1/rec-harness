# Dream-RSI 式回放：实验记录保留与数据契约

版本：2026-09-22 · 设计契约，记录器、回放器及官方格式适配尚待实现。主方案见 [Auto Research](auto-research-plan.md)。

目标：同一份原始研究历史可用于审计、图知识构建、Harness 外部优化，以及 Dream-RSI 式发现树回放。知识总结与图压缩不能替代或删除原始实验记录。本轮不移动、删除或重写已有实验归档。

## 1. 三种用途，共用事实源

- **不可变研究档案**：保留每次尝试、代码与环境身份、可见状态、输出、成本和错误；包含被淘汰、失败和中断的尝试。
- **图知识库**：从档案建立模型、缺口、方法、实验、Claim 和反证关系，支持检索与归因。
- **Replay World**：从合格档案构建冻结发现树，供新探索策略逐步选择分支、揭示历史结果。

图和 Replay World 都是原始档案的派生视图，绑定相同稳定 ID 和内容 hash。删减当前上下文、撤回 Claim 或回退模型，都不能删除档案。

## 2. 保留目录与不可变产物

```text
research_archive/<campaign>/<episode>/
  manifest.json                # 协议、各版本、数据/环境锁、预算、并发模型
  events.jsonl                 # 追加式决策、提交、完成、取消、选择、停止事件
  decisions/<decision_id>/
    state.json                 # 当时已揭示节点、合法动作、进行中任务、剩余预算
    context.json               # 实际输入引用、图快照、来源截止时间
    action.json                # 实际动作批次、参数、简短理由与预测
  attempts/<node_id>/
    node.json                  # 主父节点、依赖、分支与创建次序
    workspace-before/          # 完整快照或可无损重建的基底+补丁
    workspace-after/
    request.json               # 实际请求、工具/提示/Agent 版本与输入
    observations.json          # 公共评分、诊断、错误、训练状态
    artifacts.json             # 日志、预测、张量、配置、checkpoint 等引用及 hash
    resources.json             # tokens、GPU 秒、墙钟、峰值显存等
  archive-index.json           # 内容寻址引用、大小、完整性及可用状态
replay_worlds/<world_id>/
  manifest.json                # 来源档案 hash、构建器版本、支持范围、评分定义
  nodes.jsonl / transitions.jsonl
  validation.json              # 结构、前缀隔离、成本和重放一致性检查
```

保留实际执行的请求、输出和工具返回；不要求保存私有思维链。大产物可以无损压缩、去重或转冷存储，但必须保留可恢复引用、校验和及权限，不能只有易失的本地路径。基础模型提供方版本和环境可用性如实记录；档案可恢复不等于 LLM 随机生成可逐位复现。

模型权重不是树回放读分数的必需输入，但已保存 checkpoint 不因总结而删除；它可服务诊断复测。原本未保存的张量、权重或调用记录标 unavailable，不能声称已具备。任何后续有损清理需显式修改保留政策和回放资格。

## 3. 核心记录字段

| 记录 | 必须保留 |
|---|---|
| Episode | task/data/split/protocol hash；root workspace；Agent、LLM、Harness、Skill、工具版本；图快照；种子；预算；worker 限制；历史上下文来源 |
| Node / Attempt | node_id、primary_parent_id、branch_id、creation_seq；设计父版本与权重来源分别记录；依赖节点；前后工作区；请求；实际观测；有效性与错误；产物引用 |
| Decision | decision_id、revealed_node_ids、可见上下文；合法根/前沿动作；pending 任务；所选 batch；选择与返回顺序；停止理由 |
| Resource | 每次 generation/evaluation/diagnostic 的成本；提交、开始、完成时间；并发占用；失败/取消的已消耗成本；未知资源为 null 而非零 |
| Observation | 原始指标及方向；公开质量分转换版本；分组与诊断；success/invalid/failure 状态；数值缺失理由 |
| Provenance | 事件序号、父事件或 hash 链；所有快照内容 hash；图读取来源及 evidence_dependency_ids；权限与可见性标签 |

节点最小单元是一次真实生成—评估尝试，多 seed 子运行保留独立 run ID，聚合节点明确聚合规则。提案被提出但未执行，只进入候选动作档案，不能伪造为具有结果的实验节点。

## 4. 将历史组织成发现树

每个 episode 有一个表示初始工作区的根；每次尝试恰有一个真实主父节点，用于表示从哪个工作区继续修改。每轮训练仍独立初始化，设计血缘不等于权重继承。其他借鉴、组合、跨分支依赖作为独立关系保存，不伪造成单父节点因果。

Dream-RSI 论文的调度接口是从根或当前叶子中选择至多 W 个节点，继续一个已有分支或开启新分支。其回放中，非根节点最多有一个记录后继，根按创建次序揭示新的分支。[方法第 3 节](https://arxiv.org/html/2609.14858v1#S3)

因此采用两种资格：

- `branch_chain`：在线记录符合根加分支链的结构，可构建论文语义对应的回放世界。
- `general_dag`：存在内部节点多后继、组合或额外依赖，保留完整档案，但需显式适配或扩展动作语义；不得静默剪枝、复制节点或声称等价于论文接口。

如需收集高质量的 branch_chain 历史，运行前固定根/前沿扩展契约和每批调度规则；不为了强行兼容回放而歪曲既有实验。

## 5. 前缀回放与支持边界

回放开始时只揭示根，每次策略选择合法节点后才揭示对应历史后继及其公共观测。完整结果表仅供模拟器持有，策略运行环境无权直接读取未来结果。历史图检索必须使用当时有效快照或由当前回放已揭示事实构建的投影；不能接入包含整棵树结论的最新知识图。

- 根：按照构建时冻结的创建次序开启尚未揭示的根分支。
- 非根前沿：返回其记录的下一个尝试；不得跳过父节点直取后期高分。
- 空动作：策略主动停止。
- 已记录分支没有后继：返回 exhausted/no_recorded_continuation。它表示历史覆盖结束，不表示现实中无法改进。
- 新工具、新代码、新 prompt、未记录动作或缺失依赖：返回 unsupported，记录支持率与原因；不给虚构收益，不将其记成零分失败。

真实历史中一次代码生成可能引用其他分支的结果。回放改变顺序后若这些依赖尚未可见，该转移必须屏蔽或标 unsupported。无法恢复上下文依赖的旧轨迹，只能作为受限描述性回放，不能宣称是精确反事实环境。

各调用顺序、worker 占用、批次完成及观察暴露策略必须明确。首版可使用同步批次：一批完成后统一揭示；异步运行保留事件时间，不能用改变并发后的历史完成次序当作已证明的现实延迟。

## 6. 成本与评价

同时报告：公共 best-so-far 质量、实际选定模型质量、揭示次数、重放的历史 GPU/token 成本、批次数、终止原因和 unsupported 比例。失败尝试消耗计入预算；诊断耗时和 Harness 开发成本单列且参与相应总成本比较。

可提供论文式“质量减调用成本、加并行奖励”的目标作为可选配置；我们的预算口径另外保存 GPU 秒/BCU 与效果—预算曲线。两者明确命名、冻结系数和方向，不能把 agent calls 当成实际 GPU 成本，也不能把并行奖励直接解释为真实墙钟提速。

不同任务先按任务协议归一化或分开评分；不直接平均不同量纲。未记录的分数为缺失，禁止自动补零。隐藏评估数据和由其筛选的结论不进入世界或外部优化器。

## 7. 对外部优化器的适用范围

| 修改对象 | 历史回放能验证什么 | 仍需什么 |
|---|---|---|
| 分支选择、停止、批次编排 | 已记录支持范围内的发现效果与成本 | 新在线 episode 确认泛化 |
| 上下文、提示、协作和提案生成 | 轨迹审计与决策合规，部分已支持动作 | 新生成结果会变化，必须在线运行 |
| 新诊断工具或改造算法 | 只能回放已有测量/产物；可另行只读重测可用产物并记新事件 | 工具正确性、效用与模型重训验证 |

回放得分提高只说明在固定历史世界上的改善。多个候选不能反复在同一批世界筛选后声称泛化；按 episode/任务/模型血缘划分开发与确认世界，再将候选上线扩充世界池。

## 8. 旧记录迁移与验收

旧记录原位保留，以清单引用和新适配层导入。缺少当时上下文、快照或依赖时，标记 `audit_only` 或 `partial_replay`；只有经过结构、依赖、产物及前缀检查的 world 才标 `replay_ready`。状态是本项目的资格标记，不表示通过官方软件认证。

验收至少包括：

1. 原策略重放能够还原其已揭示节点、合法批次、成本和公共分数。
2. 改变顺序不会泄露未来观测、未来图知识或尚未成立的依赖。
3. 缺失、unsupported、失败、取消与已消耗预算语义明确。
4. 相同 world + 策略 + seed 的离线结果可复现。
5. 原始产物完整性、引用恢复和旧档案未丢失可核验。
6. 世界开发/确认拆分和真实在线增益分别报告。

当前交付是依据论文机制设计的数据保留契约，不是已完成 Dream-RSI 官方代码格式适配，也不表示已有旧实验全部可精确回放。
