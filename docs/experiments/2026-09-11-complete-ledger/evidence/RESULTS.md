# KuaiRec 循环 QFormer 实验结果

Cross8 是主基线，Cross11 是优化参考。中间层循环 ×2 保留为优先优化候选；候选资格不要求第一版超过 Cross11，也不代表已证明稳定提升。

本次下载官方 KuaiRec，固定新协议后从头训练：high_watch = watch_ratio > 2.0；按用户时间切分 80/10/10，历史严格早于目标。训练 10,022,544 条、验证 1,253,001 条。每次 1 epoch、batch=8192、1240 个更新步骤。测试集不参与模型筛选或效果评估。

原始 Cross8 使用默认 clip=10 和全 Query；Cross8 同优化设置、Cross11 和循环模型使用 clip=1、训练全 Query / 验证 Q3 置零。因此相对原始 Cross8 的差值包含架构和优化设置的综合影响；循环本身的增量参考 Cross11 的配对差值。

## 候选保留与下一步

1. **middle2：优先优化候选。** 首层/末层各执行一次，中间层共享参数循环 2 次；相对 Cross11 不增加参数，计算增幅小于整段循环。继续优化目标是保持接近基线的 AUC，并改善校准和单位计算成本。
2. **loop2_anchor、middle4：备选优化候选。** 保留已训练 checkpoint 和三个 seed 的证据，优先级按效果及额外计算成本排序，不因未超过 Cross11 而直接淘汰。
3. **loop2：保留候选，待扩展 seed。** 目前只有一个 seed；loop4 保留为低优先级机制分支，其更高计算成本和首轮下降需要先解释。

优先做现有 checkpoint 的全 Query / Q3 置零验证消融，并给 Cross11 相同评估预算，检查历史路由是否影响新模型校准。之后对 middle2 尝试学习率和循环状态混合强度；扩大训练预算时同步重跑基线。这些是后续优化任务，尚未作为本次已完成结果。

## 证据与边界

- 数据预处理、时间截断和原始记录核查见 `prepare_kuairec.py`、`reports/data-audit.json`；发布的用户快照并无逐事件采集时间保证，这是静态侧信息的 warm-start benchmark。
- 9 项模型正确性测试在 CPU/GPU 上通过；另有时间切分测试、AUC bootstrap 算法测试及新旧 full-scope 实现兼容性检查。
- 每次训练的 `runs/*/manifest.json` 保存配置和数据 SHA-256，`result.json` 保存指标，`validation_predictions.npz` 保存逐样本预测，checkpoint 保留。
- 当前数据协议无法复现包内历史 AUC 0.8877503 的未知标签/切分规则；该数值不用于本次提升判定。
- [Huginn 原论文](https://arxiv.org/html/2502.05171v1) 提供 prelude/core/coda 结构依据；本项目借鉴结构，并非完整复现其 LLM 训练方法。
- [KuaiRec 官方数据](https://zenodo.org/records/18164998)；模型依据为 rec-harness 的 auc41 baseline code bundle。
