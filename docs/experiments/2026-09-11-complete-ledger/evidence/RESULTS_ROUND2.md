# KuaiRec 循环 QFormer：第二轮迭代

本轮完成 3 个原 checkpoint 的 rec-harness 诊断、1 个重训候选的诊断复核、6 个 checkpoint × 3 种 Query 路由的完整验证，以及 2 个循环状态混合改动 × 3 个 seed 的重新训练。当前按平均 AUC 排序的首选循环候选是 **middle2 额外更新 ×0.5**；候选保留与超过基线的结论分别判断。用户随后要求重点探索结构和循环位置，相关后续工作独立记录在第三轮。

Cross8 继续作为主基线。表中同时保留 Cross8 同优化设置和 Cross11 全 Query，避免把基线也能获得的路由收益归功于循环。原始实验结果见 [第一轮报告](RESULTS.md)，本轮未使用测试集。

## rec-harness 给出的证据

诊断子集对每个验证用户均匀抽取最多 8 条事件，共 57,408 条、7,176 个用户、4,472 个正例。Hook/几何分析使用其中固定 7,232 条；诊断子集不是全量事件分布，因此子集 AUC 不参与最终模型排序。

1. **路由存在可修正的损失。** middle2 的 Q3 在原验证路由下梯度为零，Zero/Shuffle 也都为零，原因是它被显式屏蔽。恢复全 Query 后，三个 seed 的 Logloss 全部改善，AUC 两升一降；Cross11 三个 seed 的 AUC 和 Logloss 都改善。不能把零梯度当作 Query 无用的证据。
2. **维度集中不是循环特有的完全坍塌。** Q0 的最终有效秩：Cross8 12.86、Cross11 6.86、middle2 6.18；middle2 中间层第一次/第二次调用为 7.21/6.47。没有非有限值或死维度。基线也触发维度集中提示，这只支持尝试控制状态变化，不能证明提升秩就能提高 AUC。
3. **打乱和置零不能互相替代。** 例如 middle2 的 Q6 在诊断子集被打乱时 Logloss 增幅约 0.00113，置零时约 0.01224；应保留其偏置/尺度作用这一解释，不能直接删掉。所有 8 个等宽 Query 都做了配对对照，包含 toolkit 推荐的 Top/随机/Bottom。
4. **循环次数需要训练适配。** 对训练为 2 次的 middle2，在同权重下改为 1/3/4 次，子集 AUC 都下降；直接增加推理循环不是已经验证的增益。

减弱额外更新后的 seed=20262027，最终 Q0 有效秩为 7.74，高于原 middle2 的 6.18；但该 seed AUC 低于原 middle2 全 Query。这说明有效秩不是可单独优化的目标，其余 seed 尚未做几何复测。

实际使用的工具为 `analyze_hook_arrays.py`、`diagnose_collapse.py`、`analyze_perturbations.py`，26 个有效工具调用成功；曾有一批 7 个调用在导出尚未完成时启动而失败，保留失败记录，并已为分析器加上完成标记检查。未修改上游 toolkit。详见 [诊断目录](reports/round2/)、[工具源码哈希](reports/round2/toolkit-identity.json)。

## 两个重训改动

设首层输出为 q0，中间层第一遍输出 q1=F(q0)，末层保持独立。

- `middle2_damped50`：第二遍为 q2=q1+0.5×(F(q1)−q1)，只减弱额外循环的更新。
- `middle2_anchor50`：第二遍为 q2=F(0.5×q1+0.5×q0)，在再次计算前注入初始状态。

两者均共享中间层参数，不增加 Cross11/middle2 的参数量。新增更新缩放在默认值 1 时保持旧行为，缩放为 0 时退化成单遍；11 项 CPU/GPU 正确性测试通过，12 组配置与第一轮实现的输出及参数梯度逐位一致。

## 候选排序与成本

| 候选 | 相对原 middle2 全 Query ΔAUC | 同 A800 全 Query 前向 p50/ms | 参数量 |
|---|---:|---:|---:|
| middle2 额外更新 ×0.5 | +0.000419 | 17.58 | 11.408M |
| middle2 初始状态注入 0.5 | +0.000404 | 17.57 | 11.408M |
| middle2 全 Query | +0.000000 | 17.53 | 11.408M |

成本测量为 GPU 7、BF16、固定真实 batch=1024、10 次预热和 40 次前向，排除 IO；并非端到端服务延迟。新模型仍比 Cross8 的 9.232M 参数多，不能声称相对 Cross8 的参数效率提升。

保留接近 Cross8 或 Cross11 的方案作为候选，继续记录额外计算、Logloss 和用户排序指标；不会因未超过 Cross11 而直接丢弃。若均值提升但 seed 符号不一致，结论仍为有希望的候选，不能宣称稳定收益。

## 配对不确定性

- middle2 (all_queries) 相对 middle2 (native)：三 seed 平均 ΔAUC=+0.000320，配对用户 bootstrap 95% 区间 [+0.000258, +0.000382]。
- middle2_damped50 (native) 相对 baseline (all_queries)：三 seed 平均 ΔAUC=+0.000035，配对用户 bootstrap 95% 区间 [-0.000240, +0.000317]。
- middle2_damped50 (native) 相对 cross8_original (native)：三 seed 平均 ΔAUC=+0.000365，配对用户 bootstrap 95% 区间 [+0.000032, +0.000698]。
- middle2_damped50 (native) 相对 middle2 (all_queries)：三 seed 平均 ΔAUC=+0.000419，配对用户 bootstrap 95% 区间 [+0.000184, +0.000679]。

这里对同一用户重采样并在三个固定 seed 配对结果上取平均；不包含训练 seed 不确定性，也未校正本轮多个候选的选择效应。测试集仍保留给最终冻结方案。
