# KuaiRec 第三轮：结构与循环位置

按用户修正，本轮改变循环所处阶段和跨字段/历史的信息流，而非继续搜索状态混合系数。实现五种位置，在相同 seed 初筛后，对前两种增加两个 seed；共 9 次完整训练。

三 seed 的结构候选中，平均 AUC 最高的是 **历史读取后返回字段**。接近 Cross8 或 Cross11 的方案保留为优化候选；单 seed 初筛结果不与三 seed 均值混算，也不据此宣称稳定提升。

## 改了哪些结构

N0/N1 是字段阶段的两层，S0/S1/S2 是历史序列阶段的三层；同名块重复出现表示共享参数。所有方案保持 Cross11 的 11.408M 参数、8 个 Query、原特征、损失和预测塔。

| 方案 | 块调用顺序 | 调用次数 |
|---|---|---:|
| Cross11 | N0 N1 S0 S1 S2 | 5 |
| 原 middle2 | N0 N1 S0 S1 S1 S2 | 6 |
| 字段末层循环 | N0 N1 N1 S0 S1 S2 | 6 |
| 序列首层循环 | N0 N1 S0 S0 S1 S2 | 6 |
| 序列末层循环 | N0 N1 S0 S1 S2 S2 | 6 |
| 历史读取后返回字段 | N0 N1 S0 N1 S1 S2 | 6 |
| 字段—历史交替循环 | N0 N1 S0 N1 S0 S1 S2 | 7 |

前四种新位置与原 middle2 的块调用次数一致；字段和历史的 token 数不同，实测耗时见下表。反馈/交替结构会额外经过共享字段 final norm，因此这里比较的是位置与接口结构的组合，而非排除归一化因素后的纯顺序因果效应。字段和历史 K/V 都保持原始输入，跨轮只更新 Query。

## 配对不确定性

- place_feedback2 对 middle2 (all_queries)：平均 ΔAUC=-0.000051，配对用户 bootstrap 95% 区间 [-0.000318, +0.000217]。
- place_feedback2 对 cross8_original (native)：平均 ΔAUC=-0.000105，配对用户 bootstrap 95% 区间 [-0.000430, +0.000191]。
- place_feedback2 对 baseline (all_queries)：平均 ΔAUC=-0.000436，配对用户 bootstrap 95% 区间 [-0.000682, -0.000166]。

区间条件于三个已训练 checkpoint，不包含训练 seed 的总体不确定性，也未校正从五种位置选择前两种的效应。反馈结构相对 Cross8 的区间跨零，相对 Cross11 全 Query 的区间为负；这不是统计等价或 AUC 提升的证据。按用户标准，它仍作为接近 Cross8 的结构候选保留。

## 结构诊断复核

对字段循环和字段反馈的 seed=20262027 checkpoint，复用第二轮的 57,408 条固定验证事件（7,176 用户、4,472 正例），导出字段/序列各层和最终 Query 的表征与梯度；18 个 rec-harness 工具调用全部成功。

- 两组最终 Q0 有效秩分别为 7.34/7.54，仍有维度集中，无非有限值和死维度；没有依据宣称反馈结构解决了坍塌。
- 两组全 Query 路由的 Q3 都有非零梯度及有害的 Shuffle/Zero 效应，不能沿用旧的屏蔽 Q3 结论。
- 对已训练的反馈结构直接取消额外字段回读，子集 AUC 从 0.859935 降到 0.856751；增加一次回读也下降。这说明 checkpoint 依赖其训练时的调用图，不证明删除或加深后重新训练必然更差。
- 字段循环在均匀按用户抽样的子集上 AUC 更高，而完整事件验证上字段反馈更高；小子集诊断不代替冻结协议的选型指标。

完整 Hook、几何、配对扰动 JSON/Markdown 见 [字段反馈诊断](reports/round3/place_feedback2/)、[字段循环诊断](reports/round3/place_field2/)。

## 保留判断

字段反馈优先作为新的结构候选：AUC 接近 Cross8，NDCG@10 均值更高；同卡前向约 16.35 ms，比原 middle2 全 Query 的 17.53 ms 少约 6.7%，仍比 Cross8 的 13.57 ms 多约 20.5%。字段循环保留为高 seed 波动的备选，其余位置为单 seed 探索分支。第二轮的减弱更新方案仍有更高平均 AUC，本轮未将它替换为新的性能最优模型。

下一轮结构假设应优先检查：在历史后的字段回读中区分用户字段与目标物品字段；以及固定归一化调用次数的接口对照。它们需要独立重训和相同基线预算，尚未执行，不继续局限于状态混合系数搜索。

## 验证和证据

- CPU/GPU 正确性测试覆盖五种位置在关闭额外循环时与 Cross11 的训练/验证输出及参数梯度逐位一致、真实共享块调用顺序、每次调用的梯度、padding/空历史不变性、K/V 不变性和优化器注册。
- 训练/数据/预测/checkpoint 均保留在 `runs/place_*`，测试集未评估。推理成本在同一 A800 GPU 7、BF16、真实 batch=1024 下测量，排除 IO。
- 诊断导出器把共同 Hook 放到序列 final norm，适配新的跨阶段调用图；仍使用 rec-harness 原有分析工具，不从 Hook 排名直接选赢家。
