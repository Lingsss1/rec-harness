# 淘宝循环：历史可用性与读取顺序的八组匹配实验

本轮得到两个线索：**循环收益会随输入条件改变；相同两版历史的读取顺序确实重要。** 但尚未确认一个同时提高整体 AUC 和计算效率的替代结构。保留原 mature 两轮模型作为本协议参考；先浅后深仅保留为研究候选。

所有模型沿用训练 seed 20262027、HeavyBall.PSGDKron 每步更新、dense LR 1e-4、Adagrad .05、clip1、BF16、batch8192、1 epoch/2193次更新。无新增训练 seed、无预测状态到工作状态的反馈、无 test 评估。八组正式训练与真实两步 smoke 均成功。

## 循环是否只在某类任务或输入条件下获益

| 预定效果 | macro AUC 差值 | 95%配对用户区间 |
|---|---:|---:|
| released 两轮−一轮 | −.002127 | [−.003414, −.000695] |
| mature 两轮−一轮 | +.000908 | [−.001860, +.003713] |
| 上述两种循环效果之差 I | +.003035 | [+.000047, +.006292] |

两种输入使用共同19类行为词表和严格的过去历史支持集；mature 进一步将未满24小时的cart/fav/buy标签（包括零标签）改为未知。这里没有真实行为发生和入库时刻，成熟度处理是保守可用性控制，不能将跨模式AUC差称作实际线上泄漏率。

循环效果的点值由负转正，I区间刚好高于零，提示输入条件值得继续关注；但 mature 自身的macro提升区间跨零，四任务循环效果的六个直接任务 AUC 效果差区间也都跨零。**本轮不能据此确认“只有收藏/购买任务能从循环受益”。** 收藏是mature循环 AUC 点增益的主要来源，但尚不能把它与其他任务的 AUC 效果差别说成已确认结论。

BCE 则有不同证据：mature 两轮相对一轮，点击 BCE 增加 .00014229（区间[+.00006520,+.00021944]），购买 BCE 降低 .00018593（区间[−.00026568,−.00010524]）。点击−购买的直接 BCE 效果差为 +.00032822，区间[+.00020305,+.00044691]；点击−加购、点击−收藏的 BCE 效果差区间也高于零。这支持损失层面的任务取舍，不能等同于已确认各任务 AUC 的循环增益。

## 为什么保留浅→深，但不替换原模型

| 比较 | macro AUC 差值 | 95%配对用户区间 |
|---|---:|---:|
| SD−A | +.000289 | [−.002641, +.003084] |
| DD−A | −.005424 | [−.008412, −.002645] |
| DS−A | −.004422 | [−.007850, −.000711] |
| SD−DD | +.005713 | [+.003217, +.008053] |
| SD−DS | +.004712 | [+.001936, +.007656] |
| DS−DD | +.001002 | [−.001917, +.003726] |
| A−mature Cross8 | +.007689 | [+.005008, +.010917] |
| SD−mature Cross8 | +.007978 | [+.005099, +.010993] |

DD/SD/DS具有相同参数量、共享G调用次数和初始参数，顺序比较支持本次“先浅后深”方案。SD−DD只改变首轮读入，表明不能把结果概括成“第二轮越深越好”。三者相对A还增加了容量和计算；两版历史均预先计算，所以这里没有检验首轮工作状态驱动的历史写回。

SD相对A的四任务点差为 click **+.003325**、cart **−.001776**、fav **+.004193**、buy **−.004585**。click提升区间为[+.002553,+.004143]；其余三任务 AUC 效果方向的区间仍跨零。直接比较click与cart、click与buy的效果差，区间分别为[+.000486,+.009653]、[+.000558,+.016519]，说明这个结构变化存在任务取舍的证据，不能仅看macro或收藏点值。

SD仅新增231,296个稠密参数（总参数约+0.45%），但实测前向延迟为A的**1.4665倍**。它满足预定的正向点值候选条件，却不满足延迟比≤1.05的近基线效率条件，macro区间也未确认改善。因此保留为研究候选，不做替换。DD和DS不再作为本轮优化候选；一轮和Cross8保留作匹配参考。

## ITT 的借鉴点与下一项问题

百度[ITT原论文](https://aclanthology.org/2025.acl-long.1369.pdf)强调共享变换、跨步残差累积、逐通道步权重与token路由。本轮支持继续研究每轮的读取职责，但不是ITT精确复现，也未证明动态路由有效。当前第二轮已经使用首轮工作状态；固定输入历史时，每次读取仍执行K/V投影。

下一项有限问题是：**只计算一次历史编码，第一轮保留原历史、第二轮读取编码后的历史，能否保留点击收益并减轻计算和其他任务损失？** [具体四路对照草案](NEXT_EXPERIMENT.md)已记录，尚未实现或启动新训练。不继续加轮数，也不重跑已经完成的原差值实验。

[联合质量核对](reports/joint-quality-summary.json)确认八组2193更新、输入/初始化对应和原文件连续性。[配对统计](reports/joint-paired/result.json)核对实际行、用户与AUC；[延迟记录](reports/latency/completion.json)保留400次实际前向。输入内容SHA沿用此前完整审计，本轮复核文件stat和两份原metadata，不声称新计算了所有原parquet内容哈希。
