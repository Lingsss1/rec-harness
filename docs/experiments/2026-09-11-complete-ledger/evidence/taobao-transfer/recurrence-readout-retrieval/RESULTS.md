q4 的 task−shared 宏 AUC 差为 −0.000179，95% 区间 [−0.001017,+0.000626]；q8 为 +0.005156，[+0.004282,+0.005986]。后者只是优于一个较弱的共享读出模型，仍低于原 q8。

固定权重读出诊断使用原 5514 行、4647 用户、16 分层 IPW 与 10000 次共享用户抽样，实际执行 rec-harness analyze_perturbations.py 并与自有聚合核对。只有 q4 将四任务系数改为均值时，点击 BCE 增加 9.27e−6，95% 区间 [0.708e−6,17.766e−6]；其余十五个区间跨零。这些是未作多重校正的条件结果，不能挽救训练比较中落后的模型。系数是无约束实数，并非选择循环深度的概率。

已有任务差异仍支持“加购／购买在当前比较中更受益”，不支持“只有某类任务才有循环收益”。此次负结果说明按任务混合两轮状态、或单独放开第二轮 query 参数，并未把这条线索转成模型提升。[已有任务效应证据](../recurrence-research/TASKWISE_RECURRENCE_EVIDENCE.md)

新增参数可改变全局 clip、PSGDKron 分桶初始化尺度和随机探针布局。这些只有静态代码依据，尚无隔离重放量化；不能据此归因本轮 AUC 下跌。下一步先做有界优化器实现诊断，再决定是否值得继续相邻结构变体。

八次 fit（含验证）累计墙钟 4.556 小时（八卡并行，非总历时，也不包括进程启动）。配对分析 996.69 秒；读出诊断 91.85 秒。

延迟比较在同一 A800、同一实际 1024 行验证 batch、BF16 下逐模型测量，10 次预热及 40 次 CUDA event 计时，共 550 次前向；有效测量阶段墙钟 30.09 秒。单 batch 顺序测量不代表端到端吞吐或多设备稳定性。先前 v1 输入树错误、v2 PID 命名空间错误均保留；v1 无模型前向，v2 确切次数未知、上界 50 次，未保留计时样本。失败成本并未完整测得。

配对 BCE 与训练保存的 logloss 使用不同数值／clipping 约定，最大已见差约 1.40e−5，不能混用。
