## 本地信息流与查重

令 H 为历史表示，e 为入口状态，z 为工作状态，y 为预测侧潜在状态（不是预测概率）。[当前代码](../recurrence-q4-capacity/QFormerCross8NoFeedback.py:15)：

```text
e  = L0(q, H)
z1 = L1(e, H)             y1 = L2(e, z1)
z2 = L1((e + z1)/2, H)    y2 = L2(y1, z2)
输出 = 原 post 模块和四任务头(y2)
```

第二轮每次仍会执行历史投影，问题不是漏算 K/V，而是输入一直为同一 H。历史构造只有逐 token 字段投影、位置项与归一化，未在此处加入历史 token 间交互。z1 已传给 z2；保持不恢复 y→z 的现有约束。

查重发现 prediction_reset 与中间深度监督已有负结果；QueryMixing 改动整个 L1 输入，包括查询投影、交互投影及残差，不能误称只改 Q。它们又不等同于完整 HCR。限定审查未见历史 H 自身循环更新的已完成训练。[代码、真实结果与检查范围](INFORMATION_FLOW_PRIOR_ART_AUDIT_20260910.md)。

## 下一项可解释的结构对照（设计草案，尚未训练）

先测试**每轮读取哪个深度的历史表示**，固定 q4、两轮、无 y→z、原 post/任务头。入口 e 始终用原 H0；增加一个共享历史编码器 G，得到 H1=G(H0)、H2=G(H1)。G 的具体结构及成本尚待源码设计，不引入 MoE、动态路由或新损失。

| 组 | 第一轮工作读取 | 第二轮工作读取 | 问题 |
|---|---|---|---|
| A | H0 | H0 | 原循环参考 |
| B | H2 | H2 | 加深历史编码整体有无价值 |
| C | H1 | H2 | 相对 B，只改变首轮表示版本 |
| D | H2 | H1 | 相对 C，交换同两版表示的读取顺序 |

B/C/D 都先以相同顺序计算 H1、H2，再执行工作循环，共享对应参数初始化和模块/RNG 调用安排。三组参数量、编码器调用次数相同；实际输出、梯度和训练轨迹不要求相同。A 少一个编码器，B−A 包含容量与计算的共同影响，不能单独归因于循环。延迟必须实测，名义 FLOPs 相同不代表运行时间相同。

预定解释：C−B 判断首轮是否应读取较浅版本；D−B 判断第二轮改读较浅版本；C−D 判断这两版表示的顺序，但同时改变两个位置，不能单独归因于某一轮。没有 H1/H1 组，不能完整估计两轮版本选择的交互作用。若只有 B−A 改善，则仅支持增加历史编码；若 C 优于 B/D 且优于 A，才支持这套逐轮表示分工作为候选。单个任务上涨、其他任务损失导致 macro 下跌不算整体成功。区间跨零本身不能证明等效。

**这里 H2 不依赖 z1，可以提前计算；所以这不是首轮结果驱动的自适应历史写回。** 如后续要测试 z1→H 更新，需要另设同模块、相同更新次数、不同条件来源的控制，不能由 C 的结果直接推断。也不把 G(H)=H+Δ(H) 的两次计算重新命名成另一个 RTC 组；这种展开已经累计了两步增量。累加完整已有残差输出会改变尺度和语义，需要独立问题与对照。

保持原训练 seed 20262027、PSGDKron 每步、dense LR 1e-4、sparse Adagrad .05、clip1、BF16、batch 8192、2193 更新；无新增训练 seed、无 test。正式运行前固定输入协议、构造/优化器成本与比较集合。四模型应复用同一用户抽样流报告四任务、macro、直接任务效果差和成本。原 z1−e 差值补跑[已完成且未获益](../recurrence-query-difference-retry/RESULTS.md)，本设计不重复它。

历史标签成熟度 × 一/两轮的 B 设计仍保留，它回答的是输入可用性与循环收益的关系，不能被架构结果替代。B 已完成 CPU 合成覆盖，集成源码停在草案；本次未启动 GPU、读取训练数据或新增统计抽样。

研究优先级：先将上述表示版本对照与 B 的输入控制协调，再决定具体执行。ITT 的累积/选择性更新作为后续结构方向保留；预测重置、辅助损失、完整 HCR 或路由堆叠的无对照拼装优先级较低。没有新增训练结果或支持性 lesson，全局训练台账保持不变。
