# 淘宝循环收益的任务差异

问题：不同预测任务是否从第二轮获得不同程度的预测收益？复用已有验证集预测，完整报告四个任务的效果与六组任务间效果差值。

两组对照回答不同问题：

- `q4_trained`：独立训练的一轮与两轮模型，固定原训练 seed 和预算。重放历史 500 次用户抽样，保存原报告未保存的跨任务联合 draws；原 AUC 区间必须精确复现。
- `q8_frozen`：同一原始两轮 checkpoint 的一轮／两轮推理结果。衡量该模型对完整第二轮的依赖；不能替代独立训练的一轮模型。

协议固定 2,871,767 行、268,201 用户、500 次用户配对重采样，四个任务共享抽样权重。报告逐任务 ΔAUC、ΔBCE，以及全部六个 `ΔtaskA−ΔtaskB`。95% 区间仅供探索描述，未校正多任务或历史模型选择，不包含训练 seed 方差。一项显著而另一项不显著不能证明任务间差异；区间跨零不等于无效或等效。跨任务原始 BCE 的尺度不同，不能据此比较信息量。

这里的“信息增量”指任务对既有信号的利用改善，不是新增外部信息。整轮消融、第二次 attention 概率替换、分别训练的深度模型是三个不同干预，不合并解释机制。

使用不变的 `qformer-loop/compare_runs.py` AUC 实现。`protocol.json` 和 `references.json` 固定输入、比较和预算；`offline-validation-final.json` 记录八项最终合成测试。默认 `run_bootstrap.py --check` 仅读取身份并核验 hash，只有明确指定 `--run --family q4_trained` 或 `--run --family q8_frozen` 才抽样。输出拒绝覆盖或自动重启。

预算：两组串行 CPU 分析合计最多 45 分钟墙钟、3 CPU 小时、16 GiB 峰值内存、512 MiB 输出；零训练、零模型前向、零 GPU 时间，不读取测试集。正式输出保留在 `reports/<family>/`，完成凭据同时记录输入和输出身份及实际开销。

此分析不能预先指定“点击读首轮，购买读末轮”。若继续检验任务专属读出，应比较原末轮读出、共享轮次混合、各任务独立混合，并计入处理首轮状态的额外计算。

两组正式分析已完成，q4 历史 AUC 区间精确复现。全部结果见 [RESULTS.md](RESULTS.md)。已有输出不需要重跑。
