# LoopCTR 参考实验：淘宝双流动态写入

本文仅记录这一次双流信息流实验，共8组训练。讨论中称“LoopCVR”；此前核实的参考工作为[LoopCTR](https://arxiv.org/html/2604.19550v1)。这里借鉴多流读写思路，未完整复现论文模型。

## 实验方案

目标：在两轮共享工作计算中，保留两条不同状态，并动态决定读取、写入或混合，检验是否优于原始Cross8和两轮去反馈基线。

每个查询槽维护a、b两个工作状态，均由入口表示初始化。首轮默认向a写入更新，b保留入口；次轮读取两流融合状态，再向两流写入更新。预测状态从首轮传到次轮，但不反馈工作状态。

路由包括1个读取、2个写入、2个旁路混合系数。各系数有可学习静态偏置；动态组只对指定系数增加输入相关投影，输入来自两流均值的RMS归一化表示。tanh限幅后，读取/写入范围±0.5、旁路±0.25。参数跨轮共享，零初始化与去反馈基线精确一致。

**dynamic_write只将写入变为输入相关；读取和旁路仍保留可学习静态系数。** collapsed_all在首轮预测后将两流合并，是dynamic_all的状态保留对照。

固定原始淘宝发布数据及标签、17动作ID，不用mature。宽度256、8查询槽、两轮；seed20262027、batch8192、1epoch/2193更新；dense PSGDKron每步预条件、LR1e-4，sparse Adagrad LR0.05，clip1、BF16。没有新增训练seed，不评估test。主指标为点击、加购、收藏、购买四任务AUC的算术平均。

## 成本与结论

Cross8参数54763844，dynamic_write参数54764361，仅增加517个参数；同卡、同1024行验证批次推理耗时约增加14.7%。10次预热、40次CUDA Event计时，排除加载、IO及传输。

保留dynamic_write为优化候选。收益来自当前双流及动态写入组合；本轮不能拆分各部件的独立贡献，也不宣称是不同宽度或协议下的全局最优。

统计采用500次共享用户聚类bootstrap，覆盖2871767行/268201用户；28个两两对照均保留。区间条件于固定训练seed，不包含训练随机性；验证集用于探索，未做多重比较校正。
