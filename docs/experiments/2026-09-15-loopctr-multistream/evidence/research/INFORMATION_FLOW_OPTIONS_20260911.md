# 信息流组织的下一步候选（2026-09-11）

状态：研究建议，未启动新训练，不改变既有最佳模型或实验记忆。

## 原文核对

本次检索未确认同名 LoopCVR；可核实的是人大与阿里的 [LoopCTR](https://arxiv.org/html/2604.19550v1)。以下不把两者直接等同。

原文 §3.2：历史 token 只读历史，全局 token 可读两类 token。§3.3：多残差流有独立的输入融合、残差混合、输出分发，系数依赖当前状态。§3.5：深度0…L共享出口并平均监督。由此得到的本地设计建议如下，均不是论文已经验证的淘宝四任务收益。

## 当前证据限定

参见 [最新累积实验](../recurrence-round-accumulation/RESULTS.md)：分轮携带相对分轮不携带有正向训练差值，但整体低于原两轮。点击有益、其他任务存在代价；槽与历史长度的干预差支持路径作用不均匀，不能把固定检查点损失差直接变成新模型训练收益。

[历史版本实验](../recurrence-history-versions/RESULTS.md) 已测预先计算的浅／深历史顺序，不能继续称历史编码完全未试；浅→深相对父模型macro区间跨零、延迟约+46.65%。[值条件化](../recurrence-value-content/RESULTS.md) 六组低于父模型；已有QueryMixing、memory concat、task-depth readout、query bias、prediction reset、辅助深度损失等近邻方案。早期查重笔记153次训练时的“未见”不能替代当前194次完成训练的核对。

## 1. 子层级多残差流（第一优先）

每个查询槽持有两份工作表示 a,b，仍为4槽，不改成8查询，也不把预测状态当作第二条工作流。共享子层读取动态融合的 a,b，输出再按另一套系数分发，同时保留旁路状态。读取权重、写入权重、旁路混合是三种不同控制。

简化设计记号（非原文等式）：u=R(a,b)，d=F(u,H)，[a',b']=P(a,b)+W(a,b)d。F是共享工作子层；预测状态只读工作流，不写回。

与上轮区别：上轮分轮系数在训练后对所有样本相同，只缩放已有更新；此处系数依赖当前状态，且两份未合并状态跨子层持续存在。动态参数可跨轮共享，无须显式轮次ID。

必要控制：原模型、双流固定路由、双流可学习静态路由、双流动态路由。双流各组相同工作宽度/调用次数；分别报告状态显存和计算。动态vs静态只能隔离输入条件化的局部增量，参数仍须核算；不要只与原模型比。

## 2. 原始证据与可写工作记忆分离

H保持只读，新增少量可写memory slots M，第一轮读取H后将中间发现写入M，第二轮分别寻址H与M，在读取结果层融合。关键是M作为独立可寻址状态持续更新，而非简单把z1拼进已有memory。

已有memory concat/值条件化负结果使它只能列为次优。对照必须包括同容量静态M、只读M、可写M，以及匹配数量的额外普通查询槽。若普通增槽也有相同收益，则不能归因于读写记忆。M的写入只用工作状态，不用预测状态。

## 3. 任务读取同一个循环状态库，保留浅层路径

工作循环共享，保存s0/s1/s2并采用不同任务条件读取。与已有固定深度加权相比，待测差异是由当前样本内容决定读哪个状态、哪个槽，以及在进入任务头前保持浅层路径。

这是假设：共享循环可能把点击所需变化与其他任务保留需求混在一起。现有结果并没有证明梯度冲突或遗忘。需固定工作核，先比较静态和内容条件读取；再比较是否联合训练，避免同时改动状态生成与读出后无法归因。任务标签只能用于训练损失，不能当路由输入。四任务不强制按点击→加购→收藏→购买串行。

## 4. 保留原始字段token，跨轮更新交互状态

用户／物品／上下文证据以字段token保留，另设可写交互token；两轮分别让交互token读取字段与历史。不同于仅在两轮之间额外读字段，此处字段不必先压进4个查询后才被后续计算访问。

可选单向依赖：历史→交互、字段→交互、交互→交互；预测→工作仍禁用。匹配对照先让同样字段token只在入口参与，再允许第二轮参与，固定投影和token数量。预期成本高于只循环4槽，需实测，不能套用论文服务KV复用节省来替代本地单候选延迟。

## 5. 共享寻址与内容变换分工

保持共同相似度空间，给不同状态流选择不同的小型内容变换，再循环。先从两个稠密分支开始，并保持总活跃宽度；用固定均分、内容路由对照，不直接增大MoE总容量。

它检验共享算子能否对不同状态执行不同变换，但与此前V条件化有近邻，优先级低于多残差流。必须用源自相同输入的控制排除增加容量带来的普通收益。

## 执行顺序建议

先做第1项四组，其他卡可用于事先定义的读取动态/写入动态拆分、以及容量匹配的单流对照，不能把八卡当成无控制拼装八种模型的理由。保持两轮、现有seed/PSGDKron/clip1、严格历史协议、无预测反馈。优先从原mature_r2出发，不从整体退化的分轮模型继续堆模块。

训练后先比较完整macro与四任务差值；再用独立用户组诊断读写通路，直接比较任务/槽/长度组效应。上一轮确认组已经影响新设计，不能继续将它称为新设计的独立确认集。多深度监督若后续加入，应单独成因子；无论论文的零loop表现多好，训练收益与同checkpoint额外计算收益必须分别测量。
