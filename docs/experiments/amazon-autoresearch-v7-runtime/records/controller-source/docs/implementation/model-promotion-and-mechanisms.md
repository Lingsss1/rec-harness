# 模型晋升与机制研究分离

新建 Amazon autoresearch 默认冻结 `selection_policy: baseline-positive-v1`。
已有 campaign/plan 没有此字段时继续原规则；不会重判 v5/v6 历史结果。
需要明确沿用旧规则的新任务可配置 `legacy-candidate-controls-v1`。

## 性能晋升

候选和本轮新生成的每个机制对照均独立比较当前 baseline。
开发宏平均主指标严格高于 baseline（差值 > 0）即取得确认资格，不再要求
候选优于所有对照，也不使用旧的 0.005 作为新策略的晋升阈值。
训练协议原值保留，读出同时记录实际选择阈值及协议原阈值。

独立初始化确认仍须通过：每个确认 seed 的类别宏平均都严格高于 baseline。
全部通过的模型保留资格记录；单一 incumbent 按事前冻结的开发分数降序选择，
同分优先候选，再按预注册对照顺序。确认结果不用于重新排序。
原有历史对照不自动当作新的候选反复晋升。最终测试仍独立。

主机指标决定性能资格；角色对机制的 discard 解释不否决满足条件的模型。
原始角色输出和知识结论保留，主机确认释放决定单独归档。
`promoted_model` 记录实际胜出的模型，下一轮可从生成对照继续。

## 自动机制记录

新策略的开发读出 `summary.mechanism_comparisons` 为每个非基线对照记录：

- 候选/对照身份、源码哈希及原始设计卡哈希。
- 机制、插入合同、证伪条件、替代解释、预测观察。
- 候选与对照各自相对 baseline 的收益，以及彼此差值。
- 每个类别、seed 的对比切片，包括负结果和零差异。
- `mechanism_status: unknown` 及后续区分竞争解释的研究要求。

记录随内容寻址开发读出存档，并写入研究图的 `mechanism_comparison`
Observation；绑定原开发 Experiment，声明不是额外独立实验。
knowledge 角色可据此追加解释，开发记忆中的读出保留这些记录供后继研究使用。
即使角色返回空知识补丁，主机记录也存在。

例如“最近三条历史”与“最早三条历史”的比较，应保存原始提案及两个实现身份，
之后研究时区分近期性、上下文长度、信息量等解释。模型胜出不会自动把其中
任何解释标为因果成立，仍需适当的后续干预或消融。

## 减少机械输出失败

新任务在角色调用前将已知 ID、seed、对照列表、实现文件清单、开发证据 hash
及预算范围写入输出 schema。保留原始响应和校验，未事后替换错误证据。
评分排名不一致、执行身份变化及未知传输结果仍按原规则阻断。
此改动降低机械字段出错空间，不声称已经修复所有 Harness 失败。
