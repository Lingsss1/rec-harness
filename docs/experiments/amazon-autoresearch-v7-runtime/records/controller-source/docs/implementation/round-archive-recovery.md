# 模型回合归档恢复

修复两个恢复边界：

1. 回合决定已归档为measurement_required、但round_completed尚未提交时，恢复必须再次设置measurement_required停止原因。否则项目可能把缺口当作普通回合结束，跳过应进入的工具流程。
2. 恢复不能因为node.json、decision.json和observations.json存在就采用其内容；它们是可修改的投影文件。现在只读取attempt_archived事件绑定的CAS内容，核对回合、父模型、原源码和协议身份后恢复投影。keep还须具有有效评估及可核验的新源码产物。

没有提交事件的文件不构成模型选择证据；沿用中断回合的crash/unknown处理，不允许伪造keep。提交档案损坏或身份不匹配则停止，不提交round_completed。已有decision_checkpointed路径保留，仍能恢复已提交主机决定而不重新训练。

新增五项工程测试覆盖测量暂停恢复、修改本地副本、未提交keep文件、损坏CAS、回合身份不符，以及项目入口的模型→工具→模型续接（后两类分别由单测及组合场景覆盖）。项目组合使用脚本角色、固定验证报告和模拟诊断；不证明真实工具效用。模型首回合恢复后评估次数不增加。

56项相关回归通过（12.517秒）；补充项目组合场景后，恢复模块五项通过（2.279秒）。未新增Codex调用或Amazon训练。任意角色调用中途的未知结果仍不自动重发，本修复针对已提交决定/档案的恢复，不宣称整个回合的每个指令都可无损重启。

完整源码回归557项全部通过、零跳过，154.210秒，包含Torch及显式Linux隔离。rec-harness-runs/round-archive-recovery-v1保存原始日志和源码/测试摘要；公开边界及diff检查通过。此前v24安装包不包含本轮与近期工具方法/历史变更。

## Amazon 适配器终止记录恢复

Amazon 控制器现在先恢复已提交的 auto_round_deferred / auto_round_failed，再执行下一回合的预算检查。即使剩余额度不足，已提交的 measurement_required 或 role_transport_failure 也不会被预算停止覆盖，不会重复进入该回合。普通失败消耗原回合并按既有规则继续；failure.json 从事件恢复。完成事件引用原终止事件，费用仍来自已有账本。

恢复只读取最近一次完成或显式重开之后的当前回合记录；冲突终止结果拒绝提交完成。完成事件已提交但 state.json 写入中断时，仍从事件恢复。尚未提交终止记录的任意中断不在此修复保证范围内。

新增五项测试覆盖两类暂停、普通失败、冲突记录与状态投影中断。Amazon 控制器、项目、审查恢复及进度相关39项测试通过（4.943秒）；公开边界和diff检查通过。此次没有Codex调用或真实训练。
