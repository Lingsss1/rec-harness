# 后继模型记忆与前驱绑定

新项目默认冻结 `verify_successor_memory: true`。模型→工具/Harness→模型的交接中，后继模型除继承已提交的 incumbent 外，还核对前驱事件链与项目已提交报告中的 integrity 完全一致。事件链本身合法但在提交后追加了内容，也不能悄然改变本次续接的来源。

首次创建 `source-memory.json` 使用现有公开记忆导出器；中断恢复发现缓存文件时，重新从前驱导出至临时目录，逐项比较 JSON 内容。格式与自身 hash 合法但来自其他任务、被删减或被替换的包均在后继 child 启动前拒绝；保留原文件供核查，不静默覆盖。临时核验文件自动清理。普通模型使用图记忆导出器，Amazon 使用排除确认材料的开发记忆导出器。

历史项目配置缺少该开关时维持原行为，避免新导出格式改写已冻结运行的续接语义。新项目开启后应保留其源码和导出版本；若导出规则变化，应建立新的项目，不将内容不一致解释为需要重跑模型。

`tests/test_project_successor_memory.py` 覆盖两类实际控制器路由在导出后、后继初始化前中断：替换为另一份可独立通过格式/hash 校验的包后，恢复在子运行前拒绝；还原原包后完成续接并精确恢复。另覆盖合法追加前驱事件的拒绝与旧配置兼容。阶段验证和 Amazon 训练使用测试替身，本项没有新增 Codex 调用或 GPU 训练，不是工具/Harness 正收益验收。
