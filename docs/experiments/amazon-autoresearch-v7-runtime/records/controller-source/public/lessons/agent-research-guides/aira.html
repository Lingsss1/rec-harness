POSITIONING

一句话定位

AIRA 的价值不只是一套更强 Agent，而是把 Agent-as-MLE 形式化为“搜索策略 × 算子集”。论文证明：换成 MCTS 或进化搜索并不会自动变强，算子和 Memory 作用域必须与策略共同设计。

先看结论

RecHarness 应把 Router、Skill/Operator 与 Memory 作为三项联合消融，而不是只替换路由算法。不同动作需要不同记忆视野：Debug 看 lineage，Idea/Improve 看 siblings，复盘才看全局。

SYSTEM DESIGN

设计思想：它改变了哪一层？

  1. 统一表示为 (F, π_sel, O, π_op, τ)：评分、选点策略、变换算子、算子路由和终止规则。
  2. AIRA 算子加入动态复杂度、Crossover 与 scoped memory；不同搜索策略在同一 dojo 中公平比较。
  3. Draft/Improve 只看 sibling memory 促进差异化；Debug 读取完整祖先修复链，避免 undo–redo。
01 State任务、workspace、预算与当前 artifact
02 Select选择分支、组件或阶段目标
03 Operate生成、修复、改进或组合代码
04 Evaluate执行并获得指标、错误与审阅信号
05 Remember写回持久状态并决定下一跳

MATHEMATICAL CORE

数学原理

Agent = (F, π_sel, O, π_op, τ) MCTS: h(v|u)=Q(v)+c·sqrt(log N(u)/(N(v)+ε)) Evolution: P(select v)=F(v)/Σ_u F(u)

该形式把“模型聪明不聪明”与“搜索结构好不好”解耦。MCTS 的 UCT 用不确定性奖金找未充分探索分支；进化策略按 fitness 比例选亲本，再用 Improve/Crossover 产生新解并淘汰最差个体。

阅读提醒：这些 Agent 多数不是在参数空间求可微最优，而是在 artifact/code space 做黑盒搜索。公式描述的是算力如何在候选之间分配，而不是替代真实实验。

MEMORY ARCHITECTURE

Memory 不是聊天记录

Write · 写什么所有 artifact 都保存 fitness、父子关系、操作类型与执行反馈；Memory 算子再生成供下一次操作使用的摘要。
Read · 谁在何时读Draft/Improve 读取当前节点的 children/siblings；Debug 读取整个祖先调试链。
Forget · 如何控噪通过 operator-specific scope 丢弃无关历史；思考 token 不写入共享 memory，避免其他算子继承噪声推理。

建议的数据结构

SearchAgent { F, selection_policy, operators, operator_policy, termination } MemoryScope(op) = sibling if op∈{Draft,Improve} ancestry if op=Debug

实现时应把 raw artifact 与 prompt view 分离：前者完整可追溯，后者按 operator/阶段动态裁剪。摘要只是读取视图，不应覆盖原始实验记录。

不能从论文直接推出什么

  • MLE-Bench 的 CV fitness 仍可能与私榜目标错位。
  • 搜索政策与算子存在强交互，单独比较某个模块容易得出错误结论。
  • 结果依赖高算力与长时间预算，工程吞吐本身也是系统能力的一部分。

DESIGN TRANSFER

迁移到 Ling 的项目

RecHarness 应把 Router、Skill/Operator 与 Memory 作为三项联合消融，而不是只替换路由算法。不同动作需要不同记忆视野：Debug 看 lineage，Idea/Improve 看 siblings，复盘才看全局。

最小复现顺序

  1. 先定义 artifact schema 与可重复的 evaluator。
  2. 只实现一种 operator 和一种 selection policy，得到可运行 baseline。
  3. 加入按作用域读取的 memory view，并记录重复试验率。
  4. 最后再增加并行、Crossover、Reviewer 或多角色，逐项做消融。
