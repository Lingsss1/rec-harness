POSITIONING

一句话定位

AIDE 证明了代码树搜索有效，但“把整棵树摘要给模型”仍然可能造成上下文污染。ML-Master 用 MCTS 式多轨探索，并只把父节点与同深度兄弟节点的经验送入推理过程。

先看结论

适合把 RecHarness Memory 拆成 lineage memory 与 sibling memory：前者用于延续当前模型方向，后者用于提醒同批候选中哪些改法已经失败，避免 LLM 重复试验。

SYSTEM DESIGN

设计思想：它改变了哪一层？

  1. UCT 在高回报与低访问次数之间平衡，避免所有算力只投向当前冠军。
  2. Draft / Debug / Improve 对应不同程序状态；停滞次数和连续 Debug 深度构成剪枝规则。
  3. Memory 进入 reasoning/think 上下文，父节点保证连续性，兄弟节点提供对比信号与去重线索。
01 State任务、workspace、预算与当前 artifact
02 Select选择分支、组件或阶段目标
03 Operate生成、修复、改进或组合代码
04 Evaluate执行并获得指标、错误与审阅信号
05 Remember写回持久状态并决定下一跳

MATHEMATICAL CORE

数学原理

UCT(v) = Q_v / N_v + C · sqrt( ln N_parent / N_v ) c_t = R_θ^think(x, M_t) ; r_t = ε(c_t) M_t = {(r_parent, f_parent)} ∪ {(r_sibling, f_sibling)}

第一项是经验平均收益，第二项是探索奖励。N_v 小的节点拥有更高不确定性奖金；C 控制探索强度。停滞剪枝可写成 Σ_i I[Δ_i < threshold] > τ_improve，从而停止对无产出的分支继续投资。

阅读提醒：这些 Agent 多数不是在参数空间求可微最优，而是在 artifact/code space 做黑盒搜索。公式描述的是算力如何在候选之间分配，而不是替代真实实验。

MEMORY ARCHITECTURE

Memory 不是聊天记录

Write · 写什么保存执行指标、编译/运行日志、错误诊断、代码片段，并从完整推理中抽取 salient insight。
Read · 谁在何时读只读直接父节点和同层兄弟节点；父节点提供纵向因果链，兄弟节点提供横向反例。
Forget · 如何控噪用作用域选择代替全历史检索。更老祖先只通过父节点的已蒸馏结论间接保留。

建议的数据结构

AdaptiveMemory(t) { lineage: [parent.insight, parent.feedback], contrast: siblings.map([insight, feedback]), excludes: unrelated_depths + raw_long_logs }

实现时应把 raw artifact 与 prompt view 分离：前者完整可追溯，后者按 operator/阶段动态裁剪。摘要只是读取视图，不应覆盖原始实验记录。

不能从论文直接推出什么

  • 论文版本未给出完整消融，难以单独量化 memory、并行与骨干模型的贡献。
  • 同层兄弟并不天然相关；分支定义不合理时，作用域仍会带来噪声。
  • UCT 的标量回报无法表达新颖性、稳定性、资源成本等多目标权衡。

最小复现顺序

  1. 先定义 artifact schema 与可重复的 evaluator。
  2. 只实现一种 operator 和一种 selection policy，得到可运行 baseline。
  3. 加入按作用域读取的 memory view，并记录重复试验率。
  4. 最后再增加并行、Crossover、Reviewer 或多角色，逐项做消融。
