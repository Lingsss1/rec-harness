逐页答辩稿

1

实习转正答辩

各位评委老师好，我是凌浩然，来自电商策略算法部电商短视频广告模型组。今天我主要汇报实习期间围绕推荐模型优化所做的三部分工作：第一是 RecHarness 长周期模型优化框架；第二是短视频和货架电商两轮真实 LR；第三是为 Agent 提供模型内部反馈的 RecKit 诊断工具。

这三部分其实围绕同一个问题：当单次实验已经能被 Agent 自动执行后，怎样让它在几十个版本、有限实验预算和稀疏反馈下，持续做出更好的下一步决策。

2

目录

接下来我会先简单介绍个人背景，然后重点汇报工作内容，最后总结实习收获和后续规划。工作内容部分我会按照“方法框架—真实业务验证—诊断能力补全”的顺序展开。

3

个人简介

我目前在 Georgia Tech 读硕士。此前在 Shopee 做过大模型和 SEO Agent 相关工作，因此进入快手实习后，我重点探索了 Agent 与推荐模型优化的结合。

实习期间，我的主要工作包括：参与 RecAgent 应用；以第一作者完成 RecHarness 的问题归纳、方法设计和实验验证；参与短视频和货架电商精排模型的长周期迭代；以及研究并实现模型内部诊断方法。

这里我想强调，我的工作并不是单独研究 Agent，或者单独做推荐模型，而是尝试把两者组织成一个能在真实工业约束下运行的系统。

4

工作内容回顾

我的工作可以分成两条线：一条是业务优化，即两个真实精排 LR；另一条是技术探索，即 RecHarness 和 RecKit。业务项目为方法提供真实问题和实验轨迹，方法研究反过来帮助我们组织下一轮业务实验。

5

工作时间线

从时间线上可以看到，这些工作并不是彼此独立的。前期我先完成 RecHarness 的方法设计和公开数据集验证；同时在短视频 LR 中经历了调参、ML-DCN、特征接入和序列结构迭代。随后在货架 LR 中，从 Cross Attention 等表征增强，切换到 IPS、DR、SNIPS 和 batch 充分性排查。后期我把两轮 LR 中暴露出的反馈不足问题，沉淀为 RecKit 诊断工具。

因此整段实习形成的是一条闭环：框架提出问题，业务实验提供证据，诊断工具提高反馈密度，再反哺下一轮 Harness。

6

RecHarness 动机

RecAgent 已经解决了单次实验的原子能力，例如读资料、改代码、提交训练和查看指标，也已经能稳定调用多个内部平台。

但在短视频 CVR 实践中，我发现模型优化不是一次任务，而是长程搜索：单轮反馈以天计，往往跨越几十个版本；有些实现错误甚至要训练 48 小时后才暴露。此时瓶颈不再是实验能不能跑起来，而是三个问题：下一步方向怎么选、失败经验怎么保留、人与 Agent 在哪里分工。

因此我提出 RecHarness：在有限预算下选择方向，用实验轨迹保存成功与失败证据，并用 Human-gated ReAct Loop 控制搜索空间切换和上线准入。

一句话概括：RecAgent 解决单次实验执行，RecHarness 解决跨版本的长程组织。

7

论文定位与个人贡献

基于这个工业问题，我以第一作者完成了 RecHarness 论文。论文研究的问题是：在有限 trial 预算下，如何自动分配下一次推荐模型优化方向。

我的主要贡献包括三部分：第一，把工业模型迭代抽象成带反馈、带成本的方向分配问题；第二，设计 Bandit Router、Basin-aware Jump 和 Memory 驱动的实验生成闭环；第三，在 Amazon 和 KuaiRec 上完成跨数据集、跨主干验证。

需要明确的是：Bandit 选择的是语义优化方向，具体代码修改仍由 Agent 在该方向内结合当前模型、日志和 Memory 生成。

8

RecHarness 三层结构

RecHarness 分为三层。

第一层是人定义上下文：包括目标、验证指标和候选修改方向。因为业务目标、风险和上线门槛不能完全交给 Agent 自己决定。

第二层是 Bandit Router：根据历史实验结果维护各方向的后验，在有限预算下决定哪些方向更值得继续尝试；当局部搜索长期停滞时，开放 Jump Arms。

第三层是实验执行：Agent 在选中方向内读取 incumbent、成功经验、失败 Memory 和验证趋势，生成假设、修改代码、训练并验证。

所以它不是一个完全自治的黑盒，而是一个有清晰职责边界的三层闭环：人定义任务和边界，Bandit 分配预算，Agent 执行实验。

9

从反馈到下一轮试验分配

这一页是 RecHarness 的核心决策过程。

首先，把一次实验结果转成成功信号。这里的成功不是简单看指标是否大于零，而是同时要求实验有效、优于当前方向的平均候选，并且不低于历史最优模型。

随后，用二元成功或失败更新每个方向的 Beta 后验。成功增加 alpha，失败增加 beta，因此失败实验也会减少同类方向后续获得的预算。

下一轮使用 Thompson Sampling 从后验中采样，选择 Top-G 方向。它兼顾利用和探索：高收益方向更容易被选中，不确定但有潜力的方向仍保留机会。

如果最近 W 轮最优分数的提升速度低于阈值 tau，系统只会开放 Jump Arms 参与选择，并不会强制跳转。结构变化还需要重新调参和验证后，才能替换 incumbent。

这页最重要的不是公式本身，而是闭环：结果变成证据，证据更新方向后验，后验决定下一轮预算。

10

跨数据集与跨模型验证

我们在 Amazon Reviews 的 4 个数据集、5 类主干，以及 KuaiRec 的 3 类模型和 4 个指标上进行了验证。

Amazon 上，RecHarness 在多个数据集和主干中普遍优于 cold-start Base；KuaiRec 上，D2Q 的 WT-XAUC 相对 Base 提升 12.00%。同时，TPM 的 WR-MAE 相对 Base 改善 26.41%，说明 Harness 不只对序列推荐的单一排序指标有效，也能迁移到不同模型和评价目标。

这里我的结论会保持在实验边界内：这些结果证明了方向分配机制具有一定跨模型、跨指标泛化性，但并不等同于已经证明对所有工业推荐场景都有效。

11

搜索效率

相比随机搜索，在相近实验预算下，RecHarness 的有效试验为 23/48，随机搜索为 11/49，对应命中率 47.92% 和 22.45%，约提升 2.1 倍。

两者单次有效实验的平均增益接近，分别是 5.06% 和 4.94%。这说明主要收益不是把每个候选都变得更强，而是更频繁地把有限预算投到正确方向上。最大增益达到 24%，也说明 Thompson Sampling 没有完全放弃高不确定、高潜力方向。

因此这里的核心指标是搜索效率，而不是宣称 Agent 生成单个结构的能力提升了 2.1 倍。

转场：接下来用两个真实 LR 说明，这套“局部搜索—失败积累—Basin 切换”的逻辑在业务中具体怎样发生。

12

短视频 LR：旧 Basin

短视频 LR 的目标是在现有 CVR 模型上寻找可上线增量，并保持共享主干、任务头和线上时延基本不变。

初始搜索空间集中在序列已经聚合后的表示增强。我们尝试了多组调参与优化器配置、ML-DCN 主塔和子塔变体，以及 a2a 特征接入。a2a 的 v24 存在接入问题，v25 修复后仍然持平；其他结构也没有稳定增益。

这些失败的共同点是：改动都发生在序列已经聚合之后。继续扩容并没有触及原始信息流。因此失败实验不是被丢弃，而是共同构成了一个 Jump 信号：当前 Basin 的局部收益接近上限，需要重新定义搜索空间。

13

短视频 LR：切换 Basin

这里要区分 Jump Estimator、人和 Agent 的职责。

Estimator 只根据连续失败判断旧方向可能饱和，不负责凭空生成新方向。人补充模型外的业务 Context：8 路行为序列中已有 2 路包含 Self-Attention，其余 6 路缺少原始 item 与 item 的交互；同时 HSTU 处理的是主干压缩后的虚拟 token，而不是原始行为序列。

基于这个诊断，人把新 Basin 定义为 Sequence Encoder Upgrade。Agent 再结合 Memory 生成具体可验证假设：在 Target Attention 聚合前增加 Self-Attention，显式建模历史 item 之间的二阶交互；同时保持任务头和损失不变，以便控制归因。

所以这里的人机分工是：人负责定义 Basin、注入业务 Context 和工程边界；Agent 负责在新方向内形成假设、实现、查证和实验。

14

短视频 LR：最终结构

原模型先处理用户和商品稀疏特征、统计特征、预训练向量和历史行为序列。稀疏字段通过 SENET 和 Cross 建模字段权重与显式交互；历史序列使用当前候选作为 Query，通过 Target Attention 聚合。

这次改动位于序列聚合之前：对其余六路原始序列分别加入 Self-Attention，让每个历史 item 先与同一序列中的其他 item 交互，再聚合为固定长度表示并进入原有特征拼接。

后面的 Share-bottom、虚拟 token 投影、HSTU、CTCVR 主任务和辅助任务保持不变。这样一方面精准补齐原始序列交互缺口，另一方面把参数和时延变化控制在较小范围，并把实验归因集中到这一处结构差异。

这里容易被误解的一点是：HSTU 并没有直接处理原始行为 item；它处理的是共享主干压缩后的虚拟 token。新增 Self-Attention 和 HSTU 位于不同信息层级。

15

短视频 LR：线上效果

最终方案在 2026 年 6 月 15 日到 6 月 21 日进行了 A/B，每组流量为 11.08%。

我会重点汇报统计显著的内循环大盘结果：总曝光提升 0.156%，p 值 0.03，置信区间为 0.01% 到 0.30%；总预期花费提升 0.478%，p 值 0.01；总全局后验预期花费提升 0.592%，置信区间为 0.29% 到 0.89%。

其他大盘存在方向性变化，但未达到统计显著，因此不将它们作为稳定收益宣称。这个实验支持的结论是：补齐原始序列内部交互，对内循环短视频流量产生了稳定正向增量；不能据此宣称所有场景均显著提升。

16

货架 LR：表征方向接近上限

货架 LR 的目标是提升 CVR 和 CTCVR。初始模型是 ESMM 加 HTLNet，点击率约 2%，转化反馈至少延迟 24 小时，训练信号非常稀疏。

最初的默认假设是表示能力不足，因此围绕 Cross Attention、商品属性独立通道与 Gate、NISE 辅助监督进行了多轮尝试，但都没有形成稳定增量。

这些失败让我们重新提出问题：瓶颈真的是表示不够，还是因为 CVR 只在点击样本空间可观察，导致训练数据存在选择偏差？这一步把搜索从 Representation/Fusion Basin 切换到了 Objective/Gradient Basin。

17

货架 LR：反事实学习与 Local Arms

人结合业务数据补充了两个关键 Context：CVR 只有点击后才可观察，CTCVR 正例率约为 0.14%。因此我们以 ESCM² 为结构锚点，把新 Basin 定义为 Counterfactual Learning。

进入新 Basin 后，并不是一次就得到最终方案，而是继续做局部搜索。

第一，检查 IPS/DR 权重，发现原始 clip 使约 80% 点击样本的权重失去区分度。第二，采用 SNIPS，在点击子集内按权重均值归一，保留相对差异并控制方差。第三，隔离 Imputation 辅助塔的共享梯度，避免辅助误差估计污染主任务表征。第四，检查样本充分性，把 batch 从 512 提升到 4096。

在 0.14% 正例率下，batch 512 平均每次更新只有约 0.7 个正例，而 4096 约有 5.7 个正例。更大的 batch 不是简单追求训练更稳，而是让 DR/SNIPS 的点击子集统计量有基本的样本支撑。完整实验的 CVR/CTCVR AUC 约提升 0.29 个百分点。

18

货架 LR：最终结构与 DR 直觉

最终方案由三个关键部分组成。

第一，Imputation Tower 估计每个样本当前 CVR 模型可能产生的训练误差。它估计的是 loss，不是给未点击样本制造一个真实转化标签。

第二，在点击样本上，我们能够观察真实支付标签，因此可以计算真实 CVR loss，再用 SNIPS 权重对“真实误差减估计误差”的残差进行修正。直觉上，辅助塔先给一个全样本误差基线，点击样本再负责纠偏。

第三，Imputation Tower 可以读取共享特征，但通过 stop-gradient 隔离回传。共享表征仍由 CTR/CVR 主任务更新，避免误差估计任务反向污染主干。

这里的 Double Robust 直觉是：如果 propensity，也就是 pCTR 估计准确，IPS 残差校正有效；如果 Imputation 估计准确，残差本身很小，对 propensity 偏差就不那么敏感。

19

货架 LR：线上结果

最终方案为 ESCM²-DR-SNIPS、辅助塔梯度隔离和 batch 4096。A/B 从 7 月 27 日到 8 月 2 日，共 7 天；实验组流量 16.04%，对照组 21.40%，后续还进行了 3 天 AA 检查。

货架整体表现为曝光下降 1.089%，消耗提升 0.975%，预期花费提升 1.488%。细分场景中，商品卡、猜你喜欢、商城和买直页面均呈现曝光下降、消耗或预期花费上升的组合。

这一页现场不要直接说“效率显著提升”。更稳妥的表述是：模型改变了流量和预算分配，使曝光更集中于高预期价值样本；这组截图本身只支持投放结构变化，最终业务收益仍需结合支付、转化、ROAS 和显著性口径综合判断。

20

为什么还需要 RecKit

两轮 LR 暴露了同一个不足：AUC、Loss 和 PCOC 只能告诉 Agent 实验成功或失败，却不能区分失败背后的原因。

同样是没有收益，可能是特征根本没被模型使用、模块冗余、多任务之间存在冲突，或者训练样本和配置不充分。如果 Agent 只能读取 AUC，就只能基于结果猜方向。

因此我设计 RecKit，把 Ranking、Shuffle/Zero、多任务诊断、特征交互和样本充分性分析封装成工具，为 Harness 产生结构化内部证据。目标是把闭环升级为：观察模型、调用工具、生成假设、实验验证、写回 Memory。

21

RecKit：梯度敏感性 Ranking

当前尝试模型包含 40 个语义分支，经过 Share-bottom、HSTU delta 和 post-HSTU 表征后进入 CTCVR 任务。

对每个模块，我计算 activation 与 loss gradient 绝对乘积的平均值，也就是 activation × gradient 敏感性，再综合 CTCVR 任务和 Total Loss 的排名。

高敏感模块，例如 Target Attention，可以优先进入 Scaling 或结构分析；低敏感模块，例如当前快照中的 DPO、AI Tag 等，只被标记为冗余候选，后续还必须通过 Shuffle 或 Zero 扰动验证。

Ranking 是低成本筛查，不是最终因果结论。它回答“模型当前对谁敏感”，而不是直接回答“删除谁一定不会掉点”。

22

RecKit：post-HSTU 配对 Shuffle

为了验证 Ranking 是否具有区分度，我把 post-HSTU 的 1024 维表征连续拆成 64 个 16 维块，根据梯度敏感性分为 Top、Middle 和 Bottom 三档，每档选择 5 块，共 80 维做配对 Shuffle。

Shuffle 使用同一 permutation 在 batch 内跨样本置换，尽量破坏该坐标与当前样本的对应关系，同时保留边际分布。

结果上，Top、Middle、Bottom 三档的相对 ΔLoss 分别是 2.276%、1.473% 和 0.916%，平均预测变化也保持相同顺序。它说明 64 块 Ranking 对当前 CTCVR 塔依赖具有初步区分度。

但这些是连续坐标块，不天然对应可解释的语义模块，所以这一实验验证的是 Ranking 的分档能力，而不是直接生成可删除模块清单。

23

RecKit：Target Attention 与 DPO 对照

这一页进一步对语义模块进行配对 Shuffle。对 1184 个配对 batch，Target Attention Shuffle 后平均 ΔLoss 为 0.0006154，相对变化 7.05%，95% 置信区间完整位于零右侧；平均预测变化为 0.0008876。

DPO Shuffle 的平均 ΔLoss 接近零，置信区间跨过零。因此在当前模型快照和当前 CTCVR 目标下，我们观察到模型强依赖 Target Attention 的样本—表示对应关系，但没有观察到对 DPO 的明确依赖。

这里仍要保持证据边界：DPO 没有观察到依赖，不等于它在所有任务、所有切片或所有训练阶段都没有价值；还需要 Zero、重训消融以及其他任务指标确认。

B. RecHarness 方法

05为什么使用 Thompson Sampling，而不是 UCB、贝叶斯优化或直接让 LLM 选方向？＋

建议回答：

方向级反馈是稀疏、带噪且预算有限的，Thompson Sampling 能用简单后验同时表达历史成功率和不确定性，并自然平衡探索与利用。UCB 也可以作为替代基线；贝叶斯优化更适合连续或结构化超参空间，而这里的 Arm 是语义方向；直接让 LLM 选方向缺少稳定的累计反馈机制，也更容易受提示和近期日志影响。当前选择重点是低复杂度和可解释，后续可以比较非平稳 Bandit 或 contextual bandit。

06为什么把连续指标压成 0/1 成功信号？会不会丢信息？＋

建议回答：

会丢失增益幅度信息，这是当前方法的简化。好处是对不同指标尺度和噪声更稳健，也便于用 Beta-Bernoulli 后验。我们通过“实验有效、优于方向平均、不低于历史最优”减少偶然正增益。后续可把增益幅度、方差和成本纳入 reward，使用 Gaussian、ordinal 或 cost-aware posterior。

07成功阈值为什么这样定义？会不会偏向保守，导致无法探索？＋

建议回答：

阈值的作用是防止小噪声被当成成功。探索不是由降低成功门槛实现，而是由 Thompson Sampling 对高不确定 Arm 的采样概率保证。若业务噪声更大，可以把硬阈值改为基于置信区间或最小可检测效应的概率成功信号。

08Basin 和 Arm 怎么定义？是否过于依赖人工？＋

建议回答：

Arm 是一个可执行的局部修改语义，例如输入特征、表示融合、目标梯度、训练优化和容量正则；Basin 是一组共享核心假设的 Arm 集合。当前由人定义是为了保证业务语义、工程可行性和风险可控。Harness 的目标不是消灭人工，而是减少人在每一个具体实验上的重复决策。未来可以从历史轨迹中学习 Arm 聚类和 Basin 边界，但仍保留人工准入。

09Jump 的 W 和 tau 怎么设置？是否容易误跳？＋

建议回答：

W 和 tau 是预算与噪声相关的超参数，需要在历史轨迹上回放选择。Jump 信号只开放 Jump Arms，不强制切换；新结构还需要 Retuning 和验证才能替换 incumbent，因此误报的成本受到控制。更稳健的版本可以结合斜率置信区间、连续失败簇和剩余预算，而不是只看单一阈值。

10非平稳问题怎么处理？模型变了以后旧后验还可靠吗？＋

建议回答：

这是当前方法的重要局限。结构大幅变化后，旧 Basin 的后验不一定可迁移，因此 Jump 后应重置或折扣相关 Arm 的历史权重，并区分全局经验和当前 Basin 经验。后续可以使用滑动窗口、时间衰减或层级贝叶斯后验。

112.1 倍提升是否公平？＋

建议回答：

比较使用相近预算，48 对 49 个 trial，且有效试验定义一致。2.1 倍指有效试验命中率 47.92% 对 22.45%，不是最终指标提升 2.1 倍。单次平均增益相近，说明优势主要来自预算分配。仍需承认候选空间、随机种子和执行 Agent 会影响结果，因此论文还应报告多次运行和置信区间。

12Memory 具体存什么？怎么避免错误经验污染？＋

建议回答：

至少存四类信息：实验配置与代码 Diff；指标和日志证据；成功或失败原因；结论的适用条件和 Avoid Rule。Memory 不直接把自然语言总结当事实，而应绑定原始日志、提交和实验 ID。写入前做证据校验，使用时按模型版本和 Basin 检索；高风险规则需要人工确认，并支持撤销和版本化。

C. 短视频 LR

13Target Attention 和 Self-Attention 有什么区别？＋

建议回答：

Target Attention 的 Query 是当前候选，Key/Value 是历史行为，它解决“历史中哪些 item 与当前候选相关”；Self-Attention 的 Q/K/V 都来自同一条历史序列，它解决“历史 item 之间有什么上下文关系”。两者互补：先用 Self-Attention 建模序列内部交互，再由 Target Attention 或聚合模块得到候选相关表示。

14模型里已经有 HSTU，为什么还需要 Self-Attention？＋

建议回答：

因为两者输入层级不同。当前 HSTU 接收的是 Share-bottom 压缩后的 1024 维表征，并 reshape 为虚拟 token；它不是直接对每条原始行为序列中的 item 建模。新增 Self-Attention 位于原始序列聚合前，直接补齐 item×item 交互，因此不是重复堆 Attention。

15为什么只补六路？为什么不是八路一起重构？＋

建议回答：

已有两路已经包含 Self-Attention，其余六路存在结构缺口。只补齐缺失分支可以控制参数量、时延和归因，同时保持已有稳定路径不变。若八路全部重构，会同时改变过多变量，不利于判断增益来源。

16为什么 Self-Attention 放在聚合前有效，而扩 MLP、ML-DCN 无效？＋

建议回答：

扩 MLP 和 ML-DCN 都发生在序列已经被压成固定向量之后，只能增强聚合后表达，无法恢复被聚合丢失的历史 item 关系。Self-Attention 在信息丢失前建模二阶交互，解决的是信息结构缺口，而不是单纯容量不足。

17如何证明收益来自 Self-Attention，而不是参数量增加？＋

建议回答：

当前实验通过保持共享主干、任务头和损失不变，已经缩小了归因范围，但严格证明还需要参数量匹配的 MLP/Pooling 对照、随机序列对照或关闭位置关系的消融。如果这些等参数基线没有相同收益，才能更强地支持“序列交互”而非“容量增加”。

18线上结果为什么只强调内循环大盘？＋

建议回答：

因为内循环大盘的曝光和预期花费达到统计显著，其他场景多数置信区间跨零。答辩中只把显著结果作为稳定证据，其他指标只能作为方向性观察。这也是我希望保持的证据边界。

D. 货架 LR、IPS、DR、SNIPS

19CVR 不是 0/1 标签吗？为什么说存在不可观测？＋

建议回答：

支付标签本身是 0/1，但条件 CVR 定义为点击后支付概率。对未点击曝光，我们没有观察到“如果它被点击是否会支付”的反事实标签。训练只使用点击样本会改变样本分布，因此产生点击选择偏差。

20IPS、DR、SNIPS 的全名和作用分别是什么？＋

建议回答：

IPS 是 Inverse Propensity Scoring，用点击倾向概率的倒数重新加权点击样本，修正选择偏差；DR 是 Doubly Robust Estimation，同时结合 propensity 加权和 Imputation 误差估计，只要其中一部分较准确，估计仍可能较稳健；SNIPS 是 Self-Normalized IPS，在当前点击子集内对权重做归一化，以降低权重尺度和方差问题。

21Imputation Tower 预测的到底是什么？＋

建议回答：

它预测的是当前 CVR 模型对该样本可能产生的训练误差，例如 BCE loss 的估计值，不是预测一个可以当作真实标签的转化结果。点击样本上可以计算真实误差，再用真实误差与估计误差的残差进行校正。

22DR-CVR 是修改 CVR Loss，还是修改 CTCVR Loss？＋

建议回答：

它主要是对存在选择偏差的 CVR 风险估计进行修正，形成额外的 DR-CVR 训练目标。CTCVR Loss 仍然描述曝光到支付的联合事件，可以作为另一项监督共同训练 CVR 路径。具体总 Loss 是多项相加，而不是把 CTCVR Loss 内部直接替换成 DR 公式。

23为什么 Imputation Tower 不回传到共享底座？＋

建议回答：

辅助塔学习的是“主模型误差的估计”，其目标本身带噪。如果允许它更新共享底座，模型可能为了让误差更容易被估计而改变共享表征，反向污染 CTR/CVR 主任务。因此让它读取共享特征，但 stop-gradient 隔离共享回传；辅助塔只优化自身参数。

24为什么 CTCVR Loss 能让未点击样本更新 CVR 塔？＋

建议回答：

对未点击样本，曝光后支付标签一定是 0。联合预测为 pCTCVR=pCTR×pCVR，因此 CTCVR BCE 会压低联合概率。若 pCTR 在这项中 stop-gradient，梯度仍可沿 pCVR 路径进入 CVR 塔，所以未点击样本能够作为联合事件负样本约束 CVR。但它提供的是联合事件监督，不等于观察到了条件 CVR 的真实标签。

25为什么不让 CTCVR Loss 同时更新 CTR 塔？＋

建议回答：

CTR 已经由全部曝光样本上的点击标签直接监督，信号更充分。如果 CTCVR 稀疏联合目标再沿乘法路径更新 CTR，CTR 表征容易被支付目标牵引，破坏点击校准。因此在联合 Loss 中 stop-gradient(pCTR)，把该项主要作为 CVR 路径的全样本约束。

26batch 512 为什么不够？4096 为什么有效？＋

建议回答：

这里关键不是线上数据还是离线数据，而是一次参数更新看到多少有效正例。正例率约 0.14% 时，batch 512 平均只有约 0.7 个正例，很多 batch 可能没有正例；DR/SNIPS 的点击子集归一和残差估计方差很大。batch 4096 平均约 5.7 个正例，使每次更新中的权重均值和残差估计更稳定。它改善的是估计器的样本充分性，而不仅是一般意义上的梯度平滑。

27为什么原始 IPS clip 会让约 80% 样本失去区分度？＋

建议回答：

IPS 权重与 1/pCTR 成正比。如果对分母或权重做较强截断，大量低 pCTR 点击样本都会落到同一个最大权重，它们之间原本的倾向差异被抹平。放宽截断又会带来高方差，因此后续采用 SNIPS 保留相对权重，同时稳定整体尺度。

28货架线上曝光下降、消耗上升，凭什么说模型更好？＋

建议回答：

仅凭这一页不能直接证明效率提升。它能说明排序改变了流量分配，曝光更集中于高出价或高预期价值样本。是否更好还需要支付转化、ROAS、预算完成度、显著性和长期稳定性共同判断。因此我不会把“消耗上升”直接等同于“效率提升”，而会把它作为线上投放结构变化，并结合完整业务看板做最终判断。

E. RecKit 与模型诊断

29activation × gradient 为什么能表示模块重要性？＋

建议回答：

一阶泰勒近似下，如果把激活扰动为零，Loss 的变化近似为 activation 与对应 gradient 的内积。因此 |a×∂L/∂a| 可以低成本估计当前 Loss 对该模块输出的局部敏感性。但它只是一阶、局部、相关性的筛查指标，可能受尺度和饱和影响，所以需要 Shuffle/Zero 进一步验证。

30为什么要同时看 CTCVR 排名和 Total Loss 排名？＋

建议回答：

只看 Total Loss 可能被样本更丰富的辅助任务主导，只看 CTCVR 又可能忽略对其他任务的破坏。综合排名用于筛出既影响核心转化目标、又在总体任务中重要的模块；同时也可以单独分析排名分歧，定位多任务冲突。

31Shuffle 和 Zero 有什么区别？＋

建议回答：

Zero 同时破坏模块的信息和幅值分布，容易引入分布外输入；Shuffle 尽量保留边际分布，只破坏样本与表示的对应关系，因此更适合验证模型是否依赖该对应关系。两者都不是重训消融：Shuffle 更接近依赖性干预，Zero 更像关闭模块，最终仍需 retrain ablation 验证结构价值。

32为什么用同一个 permutation 跨样本 Shuffle？＋

建议回答：

同一个 permutation 能保证被选中的坐标块在样本维度上以一致方式错配，避免不同维度使用不同随机映射而制造额外噪声。原始值分布基本保留，但当前样本与这块表示的对应关系被破坏。

33Top > Middle > Bottom 能证明 Ranking 正确吗？＋

建议回答：

它只能说明当前 Ranking 对 post-HSTU 连续坐标块的模型依赖具有初步单调区分度，不能证明每一个坐标排名都准确，也不能直接映射成语义模块。还需要更多随机种子、不同 batch、不同模型快照和 Zero/重训消融。

34DPO Shuffle 不显著，是否应该直接删除？＋

建议回答：

不能。当前结果只表示在当前快照、当前 CTCVR 目标和当前样本上，没有观察到明确依赖。DPO 可能影响其他任务、特定人群或训练过程，也可能与其他模块存在替代关系。删除前至少需要多任务诊断、Zero、分切片测试和 retrain ablation。

3595% CI 用 N=1184 个 batch 是否满足独立性？＋

建议回答：

当前置信区间把配对 batch 近似视为独立观测，是工程上的初步估计。如果 batch 来自相邻时间或存在用户重复，独立性可能被高估。更严格的做法是按用户或时间块做 cluster bootstrap，或者对多个数据窗口重复实验。因此这里把 CI 作为筛查证据，而不是最终线上因果结论。

36诊断工具怎样真正帮助 Agent，而不是增加更多指标？＋

建议回答：

关键是把工具输出映射成可执行假设，而不是堆报表。例如高敏模块进入 Scaling 或结构增强候选，低敏模块进入 Shuffle/Zero，任务排名分歧触发梯度冲突诊断，正例不足触发 batch/采样检查。每个工具都要定义适用条件、输出 schema、下一步动作和 Avoid Rule，才能成为 Agent 的决策接口。

F. 安全、落地与未来规划

37Harness 自进化会不会把错误经验越积越多？＋

建议回答：

这是必须重点控制的风险。我的设计不是允许 Agent直接修改生产 Harness，而是从轨迹提出局部 Patch，通过离线回放、对照实验和人工审核后才合入；所有 Skill、Routing 和 Memory 都版本化并支持回滚。原始证据与总结分离，避免一句错误自然语言结论覆盖实验事实。

38哪些决策永远不能完全交给 Agent？＋

建议回答：

业务目标和约束、实验预算、搜索空间重大切换、上线准入、回滚策略，以及涉及用户体验和收入风险的决策都应保留人工责任。Agent 可以提出建议和证据，但最终负责人必须可追溯。

39下一阶段最小可落地版本是什么？＋

建议回答：

先不追求完整 Self-evolving。第一阶段只把 Ranking、Shuffle 和样本充分性检查封装成三类 Rec-Skill，并规定输入输出；第二阶段接入现有实验轨迹，自动生成候选但不自动执行；第三阶段做离线回放，比较是否减少无效实验；通过后再开放有限的自动执行权限。

40如何评价 Harness 是否真的在进化？＋

建议回答：

不能只看最终 AUC。应同时评价相同预算下的有效试验命中率、达到目标所需 trial 数、重复失败率、错误恢复率、人工介入次数、结论可复现率和线上风险。只有新版本在固定回放任务上稳定优于旧版本，且没有扩大风险，才接受更新。

现场表达的五个风险点

  1. **不要说“Agent 自动发现了最终方向”。**更准确：Estimator 判断旧 Basin 饱和，人补充 Context 并定义新 Basin，Agent 在新 Basin 内生成和执行候选。
  2. **不要把 RecHarness 的 2.1 倍说成模型指标提升 2.1 倍。**它是有效试验命中率提升。
  3. **不要把短视频全部大盘都说成显著。**PPT 中稳定证据集中在内循环大盘。
  4. **不要把货架“曝光下降、消耗上升”直接说成效率提升。**必须补充转化、ROAS、预算和显著性口径。
  5. **不要把 Shuffle 说成严格因果证明或可直接删模块。**它是保持边际分布、破坏样本对应关系的依赖性干预；最终结论需要重训消融。
