先给结论

TayFCS 是目前四篇里最直接贴近推荐特征工程、证据也最完整的一篇，但它诊断的是“哪些 field 组合值得显式构造”，不是“模型哪个内部模块应该 scaling”。

对 Kai v2 的现实意义：代码里已经显式构造 194 个 user field × 30 个 photo field = 5,820 个配对信号。TayFCS 可作为“交叉候选粗排 + 去冗余”的论文基线，检验这些交叉是否值得全保留、是否还缺少跨组二/三阶组合。

1. 它解决什么

困难

F 个 field 的所有非空组合有 2F-1-F 个。把所有组合先做成 hash embedding 再学习 gate，内存、训练和筛选时间迅速爆炸。

论文策略

候选组合的重要性已经“藏在 Base 对各 field embedding 的梯度里”。先用梯度外积近似 Hessian/高阶导数排序，再只物化少数候选。

候选数 |P*(F)| = 2|F| - 1 - |F| 例：255 个 field 不是 255×254/2 那么简单；若考虑任意阶，组合空间不可枚举。

论文实际只考虑二阶和三阶组合，最终加入每个模型的组合数量 K 通常为 5–15；这与“少量高价值交叉”的工程直觉一致。

2. 完整流程

① 训练原始 Base
只用原始 field，得到 f(x;θ)
→
② 一次反传
求每个 field embedding 对输出的梯度 J
→
③ TayScorer
用 J 外积近似二/三阶组合重要度
→
④ LRE
Top window 训练 LR，逐 field shuffle 去冗余
→
⑤ 物化 Top-K

3. 关键公式：从“二阶导很贵”到“一遍反传”

3.1 Taylor 展开里，交叉项就是组合贡献

f(x) = T₀ + T₁(x) + T₂(x) + T₃(x) + … Δx = x - x₀ T₂ = ½ Δxᵀ H(x₀) Δx 其中 field i,j 的交叉项： (∂²f / ∂xᵢ∂xⱼ) · Δxᵢ · Δxⱼ

xi 不是原始 ID，而是第 i 个 field 查表后的 embedding 向量。x₀ 取该 field embedding 的均值，作为相对“无信息”的参考点。

3.2 不显式算 Hessian：用梯度外积近似

J(x) = [∂f/∂x₁, …, ∂f/∂xF]ᵀ Ĥ(x) = J(x)ᵀ J(x) 二阶 (i,j) 的直觉分数： score(i,j) ∝ | (gᵢ·Δxᵢ) × (gⱼ·Δxⱼ) | 三阶近似： Ĥ(x₀) ⊗ J(x₀) T₃ ≈ 1/3! · [Ĥ⊗J] ⊙ [Δx⊗Δx⊗Δx]

论文借用 Information Matrix Equality 的梯度外积思想解释二阶近似；把它推广到三阶是启发式扩展，不是严格证明对任意深度推荐模型都等价。所谓 O(n) 指获取基础梯度的反传复杂度不再做 O(n²) 次二阶求导，并不代表列举/排序所有组合没有组合计算与存储成本。

3.3 LRE：高分不等于有增量

ŷ = σ(β₀ + Σi∈(FW∪F) βᵢxᵢ) G(xᵢ) = Perf(Feature Window) - Perf(Feature Window \ xᵢ) 若 G(xᵢ) ≤ 0：shuffle/移除它反而不差 → 视为冗余，换入下一个候选。

实现上在 LR 验证集逐个置换候选 field。注意论文文字里会以 Logloss 表达：若 shuffle 后 Logloss 下降，该组合是冗余/有害。方向必须按你选择的 Perf 指标统一，避免符号写反。

3.4 组合 embedding 的工程处理

cross_id = hash(value_i ⊗ value_j [⊗ value_k]) mod τ 论文阈值 τ = 5,000,000

高基数组合用 hash modulo 限制表大小，代价是碰撞；论文没有消除组合值层面的冗余。

在线案例

  • 广告 CVR 模型每日更新，训练样本十亿级、特征数百。
  • 只用验证集的 10%，约 5 万样本；约 1 小时筛遍 sparse 组合。
  • 选 12 个：8 个二阶 + 4 个三阶；实验/对照各 5% 用户流量，观察两周。
  • 论文报告 CVR +13.9%、收入 +0.73%，随后全流量。

成本

加入组合后，DNN 每 batch 推理时间在 Frappe、iPinYou、Avazu 分别增加约 10%、12.5%、13.7%。因此不是“零成本特征优化”。

5. 迁移到 Kai v2：不要一上来扫所有 255³

建议围绕业务语义先定义候选域，再用 TayScorer 排序。当前显式 194×30 user-photo 交叉本身就是天然的二阶候选集合。

候选域规模/做法要回答的问题
现有 user × photo194×30 = 5,820；先算 pair score是否只需保留少量高价值配对？哪些 user/photo field 贡献集中？
context × photo限制在场景、入口、时间、设备等业务白名单是否缺少曝光环境与内容属性的显式交叉？
user × context × photo只从高分二阶向外扩一层，避免全 255³三阶是否提供条件化偏好，而非简单重复二阶？
序列统计 × target以聚合后的行为统计为 field，不直接展开所有 token长序列模块未捕获的简单共现是否值得显式记忆？
最小可回答的问题：在固定 Base 与相同训练预算下，TayFCS Top-K 组合是否显著优于随机 K、业务专家 K、按单 field 梯度乘积 K？若 Top-K 只在 LR 上有效、重训深模无增益，就不能进入生产。

多任务注意事项

gᵢ = Σt λt · ∂Lt/∂xᵢ 或分别得到 scoreCTR, scoreCTCVR, scoreGMV …

直接用总 loss 会把任务权重带入筛选结果。建议先按主目标单独打分，再报告跨任务 Pareto：主任务增益、其他任务伤害、梯度方向冲突。

6. 最小复现方案

  1. 数据：成熟 Base 的冻结 checkpoint + 代表性离线窗口；先用 5–10 万样本扫描，不以“七天”作硬要求。
  2. 候选：现有 5,820 个 user-photo pair；只做二阶，暂不做三阶。
  3. 梯度：在 field embedding 输出注册 hook；按样本计算 gi 与 Δxi=xi-field mean，跨 batch 聚合绝对组合分数。
  4. 对照：TayFCS Top-10、随机 10、业务已有高频 10、简单 |a·g| field 两两乘积 Top-10。
  5. LRE：统一输入原 field + 候选组合；LR 训练一次，每个候选重复多次 shuffle，bootstrap 置信区间，替换非正增益组合。
  6. 深模重训：固定 hash bucket、embedding dim、总 step、seed；分别测“新增 Top-10”和“用 Top-10 替换原 5,820”的质量/资源。
  7. 验收：AUC/NE/Logloss、分人群与冷启切片、embedding 内存、训练吞吐、线上 latency 预估。
实现陷阱：原论文记号把 x 当作 field 向量，但真实 embedding 是多维的。必须明确向量如何压成 field score（维度求和、L2 或内积），样本与 batch 如何取绝对值/均值；否则不同实现会得到不同排序。

7. 证据边界

它可信地支持
  • 推荐/广告里高阶组合筛选可从已训练模型梯度低成本粗排。
  • 高分组合仍需代理模型去冗余。
  • 公开三数据集、跨五种模型迁移和在线 A/B 都提供了正证据。
  • 官方代码已公开，复现性优于 MISO。
它没有证明
  • 梯度外积是任意深模 Hessian 的无偏估计。
  • 三阶启发式在所有数据稀疏度下可靠。
  • 能诊断 HSTU、Share-bottom 或塔宽度瓶颈。
  • 线上 +13.9% CVR 能外推；这个数字很大但论文没有给绝对基线、置信区间和完整线上系统细节。

证据等级：较高（针对特征组合选择） 对模块 scaling：不适用

8. Leader 最可能问什么

Q1：我们已经有 Cross / HSTU，为什么还要显式交叉？

隐式交互依赖容量和数据把共现学出来；显式 hash cross 提供强记忆捷径。论文在 DCN 和 MaskNet 上仍有增益，但 Kai v2 是否重复建模必须用“替换/新增 Top-K”对照验证，不能靠论文类比。

Q2：一遍 backward 怎么可能算完所有二阶和三阶？

一遍 backward 得到所有 field 的一阶梯度；之后用这些向量的外积组合出近似分数。省掉的是逐组合二阶求导/重训，不是省掉候选枚举、外积计算、排序和存储。255 field 的二阶可做，三阶仍要剪枝。

Q3：JᵀJ 近似 Hessian 的理论条件在深度推荐里成立吗？

严格 IME 依赖似然模型与正则条件，论文把梯度外积用于重要度排序而非精确 Hessian，三阶更是启发式。所以我们只检验排序质量：Top-K 是否比随机/业务/简单梯度基线更容易在重训中产生增益。

Q4：为什么还要 LR？深模里不冗余，LR 里可能冗余，反过来也一样。

对，LR 是便宜的增量信息代理，不是深模真值。它的作用是砍掉明显重复候选；最终必须回到目标模型重训。消融显示去掉 LRE 在 Avazu/Frappe 多数设置下降，但不是理论保证。

Q5：Shuffle 一个交叉特征会不会制造 OOD？

它保留交叉 field 的边际取值和频率，只破坏与样本/标签及其他 field 的联合关系，仍会产生联合 OOD。用小窗口代理、随机/Bottom 对照、多次置换；只将其解释为条件增量估计。

Q6：增加的内存和延迟能接受吗？

论文将大表 hash 到最多 500 万 bucket，公开实验推理时间约 +10%–13.7%。Kai v2 已有大量 sparse 参数，必须先设资源预算；更值得试“Top-K 替换 5,820 交叉”而不仅是新增。

Q7：为什么在线 CVR 涨 13.9% 这么夸张，可信吗？

这是论文自报、两周、双方各 5% 用户流量，同时 revenue 只 +0.73%。没有绝对 CVR、置信区间、流量量级与完整配置，适合证明“有线上可用案例”，不适合做内部收益预期。

Q8：冷启追平怎么串起来？

成熟 Base 提供梯度排序，筛出少量显式交叉作为冷启模型的高信息先验；实验应比较冷启收敛曲线、达到 Base 指标所需样本/step，而非只比最终 AUC。论文只证明组合迁移到其他结构，不等于证明冷启加速。
