Which Neurons Matter in IR?

Vast et al.，ICTIR 2024｜在 MonoBERT 精排 Cross-Encoder 中用 Neuron Integrated Gradients 找“相关/不相关”神经元，并用剪枝直接验证排序指标。

IR / 精排Neuron IGPruning validation

1. 为什么这篇对我们更直接

此前 Taylor pruning 多来自视觉。这篇把内部归因放进真实 IR reranking：输入是 query–passage 对，输出相关/不相关，最终用 nDCG@10 而非只看分类 loss 验证。研究三件事：能否区分相关与不相关神经元、域内/域外是否共用神经元、这些神经元被移除后是否真影响排序。

2. 核心流程

中性 baseline→100 步输入插值→每个线性输出算 NIG→token 求和→样本/数据集平均→Top 0.01/0.1/1%→置零剪枝验证

3. 关键公式

从 baseline x′ 到真实输入 x：γ(t)=x′+t(x−x′)。令 γy(t) 是中间神经元 y 在路径 t 的激活：

NIGy(x) = ∫₀¹ [ ∂F(γ(t)) / ∂γy(t) ] · [ ∂γy(t) / ∂t ] dt

第一项是“输出对该神经元的下游敏感度”，第二项是“输入沿路径移动时该神经元变化多快”。二者积分，得到该神经元承载的路径贡献（conductance）。

Transformer 同一线性维度会出现在所有 token 上。论文把该维度跨 token 的 conductance 求和，再跨多个样本取均值，形成 task-related neuron 分数：

Sy,D,c = (1/|Dc|) ∑x∈Dc ∑token NIGy,token(x)

c 分 relevant / non-relevant；D 分 MSMARCO 域内及多个 BEIR 域外数据集。

4. Baseline 是怎么选的

IR 没有天然“黑图”。作者比较 [PAD] 替换和零向量等方案，用 1000 个 MSMARCO 输入测 baseline 是否把两类 softmax 差压到接近 0，最终选择把全部 embedding 替换为 fully padded counterpart。这个步骤很关键：不是随意指定零值，而是先验证 baseline 的“中性”。

5. 实验与可信证据

模型/数据

castorini/monobert-large-msmarco。MSMARCO 为域内；FiQA、NQ、BioASQ、TREC-Covid、NFCorpus、TREC-News、Robust04 等为域外；LoTTE 和 MSMARCO dev 用于独立剪枝验证。

机制发现

同一数据集的 relevant 与 non-relevant Top 神经元集合几乎不重合，说明两类判断可能由不同内部单元承载；不同 OOD 数据集的共享情况也不同。

干预验证

随机同层剪枝几乎不影响指标；按 NIG 选出的 Top 神经元被置零后，部分方案带来显著 nDCG@10 下降。例如 MSMARCO “non-relevant” Top 1% 剪枝，在论文表中对 MSMARCO/LoTTE 都出现约 50% 量级相对下降。

证据要准确讲：不同 attribution scheme 的结果差异大；某些 relevant 交集剪枝几乎无影响。论文证明“部分 NIG 排序能找到关键神经元”，不是“任意 Top-NIG 集合必然关键”。

6. 实现伪代码

for dataset, label in attribution_splits:
  score = zeros(all_linear_output_dims)
  for x in correctly_predicted_examples(dataset, label):
    for k in range(1, 101):
      t = k / 100
      x_t = baseline + t * (x - baseline)
      y_t, dy_dt = capture_neurons_and_path_derivative(x_t)
      grad_y = grad(target_probability(model(x_t), label), y_t)
      score += sum_over_tokens(grad_y * dy_dt) / 100
  score /= number_of_examples
  top_sets[dataset, label] = top_percent(score, [0.01, 0.1, 1.0])

# 独立验证：同层、同数量随机对照重复 50 次
for neurons in top_sets:
  delta_ndcg = evaluate(zero_neurons(model, neurons)) - evaluate(model)

8. 边界与失败模式

  • 单一 MonoBERT 架构，不能直接代表推荐多任务或 HSTU。
  • NIG 约 100 次梯度，成本高，适合候选复核，不适合每天全量扫描。
  • Baseline 与线性插值可能偏离离散 token/embedding 流形。
  • 平均后得到“task neuron”会掩盖长尾用户和小场景；推荐必须分桶。
  • 置零剪枝存在 OOD；应增加 shuffle，并保持同层同数量随机对照。
  • 集合不重合不等于功能因果可解释，还需样本级与联合干预。

9. Leader 尖锐问答

Q1：这篇比 MISO/Taylor 更能证明我们方向吗？

它提供了排序精排模型、nDCG 和神经元剪枝的直接场景证据，但模型仍是 MonoBERT。它更接近业务问题，仍需在 Kai Base 做本地相关性和干预校准。

Q2：为什么用 NIG 而不是一次梯度？

跨 baseline→输入路径积分能缓解终点梯度饱和，更适合确认稳定“任务神经元”；代价是约 100 倍梯度，因此我们用普通梯度粗筛、NIG 复核。

Q3：为什么 relevant 与 non-relevant 神经元几乎不重合？

这是作者的集合观察，提示模型可能使用不同通路支持两类判断；它不是功能命名的最终证明。需要正负样本干预和跨数据复验。

Q4：为什么有些 Top 神经元剪掉不掉点？

可能有冗余、归因正负抵消、集合交集过严或 baseline 偏差。论文结果本身说明 attribution 只能筛候选，干预才是验收。

Q5：Top 1% 掉 50%，是不是能直接拿来做剪枝？

恰恰相反：Top 是关键单元，剪掉用于验证，不是压缩。若要剪枝应验证 Bottom-K，并微调恢复；本课题主要用 Top-K 定位依赖和瓶颈。

Q6：迁移到多任务后分数怎么算？

每个任务单独算一份，再算线上权重总 loss；报告任务间 Top-K overlap 和梯度方向。只算总 loss 会被权重大的任务主导。

Q7：对冷启动追平有什么抓手？

同一冻结数据上比较成熟 Base 与冷启模型的模块归因谱：成熟模型稳定高分而冷启缺失的分支，是蒸馏、初始化、损失重权或专项预训练的候选，不直接等于结论。
