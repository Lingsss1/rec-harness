# 假设生成前的开发历史分布

`history_diagnostic: true` 现同时开启两个阶段：提出假设前提供 incumbent 的开发历史分布与分桶指标，候选完成后提供原有配对历史诊断。基线阶段没有候选或确认结果，不新增训练或模型推理。

读取已审计开发排名和冻结训练数据，按训练历史总长度聚合。报告绑定协议、模型、类别/seed、数据与排名哈希、训练收据及实现身份，写入独立 `baseline_history_completed` 事件和 CAS。恢复重新核验输入并复用相同聚合；拒绝投影或输入变化。角色只收到分桶人数与 HR/NDCG，不收到用户 ID、逐用户排名、原始交互或依赖路径。

真实验收使用完成的 v2 四类基线，写入独立诊断目录 `baseline-history-context-acceptance-v1`，原研究账本不变。各类开发 seed 42、1000 用户；重复结果一致，未调用 Codex。

这里是训练历史总长度，不是截断后的输入长度，也不是本轮新预注册的分组。51–128 分桶跨越 121 位置的理论卷积范围，不能据此精确计数超过该范围的用户。绝大多数开发用户的短历史说明“最大输入长度较长”本身不足以证明普遍的长程依赖缺口；该分布并未证明模型机制或工具决策效用。确认集和最终测试未读取。
