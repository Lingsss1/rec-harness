# Autoresearch 工程完成标准

当前工作以完整实现 autoresearch 为主，最终测试口径暂缓。本文按可执行能力组织验收；实验涨点、工具晋升或论文结论成立不作为软件完成的必要条件。历史实验仍保持原门槛，不能为通过验收修改结果。

| 必须覆盖的能力 | 主要实现入口 | 工程验收依据与剩余检查 |
|---|---|---|
| 自动模型研究：证据、假设、实现、对照、评估、决策、知识更新、多轮续接 | `autonomous.py`、`adapters/amazon_autonomous.py` | 小型两轮与 Amazon 配对运行已有真实证据；整体能力索引见实现清单 |
| 缺口判断、工具开发、验证、晋升或拒绝、回到研究 | `measurement_discovery.py`、`project.py`、`tool_pipeline.py` | 自动路由及后继研究有工程覆盖；真实自主发现缺口仍未观察到，不能把人工指定缺口写成自主发现 |
| Harness 历史诊断、前缀验证、独立开发与确认、晋升和回退 | `evolution_auto.py`、`harness_pipeline.py`、`amazon_harness_online.py` | 三阶段接线与恢复已有覆盖；真实运行的零收益拒绝不要求改成晋升 |
| 图记忆、来源、反证、条件检索、跨任务继承 | `store.py`、`knowledge.py`、`memory_transfer.py` | 合成任务迁移及图/平面对照已有证据；真实推荐迁移收益仍未证明 |
| 中断恢复、失败保留、重复调用防护、成本与产物审计 | `round_recovery.py`、`online_recovery.py`、`project_report.py` | 成功结果复用及未知结果保守停止均为明确合同；当前真实 v5 还需终态审计和零新增调用恢复验收 |
| 安装后可运行、入口与源码一致 | [v33 安装验收](install-acceptance-v33.md) | 144 个模块及原生源码一致、20 个入口、645 项安装回归通过且零跳过 |

上表是审计入口，不是逐项完成声明。详细限制及原始证据索引见[实现清单](completion-matrix.md)，需求依据见[方案第九节](../auto-research-plan.md#9-实施阶段与验收)。

当前收尾顺序：

1. 完成已启动的 [Amazon 三组 v5](../experiments/amazon-tool-live-v5.md)，核对所有角色收到的模型与测量身份、独立复算和历史成本。合法拒绝也可通过执行完整性验收。
2. 对该终态执行恢复检查，证明已完成角色和训练不会重复调用；发现实现错误时修复并补相应回归。
3. 对照上述能力核对入口、配置、恢复及测试，区分缺少工程实现与缺少科学效用证据；仅为实际工程缺口新增开发任务。

不因尚未观察到正收益而自动追加完整训练 campaign。论文查询沿用 Codex 工具；最终测试暂缓不影响当前工程收尾。
