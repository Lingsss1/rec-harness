# 固定选择与端到端生成的报告边界

现有工具、Harness、图/平面记忆对照和经验迁移在线执行器允许研究角色生成新候选，其新报告明确记录 `evaluation_mode: end_to_end_candidate_generation`。使用脚本角色夹具时仍保留原有online=false；评价类型不表示调用了真实Codex，也不证明一般科学效用。

Evolution阶段规则可预先声明evaluation_mode，支持：

- fixed_candidate_selection：在预先固定候选集合中选择。
- end_to_end_candidate_generation：允许研究过程生成新候选。
- offline_measurement：离线测量验证。

声明后，报告必须提供相同类型；缺失或不匹配作为验证合同错误拒绝，不能作为数值淘汰触发项目继续。非法配置在预检及候选生成前拒绝。未声明此字段的旧计划保持原合同，不事后补造历史类型。工具历史只保留报告中明确、合法的类型名称，不共享报告分数。

该字段是评价范围约束，不能验证自定义外部验证器是否忠实执行了其自报类型。内置在线执行器的类型由其实现确定。当前没有新增固定候选选择执行器，也不能把现有端到端验证说成固定候选选择能力验收。

首批工具/Harness/历史/续接相关30项回归通过（17.667秒）；补充记忆、迁移及预检后15项通过（3.866秒），测试有重叠。新增测试覆盖匹配、不匹配、缺失、非法类型、旧计划兼容与在线生产者报告字段。证据位于rec-harness-runs/evaluation-mode-v1，无Codex调用或Amazon训练。本项晚于v27安装包。
