# 已有基线指标不能作为缺失测量转交

模型测量发现与优化器测量转交原先只检查诊断/激活输出中的同名量，未检查公开基线指标。现在，所有相关基线条件都已提供的同名指标也计入已有测量。例如各品类/seed 均有 HR@10 时，不能再以“缺少 HR@10”为理由开发工具。

普通测量评审使用其公开 baseline 行；优化器转交使用所引用轨迹中的基线行。主机只做精确名称和完整条件覆盖检查，不推断语义等价。`HR@10.category_spread` 等不同定义的派生量仍须按原测量审查合同判断；若某个条件没有该指标，也不会仅因另一行含有同名指标就声称全覆盖。

基线已有量、诊断已有量及前置条件检查都在创建缺口或提交转交前执行。此项未修改冻结预算、验证器门槛、晋升规则或历史结果，也没有新增 Codex/训练调用。

定向验证：测量发现 9 项、Amazon 转交证据 5 项及转交端到端恢复 6 项全部通过，覆盖已有 HR@10 拒绝、不同派生量不误拒绝、不完整条件不冒充完整覆盖，以及合法转交/拒绝/中断恢复路径。恢复日志 `/tmp/rec-harness-existing-metrics-handoff-tests.log`。没有据此宣称主机能判断任意两个指标的语义等价。
