# 工具生成输入中的运行接口

新建 `AutonomousEvolution` 工具任务时，如果冻结计划指定 `public-aggregate-measurement-v1`，主机将 `diagnostic_contract` 写入候选上下文：`diagnostic.py:measure(request)` 入口、公开聚合请求字段、返回值字段、CPU jail 调用方式、数据可见范围和失败处理要求。这个上下文与验收计划一起实际传给 tool 角色，并被原有配置/候选 hash 和生成输入 hash 绑定。

原接口只有计划中的合同名称，测量转交上下文没有入口和输入输出说明；脚本角色预先知道接口，不能证明真实 Agent 能据此实现。现在普通工具任务和优化器转交任务使用相同的主机接口说明。调用者提供冲突说明时在初始化冻结之前拒绝，不将它交给生成角色。

只在新任务初始化时注入，恢复旧冻结任务不重新构造上下文。其他工具合同不套用聚合接口。此补充不改变验证门槛，不新增生成调用，也不证明候选正确性或科学效用；六阶段独立验证仍负责验收。

定向测试覆盖实际角色输入、优化器转交后的冻结上下文、错误接口拒绝，以及已有生成/验证恢复路径。v16 安装包早于本变更。

执行补充：worker 将已冻结并放入 jail 的工具目录加入 Python 模块搜索路径，允许入口导入同目录的辅助模块；入口模块也先注册到 `sys.modules`，支持依赖模块注册的 Python 行为（例如带延迟类型注解的 dataclass）。原加载方式只执行单文件 spec，没有提供这两项运行条件，多文件归档测试无法覆盖此执行缺口。

真实 Python 子进程测试在临时目录中调用同一个 worker，组合 `helper.py` 导入和 dataclass，验证测量结果为独立已知的范围值 3。测试使用隔离 Python 模式，但不冒充 CPU jail 权限隔离验收。生产 CLI 仍固定读取 `/inputs`、写入 `/output`；新 worker 的文件 hash 随新工具冻结，旧任务不替换已冻结 worker。

后续[实际 CPU jail 验收](../experiments/multifile-diagnostic-jail-v1.md)已覆盖两组输入、非 root/输入只读检查、结果收集、费用和无重复执行读取；均通过。它补充执行链证据，不增加自主工具效用结论。
