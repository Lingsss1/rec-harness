# 工具生成前的历史检索输入

工具演化配置可声明tool_history_sources，读取已有或失败工具的已提交记录，例如：

```json
{
  "tool_history_sources": [
    {"campaign": "../previous-tool-campaign", "cutoff_seq": 42, "candidate_ids": ["old-tool"]}
  ]
}
```

路径相对所属配置文件解析。cutoff_seq和candidate_ids可省略：分别冻结初始化时的最新事件前缀和其中全部工具候选。重复campaign或相同事件前缀拒绝；候选不能来自截止点之后。

初始化只读校验源事件链、计划摘要和方法卡CAS，生成tool-development-history-v1并写入冻结context.tool_history，实际交给工具角色。历史包含方法卡、实现/计划身份、验证条件和输入合同、各阶段通过/拒绝状态，以及淘汰、替代、回退状态。没有方法卡的旧记录保持null，不臆造测量定义。作者收到比较已有及失败设计的明确指令；这不证明作者一定采用了历史建议。

不共享验证分数、验证样本、原始输出或自由文本错误。主机把已选历史的开发ID和已访问验证ID并入新计划development_ids，防止再次使用这些条件自证。旧验证事件没有可核对的报告及评价ID时拒绝接入，而非假设其独立。

历史在初始化时冻结，源后续追加事件不改变新任务输入。新任务恢复不重新读取历史；使用者不能直接伪造保留字段tool_history。联合项目在启动第一个模型回合前检查配置的工具历史，避免研究进行到工具阶段才发现来源不可用。显式来源入口不会扫描其他目录。新项目的本地已完成工具历史自动继承规则见下文。

联合项目现同时保存历史截止序号和event_head，再把历史开发/验证ID并入工具计划；进入后继工具回合时必须匹配这一前缀，不能读取项目启动后的新增历史。单独工具初始化在合并排除集合后也执行验证预检。

内置验证器预检会读取实际评价ID，包括reference、shadow、online及嵌套工具/Harness pipeline，提前拒绝与development_ids重叠的计划。命令中的--stage必须与计划阶段一致。自定义外部验证器仍只做文件检查，运行后的报告门槛继续负责检查其评价ID，不能宣称所有外部命令都能在生成前排除重叠。

53项相关测试通过（36.319秒）；补充验证条件和作者指令字段后，历史模块6项再次通过。覆盖作者实际收到历史、未来事件排除、未知卡片、重复源、计划/CAS篡改、旧验证身份缺失、回退状态和项目预检。公开边界及diff检查通过。

真实只读核验位于rec-harness-runs/tool-history-acceptance-v1：读取tool-method-authoring-v1的一份真实方法卡和三个离线验证状态，冻结七个排除条件；重复提取一致，源账本未变。没有新增Codex调用、训练或工具生成，不推导历史检索的科学效用。该变更晚于v24安装包。

启动前排除补充：33项项目及验证相关回归通过；补充阶段一致性和前缀摘要绑定后，23项定向测试通过（0.575秒）。这些测试有重叠，不合并计数。rec-harness-runs/tool-history-preflight-v1保存真实历史只读核验：复用两个既有参考条件的计划被预检拒绝，源账本不变，零新增调用和作业。

## 项目内自动继承

新项目默认冻结 inherit_tool_history=true。下一工具回合自动合并本项目已提交的工具episode与显式tool_history_sources，作者同时获得前驱源码和历史方法卡/验证状态。只读取project_transition绑定的已完成工具回合；报告须匹配项目事件摘要，并能对应子控制器的evolution_stopped事件。历史截止点固定在该终止事件，后续追加记录不进入输入。未经项目提交的目录不作为历史来源。

显式配置的同路径来源优先保留其既定截止点和候选筛选；不会重复加入。旧项目未冻结此开关时沿用原行为；新项目可显式设false。继承历史后继续排除其开发和已访问验证条件；固定内置套件若重复这些条件，会在生成前被预检拒绝，不能把继承历史后的重复验证算作独立效用。外部验证器仍由报告门槛检查ID独立性。

双工具迭代工程测试覆盖第二作者接收第一工具的方法卡、前驱源码和排除条件；使用按episode区分条件ID的脚本报告，不代表真实独立科学实验。另覆盖未提交目录、终止报告缺失、报告篡改及未来事件排除。项目、Amazon、转交、恢复与方法卡相关41项测试通过（59.398秒），公开边界及diff检查通过。没有新增Codex调用或训练；变更晚于v25安装包及564项全量源码回归。

真实只读检查保存在rec-harness-runs/project-tool-history-v1：从joint-tool-project-v1自动找到一个已提交工具回合，但旧拒绝事件缺少可核对的评价ID，因此collect明确拒绝接入新作者历史。项目和子控制器事件链均不变。该检查证明旧记录的拒绝边界，不算真实历史成功送达，也未重写或补造旧报告。

## 正确性失败的历史记录

新验证拒绝事件保留实际返回的公开报告及摘要、候选实现和计划身份，不再只归档数值门槛失败。这样，正确性/稳健性报告返回passed=false时，其候选方法和已使用条件仍能进入后续检索与排除集合。原始CAS报告归档路径保持不变。

拒绝历史区分validation_gate（合法报告未满足数值门槛）和validation_contract（正确性失败或报告合同检查失败）；后一类不升级为有效测量，也不触发Harness数值淘汰后的继续规则。历史只共享此固定类别，不共享自由错误文本或分数。用于排除的evaluation_ids必须为非空字符串列表；缺失、非法ID或没有返回报告时仍拒绝接入。非公开报告不写入公开拒绝事件。旧事件不回写，因此上一节真实旧历史仍保持原来的拒绝结果。

50项相关测试通过（19.337秒），覆盖实际脚本验证器返回正确性失败→事件保留→历史提取→终态恢复零重复，以及非法ID、非公开字段和Harness拒绝续接边界。证据在rec-harness-runs/rejected-tool-history-v1。无新增Codex调用或Amazon训练；本项晚于v25包及564项完整源码回归。

后续[真实CPU拒绝验收](../experiments/rejected-tool-history-cpu-v1.md)已完成：已知错误工具在两个实际隔离案例中一错一对，真实验证器返回正确性失败；历史保留条件并阻止再次使用，恢复和独立复算零新增执行。合计4 BCU，无Codex调用或Amazon训练，不增加工具科学效用结论。
