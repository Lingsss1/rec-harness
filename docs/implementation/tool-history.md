# 工具生成前的历史检索输入

工具演化配置可声明tool_history_sources，读取已有或失败工具的已提交记录，例如：

```json
{
  "tool_history_sources": [
    {"campaign": "../previous-tool-campaign", "cutoff_seq": 42, "candidate_ids": ["old-tool"]}
  ]
}
```

路径相对所属配置文件解析。cutoff_seq和candidate_ids可省略：分别冻结初始化时的最新事件前缀和其中全部工具候选。重复campaign或相同事件前缀拒绝；候选不能来自截止点之后。

初始化只读校验源事件链、计划摘要和方法卡CAS，生成tool-development-history-v1并写入冻结context.tool_history，实际交给工具角色。历史包含方法卡、实现/计划身份、验证条件和输入合同、各阶段通过/拒绝状态，以及淘汰、替代、回退状态。没有方法卡的旧记录保持null，不臆造测量定义。作者收到比较已有及失败设计的明确指令；这不证明作者一定采用了历史建议。

不共享验证分数、验证样本、原始输出或自由文本错误。主机把已选历史的开发ID和已访问验证ID并入新计划development_ids，防止再次使用这些条件自证。旧验证事件没有可核对的报告及评价ID时拒绝接入，而非假设其独立。

历史在初始化时冻结，源后续追加事件不改变新任务输入。新任务恢复不重新读取历史；使用者不能直接伪造保留字段tool_history。联合项目在启动第一个模型回合前检查配置的工具历史，避免研究进行到工具阶段才发现来源不可用。该入口不会自动扫描其他目录或选择未配置的源。
