# 工具测量范围准入

工具验证计划的 `measurement_scope.supported_outputs` 可显式声明测量名称及定义。仅在实现后才发现候选不符合固定参考输出，会浪费工具生成调用；这也不能说明该科学缺口不存在。

新项目默认冻结 `enforce_tool_measurement_scope: true`。自主测量审查或优化器提出缺口后，若满足工具路由条件但所需测量名称不在声明范围，调度器保留 `pending_gap`（以及已有优化器转交来源），以 `measurement_contract_unsupported` 停止，记录所需名称、已声明名称和范围 hash。不会创建工具子目录、调用工具角色或将候选记为科学失败。

匹配声明时继续原来的工具开发和独立验证；范围检查只比较精确名称，不证明定义、输入条件、因果解释或效用相符。未声明范围的计划保持原有验证路径，不能据此推断其支持任意测量。

旧冻结项目没有 enforcement 字段时保持旧行为。修改合同、增加输出或追加验证器，应创建新的项目/验证计划；不能在已停止项目里重写配置恢复。显式关闭 enforcement 时不执行本项名称门槛，但不跳过后续验证。

回归使用脚本角色和独立事件/目录，覆盖：自主发现的不兼容缺口只调用一次审查且恢复不重发；匹配测量继续模型→工具→模型；优化器来源保留且不调用工具；非法声明在创建项目之前拒绝；旧字段缺省行为保持。它不是新的真实 Codex 工具闭环验收。

验证：项目范围准入、联合调度和优化器转交共 23 项测试通过（39.735 秒）；公开目录边界、语法和 diff 检查通过。没有新增 Codex 调用、真实训练或工具晋升。本变更尚未纳入 v20 wheel。
