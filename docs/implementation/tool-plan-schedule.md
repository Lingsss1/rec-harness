# 连续工具迭代的独立验证计划

项目可在首次运行前设置 `tool_followup_plans`。第一轮使用原有 `tool.plan`，列表中的完整计划依次用于第二轮、第三轮等工具更新；长度必须等于 `max_tool_updates - 1`。每个元素与 `tool.plan` 结构相同，包含预算、身份、开发条件排除集合、六阶段命令及门槛。不能在看到前一轮结果后追加或修改计划。

例如，在配置文件所在目录准备完整的第二轮计划后：

```python
import json
from pathlib import Path
config = json.loads(Path('project.json').read_text())
config['max_tool_updates'] = 2
config['tool_followup_plans'] = [json.loads(Path('tool-validation-round-2.json').read_text())]
Path('project-with-followup.json').write_text(json.dumps(config, indent=2))
```

后续计划的脚本入口、内置套件路径和显式依赖相对项目配置文件解析。内嵌计划的原来源文件位置不会另外参与路径解析。

创建项目时检查全部计划的方法卡合同、字段、阶段、预算及测量范围，预检全部套件并冻结每轮验证器文件摘要。后一轮会排除之前计划的开发条件和内置验证套件条件；如果重复使用这些条件，在首轮模型调用前拒绝项目。外部自定义验证器无法静态提取全部条件，仍通过实际历史报告排除和运行后的报告门槛检查独立性。不存在的Python脚本入口现在按阶段拒绝，不会被其他阶段有效文件掩盖。

进入工具回合前再次核对所选验证器摘要；该轮生成、验证和晋升使用同一个计划。测量审查及优化器转交使用下一轮预算。工具晋升后的模型复测采用该工具所属计划的验证身份，不能误用第一轮条件。工具缺口范围也按下一轮计划判断。历史继承、源码继承和旧条件排除继续生效。

未提供列表时保留原来的单计划配置；历史条件排除规则仍生效，重复固定套件可能被拒绝。旧冻结项目不自动生成计划列表。该功能不会自动设计科学验证条件或修改门槛。

新增六项工程测试覆盖两次工具晋升和模型续接、不同验证身份与预算、终态零重复恢复、配置不变性、提前拒绝无效计划、验证器变更、路径解析、内置条件重叠和优化器预算。双工具流程使用脚本角色与固定报告，只证明配置与调度，不代表真实工具效用。相关61项回归通过（32.575秒）；预算联动补充后11项通过（14.795秒），新增优化器预算单测另行通过，测试有重叠不相加。
