# 工具正常淘汰后的有界续接

新项目配置tool_followup_plans时，默认启用continue_after_tool_rejection。首个工具候选若因合法验证报告未满足收益、回归或成本门槛而被淘汰，项目消耗该轮计划，保留未解决的MeasurementGap和此前稳定工具，使用预先冻结的下一轮计划创建新候选。

下一作者收到已提交的失败历史及门槛原因；已有开发与验证条件继续排除。失败实现不会作为已晋升工具注册，也不会覆盖稳定工具源码。新候选通过全部门槛后才返回模型研究并复测缺口。每一轮的原费用留在子控制器账本，失败不会返还费用。

该流程不是服务调用重试。传输失败、非法报告、条件重叠和正确性检查返回passed=false仍停止。只有rejection_kind=validation_gate进入此分支。用完max_tool_updates指定的计划后，以tool_rejected停止并保留缺口，不强迫晋升，不自动追加计划，不降低门槛。启用此流程时tool_updates统计已消耗的工具候选计划，包含正常淘汰的候选。

可显式设置continue_after_tool_rejection=false关闭。没有预先声明tool_followup_plans时，不能显式启用；普通单计划项目默认不变。旧冻结项目缺少开关时沿用原行为。

工程测试使用脚本作者和固定验证报告，覆盖首轮淘汰→失败历史送达→第二轮晋升→模型复测，全部淘汰后的次数上限、缺口保留、异常报告停止、显式关闭、缺少计划的提前拒绝，以及项目转换事件提交后中断恢复。恢复不会重新生成已拒绝候选。该证据不代表真实工具效用或真实自主修复。

18项初始相关回归通过；补充转换中断场景后，项目、Amazon、测量范围及工具续接24项通过（36.315秒）。日志与摘要位于rec-harness-runs/tool-rejection-continuation-v1；公开边界和diff检查通过。没有真实Codex调用或Amazon训练，变更晚于v27安装包。
