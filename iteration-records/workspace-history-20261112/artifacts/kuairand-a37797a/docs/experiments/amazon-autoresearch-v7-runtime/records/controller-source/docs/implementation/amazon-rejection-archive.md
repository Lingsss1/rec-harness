# Amazon 失败角色即时归档

此前 Amazon 的 `role_rejected` 只保存角色、原因和可重试标志。失败请求及返回草稿留在工作目录，直到周期整体验收或显式重开时才绑定到 CAS。这使停止且未重开的失败任务缺少当时的不可变原始档案。

现在拒绝事件直接携带 `archive`，绑定已有 context、request、response、schema、resources、process、launch、stdout、stderr、论文搜索收据、rejection 和返回工作区 manifest/文件。缺失文件不伪造。归档在下一次重试前发生，不需要新增调用或启动训练。

`verify_campaign` 逐项核验这些 CAS 对象，并验证提交事件中的角色和输入 hash，以及拒绝文件中的原因、可重试标志与事件一致。修改工作目录不会改写过去的事件或 CAS；篡改 CAS 文件会导致核验失败。旧拒绝事件没有 `archive` 时保留旧格式，不事后补造归档。

工程测试覆盖成功传输但语义被拒后的两次重试，以及 crash、timeout、缺失传输收据的停止路径；后三者重复恢复不重发、失败费用不退款。测试验证返回草稿已进入 CAS、修改工作副本不影响归档、CAS 篡改被拒绝。相关 Amazon 控制器测试 22 项通过。测试使用模拟角色，不代表新的真实 Codex/GPU 验收。

完整核心检查通过：公开边界、语法检查及 444 项测试（423 项通过、21 项环境条件跳过）。本次无新增真实角色调用或训练，源码变更尚未纳入 v17 安装包。
