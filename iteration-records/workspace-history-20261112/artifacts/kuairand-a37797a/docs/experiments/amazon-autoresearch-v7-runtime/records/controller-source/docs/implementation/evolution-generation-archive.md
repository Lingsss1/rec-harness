# 工具与 Harness 生成原始档案

正常生成工具/Harness 候选时，先前只有候选源码或策略进入 CAS；请求、CLI 日志和论文检索收据仍留在开发目录。中断恢复已有部分收据归档，但正常路径缺少同等保护。这不满足方案 §4.2 的原始实验档案要求。

现在每次生成通过 `candidate_generation_archived` 事件绑定已有的 context、request、schema、response、resources、stdout、stderr、论文搜索收据、prompt、launch 和 process 文件。正常路径在提交候选实现前归档；失败路径也归档当时可用的文件。缺失文件保持缺失，不补造成功请求或搜索。候选的开发结束事件继续独立记录执行状态，归档本身不代表生成成功或验证通过。

恢复复用已提交归档，并拒绝不同的工作文件覆盖原收据。`Evolution.verify` 校验这些 CAS 对象；终态恢复不会生成第二次调用或归档事件。历史已完成候选不回填新事件。

新建工具演化任务还会冻结完整搜索策略：未明确设置工具搜索时，工具角色使用 `live`，通过 Codex 自带工具检索论文。显式 `disabled`、`cached` 或 `live` 均保留。普通底层传输及旧冻结任务的默认行为不变；Harness 优化器也不会因此获得搜索权限。启用搜索不会新增独立角色调用，Codex 内部工具请求数可能增加，仍不把角色提交数当作 API 请求数。

工具响应没有 MethodCard，因此工具提示要求将精确 URL、论文版本/章节放入 `diagnostic.py` 的模块说明，并在 `limitations` 报告来源局限，不再要求填写不存在的 `method.sources`。源码与原始检索日志分别归档；工具来源说明仍是 Agent 报告，不是正文/公式核验。

测试覆盖正常生成、失败传输、归档早于实现事件、CAS 篡改拒绝、终态零调用恢复、原有中断恢复，以及新任务搜索设置冻结和显式禁用。使用脚本角色与合成收据，不构成真实论文路线或在线效用验收。

验证结果：演化与搜索 26 项通过，项目与优化器转交 18 项通过；最终 `bash scripts/validate-core.sh` 的公开边界、语法及 442 项测试检查通过（421 项通过、21 项环境条件跳过）。本次未增加真实 Codex 调用、训练或工具晋升；变更尚未打入 v17 安装包。
