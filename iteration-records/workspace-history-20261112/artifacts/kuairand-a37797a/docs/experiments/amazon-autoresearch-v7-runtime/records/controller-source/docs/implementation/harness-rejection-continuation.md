# Harness 候选淘汰后继续模型研究

新项目默认冻结 `continue_after_harness_rejection: true`。当独立验证正常完成、报告身份和条件合法，但收益、回归或成本未达到原门槛时，候选仍永久淘汰。项目消耗一次 Harness 尝试额度，在剩余模型回合内从上一 incumbent 和开发记忆继续；没有已晋升策略时保留原策略，有已晋升策略时继续使用该版本。不会启用被拒补丁，也不重试其验证。

过去这类正常淘汰会直接结束整个项目。现在 `max_harness_updates` 也约束被拒尝试，避免反复提出候选绕过次数上限。回合之间的事件提交、源码与记忆核验沿用已有恢复合同。

执行失败、生成失败、非法报告、开发数据重用、缺失比较组，以及未解决的测量前提仍停止。只有通过报告合同检查后的数值门槛失败，才记录 `rejection_kind: validation_gate`；原始报告、报告 hash、计划与实现身份写入拒绝事件，终态报告给出拒绝阶段。门槛失败不等于模型假设被推翻。

可配置 `continue_after_harness_rejection: false`，保留遇拒即停的策略；该字段必须为布尔值。已冻结且没有此字段的旧项目仍保持原行为，不回写历史，不重新打开已停止项目。工具淘汰仍以 `tool_rejected` 停止，因为其待解决测量缺口不能被忽略。

工程测试覆盖原策略续接、第二个候选被拒时保留此前晋升策略、项目转换中断恢复、终态零新增调用、显式停止与旧配置兼容，以及不合法报告不能冒充数值淘汰。测试使用脚本角色和固定报告，只证明控制流，不提供在线收益证据。
