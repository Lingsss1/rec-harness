# 方法卡来源准入

此前 MethodCard 只校验 origin 枚举，`paper_claim` 携带空 sources 或无法定位的来源字符串也能进入提案和图知识。方案 §3.4 要求区分论文声明、Agent 假设与本地证据，因此新任务需要在实现候选前阻止无来源的论文声明。

新建通用模型和 Amazon 自动研究默认冻结 `require_method_sources: true`，并在实际角色输入提供 `locatable-method-sources-v1` 合同。每条论文来源必须是非空引用字符串，含具体 HTTP(S) 文档 URL、DOI 或 arXiv 标识；可附版本、章节和解释。只给标题、unknown、空列表或网站首页不能通过。Agent 假设可保留空来源，不要求编造引用。

通用控制器在写入 Method/Proposal 和调用 experiment 之前检查。Amazon 在 hypothesis 的主机校验中检查，继续使用既有有限角色修复策略；不能绕过合同直接注册候选。该检查不发起网络请求，也不新增独立审稿角色。论文查询仍由 Codex 自带工具承担。

合同检查的是引用语法和可定位标识，不证明链接存在、来源为一手论文、版本准确、正文支持声明或方法适用于当前模型。测试故意使用虚构 DOI/URL 来确认这些界限。论文内容级核验仍未完成，不能把准入通过写成已证实的机制或实验事实。

缺少此字段的旧冻结任务仍按原合同恢复，不回写旧方法卡或修改历史输入。新配置显式关闭时也会被冻结，不能在运行中修改开关。源码级 `validate_card` 的历史调用默认保持兼容；新任务准入显式传入此要求。

24 项相关测试通过，包括无来源论文声明不进入 experiment、不写入 Method 节点、来源格式检查、旧合同兼容及 Amazon 流程恢复。Amazon 合成夹具原先取 schema 第一个枚举而被误标为 paper_claim，现明确标为 agent_hypothesis；没有为通过检查添加虚假引用。

完整核心检查通过：公开边界与语法检查，以及 447 项测试（426 项通过、21 项环境条件跳过）。本次没有新增真实 Codex 调用或训练；该源码变更尚未纳入 v18 安装包。
