# 未准入生成草稿的保留

方案要求失败和中断尝试保留原始研究产物。此前隔离 Codex 只有在响应成功解析并通过 schema 后，才将声明的模型文件复制回主机工作目录。超时、进程失败或非法响应下，草稿虽仍在原隔离目录，却未进入正常归档链。

现在隔离进程执行器返回后、响应校验前，主机复制 `/workspace/model/` 下的普通文件及原始 `response.json` 到角色目录的 `returned-workspace/`。响应按原始字节保留，不要求是合法 JSON，源码也不要求可执行。manifest 记录文件 hash、大小及未跟随的链接/非普通文件。

该目录独立于已准入的 `model/`。训练、源码准入、工具晋升仍使用原有检查和声明的输出；返回草稿不会自动进入这些流程。主机不会为了收集草稿重新调用 Codex。如果进程执行器尚未返回，不提前读取仍可能写入的工作区。

通用控制器的递归角色归档保留该目录；工具/Harness 的生成归档及 Amazon 完成角色归档显式核对 manifest 并绑定这些文件到 CAS。旧角色没有该目录时保持原归档格式。Amazon 失败事件当下的 CAS 绑定也已补齐，见[失败角色归档](amazon-rejection-archive.md)，不再等待显式重开周期才保留不可变收据。

测试使用模拟隔离进程失败，证明失败后保留草稿及非法响应、但不进入已准入模型目录；另覆盖不跟随文件/目录软链接、重复捕获拒绝、文件变更拒绝，以及工具/Harness 生成事件中的草稿 CAS 引用。这些是工程检查，不代表本次执行了真实 Codex 或新的 OS 隔离验收。
