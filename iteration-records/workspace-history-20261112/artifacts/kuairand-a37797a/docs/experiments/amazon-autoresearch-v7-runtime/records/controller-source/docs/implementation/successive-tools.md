# 连续工具更新

新项目冻结 `inherit_tool_source: true`。第二次及后续工具更新从项目当前激活的工具继承源码：先校验前驱 Evolution 及独立验证结果，再把其实际实现归档恢复到专用输入目录。初始工具模板不再覆盖已经晋升的代码。旧项目没有该冻结字段时保持原有输入生成方式。

子演化初始化再次核对继承源码的快照 hash 与前驱实现 hash，一致后才冻结候选配置。Codex 上下文包含前驱候选 ID、实现 hash、计划 hash；图中通过 BASED_ON 关联一个明确标为 `inherited_source` 的 ToolVersion。它表示跨 campaign 的已验证输入来源，不冒充本 campaign 的晋升，也不把不同 campaign 的本地版本链合并。

后继模型仍激活新工具的完整实现，并保留所有此前工具晋升形成的测量要求。新工具遗漏旧要求时会被后继复测阻塞，不因“已晋升”而跳过检查。

多文件工具按增量修改生成完整发布快照：`changed_files` 指定新增或修改的文件，未修改的继承文件保留原 CAS 身份。主机核对其实际内容，未声明的修改或删除会拒绝候选；当前不提供删除文件的补丁语义。验证器和发布目录均接收完整快照，避免只更新 diagnostic.py 后丢失 helper.py。工具角色提示明确该交付合同。既有已提交实现仍按原事件恢复，不追写历史快照。

五阶段集成测试执行模型→工具 1→模型→工具 2→模型，验证第二次角色实际收到第一次源码，两个测量要求都由新工具复测、前驱图关系正确、五个子阶段验证通过且终态恢复无重复生成。另检查伪称继承但源码不匹配时拒绝冻结配置。这是脚本角色/CPU 测量替身的工程验收，不是新增真实 Codex 或工具效用实验。本项晚于 v14 安装交付。
