# 可冻结的合成验证任务

旧 isolated-toy-v1 只生成同一个无噪声双变量交互函数；修改 `data_version` 名称不会改变真实任务。现在可在 `protocol.synthetic_task` 显式选择宿主任务：

```json
{
  "family": "periodic-v1",
  "training_rows": 180,
  "validation_rows": 120,
  "noise_std": 0.1
}
```

支持 `bilinear-v1`（原双线性交互）、`piecewise-v1`（符号条件交互和二次项）、`periodic-v1`（周期交互）。输入仍为两个实数，模型 API 不变；训练行数和验证行数各限16至10000，噪声标准差为0至1的有限数。噪声来自独立确定性随机流，不因改变噪声水平而改变特征。不同任务的难度与用途应由预注册实验决定，不能预设它们必然带来工具收益。

任务合同参与协议 hash，宿主 scorer 源码仍冻结。配置省略该字段时继续使用原180条训练、120条验证和无噪声双线性数据，样本逐项不变。显式 null、未知任务和越界参数被拒绝；不能把该合同用于未隔离的自定义评估路径。

每个候选仅收到训练标签和验证特征；宿主持有验证标签、校验两次新进程预测一致并计算分数。完整合同在角色协议中可见，合成任务本身不是保密 benchmark。当前 `quality=1/(1+MSE)` 保持不变，未降低晋升门槛。

在线套件把每个 case 的合同冻结，并对该 case 的基线和候选使用同一合同。跨 case 的数据/seed 条件排除仍按原规则执行；同 seed 换任务名称不能绕过独立条件检查。任务合同属于协议，不改变固定工具身份，因此记忆迁移可以比较不同源/目标任务合同，并明确其仍是合成回归范围。

25项定向测试通过，覆盖原样本兼容、可复现的新任务、非法合同、验证标签隔离、宿主评分，以及两个任务合同经配对控制器传至各次评估。`rec-harness-runs/synthetic-tasks-cpu-v1/acceptance.json` 另记录4次真实CPU jail训练：两个新任务各在两个新进程复现，原线性基线 quality 分别为0.9150361961、0.7758262050。宿主重新计算结果一致；无 Codex 或 Amazon 训练。该验收证明数据与执行接口，不证明新任务上的工具/Harness收益。新增接口晚于v21安装包。
