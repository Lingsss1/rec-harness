# 晋升后真实 CPU 复测与审查送达

证据目录 `rec-harness-runs/project-successor-cpu-v1`。本次角色、工具作者及晋升验证器是明确的工程夹具；诊断实际在非 root CPU jail 执行，模型使用本地 toy 评估。没有 Codex 服务调用或 Amazon 训练，不是自主发现缺口或工具科学效用验收。

路径为模型测量缺口→夹具工具晋升→项目提交后中断→恢复→后继模型真实 CPU 复测→正常模型研究。恢复没有重新调用工具作者。工具计算实际基线各 seed 质量的最大值减最小值；宿主按已归档 request 重新计算，核对诊断输出及 `measurement_output_observed` 的值完全一致。覆盖记录保留原缺口 ID 和工具实现身份。

初次运行已完成项目，但末尾 `audit_exposure` 在读取 measurement 角色时报 `KeyError: identity`：该角色按设计只收到精简诊断摘要，旧审计只支持完整记录。修复后仅运行 `audit.py`，没有重启原运行。审计从该角色实际基线和绑定工具重建诊断身份，再核对摘要每个字段与此前已提交的诊断完全一致；完整记录角色保留原检查。查询使用只读数据库事务。

最终 `acceptance.json` 记录一次真实 CPU 诊断、evidence 和 measurement 两条成功送达、完整项目/子回合事件检查。禁止创建子回合时终态恢复精确一致，新增执行为 0。验收绑定 CPU 收据、脚本与审计模块 hash；不将夹具的固定 `passed` 报告当作真实独立效用。

定向16项测试通过。新增断言覆盖精简摘要送达、重复审计无事件变化，以及重新计算输入 hash 后伪造输出或更换基线仍被拒绝。该修复晚于 v21 安装包。
