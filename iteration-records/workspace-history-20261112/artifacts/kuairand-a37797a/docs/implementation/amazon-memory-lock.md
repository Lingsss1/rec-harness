# Amazon 记忆导出核验控制器冻结配置

导出器原先核对 study 配置 hash，却没有核对自身 `amazon-auto.json` 与 `auto-lock.json`。因此修改任务名、绑定路径或来源合同开关后，可能产生不同身份或不同格式的记忆包，而没有先报配置已变更。

现在导出开始即要求控制器锁存在，且 config_hash 匹配；检查发生在打开 study、读取研究文件和写出记忆包之前。不补造缺失锁、不调用恢复，也不修改源配置。旧的合法冻结任务继续使用原格式导出；没有冻结锁的手工目录需先提供可审计的控制器来源，不能自动视为真实已冻结任务。

35 项相关测试通过，覆盖任务名、来源开关和 study 路径改写，以及锁文件缺失；这些错误在读取不存在的 study 之前被拒绝，输出文件不生成。测试夹具补齐真实控制器原本就生成的锁，旧合同测试使用独立目录，避免在同一冻结任务上改写配置。

真实只读检查使用已完成的 Amazon v3：两次导出的内容均与原 `development-memory.json` 完全一致，共 1 个周期，包 hash 为 `0a54019f936521c091d50b08d69825c0f8eac04a22bb00a43fd4c69b2e3376b2`。控制器配置、锁、study 配置、事件投影、原记忆文件及事件链均未变化。证据在 `amazon-memory-lock-readonly-v1/acceptance.json`。

本次没有新增 Codex 调用、训练或最终测试，也没有改变模型选择或研究效果结论。

完整核心检查通过：公开边界、语法及 452 项测试（431 项通过、21 项环境条件跳过）。源码变更尚未纳入 v18 安装包。
