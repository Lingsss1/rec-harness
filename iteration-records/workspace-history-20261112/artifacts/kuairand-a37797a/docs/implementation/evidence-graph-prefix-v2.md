# 证据图读回修复：prefix-evidence-v2

本次目标是让已经产生的开发证据进入后续研究上下文，并保留来源、可见范围、反证和缺失信息。没有修改实验评分、晋升规则或原始归档；没有增加研究角色或模型调用。

## 旧路径的断点

1. 本地图范围由语义检索后的 history 决定，最近实验可能被第一层检索排除。
2. 跨 campaign 的 development_memory 有读出和解释，但不等于当前 study 的原生图；旧路径无法匹配时只留下当前基线。
3. MeasurementGap 可以写入，假设前的节点类型白名单却不包含它。
4. Store.snapshot 的字段是 version，投影读取 graph_version，导致版本号为空。
5. 轮目录按字符串排序会把 round-10 放到 round-2 前面，不能用该顺序解释最近实验。

## 修复后的数据流

控制器在语义裁剪前保留完整的可见 history、research_memory、执行失败，构建只读证据视图。语义短名单仍作为相关性信号，但不再限定图检索候选范围。历史按 campaign 输入顺序、campaign 内数字轮次排列；没有轮次身份的显式读出不冒充最近实验。

本 campaign 目录仅读取编号小于当前轮次的读出和故障。恢复旧轮次时，即便后续轮次目录已经存在，也不把它们带入新上下文；已冻结的原上下文保持不变。

原生图仍要求同协议、所选可见历史中的任务、公开开发证据。确认和最终测试不进入研究上下文。v2 原生解释节点沿用知识写入校验器 public_only 的约定：未填写 visibility 视为 public，显式 private 仍然排除；原生实验事实仍要求显式 public。真实模型读回暴露了这个字段可选性不一致的问题，不能仅靠带齐字段的测试样本覆盖。原生 MeasurementGap 与已有解释一样执行引用闭包过滤；无法提供其原生证据时不会伪造依赖节点。

跨运行记录采用只读投影，不写入原生 Store：

| 来源 | 表达 | 资格 |
|---|---|---|
| 原生实验和解释 | 保留原有节点和合法关系 | 原有协议与可见性检查 |
| 导出开发读出 | imported_development / Experiment | 哈希校验的导出聚合，未重新审计原执行收据 |
| 导出设计记录 | imported_memory / Observation | 原记忆哈希、轮次、设计哈希和有截断标记的原文摘录 |
| 导出解释和测量缺口 | imported_memory / Claim 或 MeasurementGap 等 | reported_interpretation；原始引用保留为 reported_evidence_refs，不能充当可见证据节点 |
| 执行失败 | execution_record / Observation | 流程故障，不是科学机制反证 |

导出解释通过 DERIVED_FROM 指向其记忆记录，再指向导出读出。这只是文档来源链；不补造 SUPPORTS/CONTRADICTS 边、不把未验证解释变成事实。相应的原生实验已经存在时优先使用原生图，避免将同一导出解释再算一份证据。完整原始设计保留在源记忆；视图仅提供明确标注的摘录。

## 预算和选取顺序

默认总节点上限 64（包含当前基线）。按顺序尝试加入：

1. 最近两份可用开发读出；最近一次执行故障。
2. 最近两份读出各关联的一项测量缺口和解释（如存在）。
3. 最多两组修订关系及其目标和证据，优先近期任务。
4. 反证/淘汰信息配额，再加入第一层语义短名单。
5. 沿用关键词、角色和两跳关联的候选顺序填充剩余位置。

每次按完整引用依赖集合加入；放不下就记录 omitted_requests，不超限、不保留悬空的解释引用。最近实验优先保留不等于所有历史永远可见。导出记忆中的缺失原始引用保持明确的未验证状态。图包含选择原因、遗漏、来源、coverage、图版本、事件头和内容哈希。

研究员仍是读取预先构建的上下文，而非自主多轮查询数据库。coverage.instructions 要求区分观察与导出解释、检查反证和测量缺口、说明相关历史排除理由；结构校验只能确认引用合法，不能证明模型理解或实际使用了证据。本次没有为增加引用数量强制模型引用不相关结论。

实验后的 analyst（六角色模式下的 knowledge）也收到同一份冻结的 prior_research_evidence，便于对照历史解释与本轮结果。该视图不会扩张知识补丁的可写引用集合：补丁仍只能引用当前 graph / patch_contract 允许的证据，不能把导出记忆 ID 当成本地实验事实。交付前重新校验视图哈希。

## 兼容策略

- 新建普通研究任务默认 evidence_graph_policy=prefix-evidence-v2，示例配置显式标注。
- 旧冻结配置缺少该字段时继续走 native-selected-v1；旧上下文不重写。
- review-only 新任务默认旧策略。图版本号字段错误得到修复。
- 图知识的写入、独立代码审稿、性能晋升与科学解释分离规则不变。

## 验证与限制

使用 v5/v6 共 20 轮的公开摘要和 v7 归档内的对应开发记忆，按编号逐轮释放此前记录；比较同一空目标 study 上旧路径和新路径的跨运行读回能力。包含 14 份有哈希的开发读出；有读出不等于完整周期成功。

完整原生图、当时逐轮 embedding 排名和恢复时间不可得，因此这是受控的轮次前缀模拟，不是对真实历史决策的精确重放。源记录、实现哈希、逐轮选中节点和遗漏均记录在输出 JSON 中。没有运行 LLM、训练或独立确认，不能推导 HR@10、因果归因准确率或研究效率提升。

详细结果和复现命令见 [20 轮模拟报告](../experiments/evidence-graph-prefix-v2.md)。另以 16 节点预算检验饱和情况下的最近证据保留和遗漏报告。测试覆盖原生测量缺口、修订、跨运行来源、哈希破坏、私有和未来证据、闭包、预算、实际 Store 版本与旧策略分派，以及模拟的确定性。

后续真实角色调用、CPU 数值合同与故障恢复验证见 [运行场景验证](../experiments/evidence-graph-live-v2.md)。
