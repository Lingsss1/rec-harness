# 论文检索进入决策轨迹

方案 §5.5B 要求外部优化器能够检查当时发生的工具调用。此前 Codex CLI 的搜索收据保存在角色原始档案中，但未进入 `collect_traces` 输出；优化器仅看到方法卡中的来源字符串，无法判断是否观察到搜索事件。

新调用生成 `codex-literature-search-v2` 收据，保留 CLI 搜索事件、日志 hash、角色响应 hash 和 Agent 报告的来源。轨迹中的 `literature_search` 核验收据、日志和响应的 CAS 对象，再重新提取搜索事件并逐字段比较。替换为另一份合法 CAS 日志或响应也不能通过绑定检查。失败角色尚未接受的响应不会被当作已接受来源。

检索发生在角色调用期间，放在轨迹的调用证据中，不注入调用前的 `visible_state`。优化器只能读取截止点内已提交的角色档案；原始角色前缀回放仍读取当时输入。新字段不增加 Codex 调用，也不启动独立搜索服务。

`search_observed` 只表示出现了相应 CLI 事件，可能包含开始、完成或失败事件，不能解释为成功搜索次数。`reported_sources` 仍标为 `agent_reported_unverified`。该实现不验证论文正文、公式、版本或方法适用性，也不会因搜索事件存在将 Agent 假设改成本地实验证据。

旧 v1 收据不新增轨迹字段，以保持已冻结前缀 hash。未归档搜索记录不推断为未发生搜索。四个真实历史控制器（Amazon v3 和工具在线比较三组）的 25 条轨迹与已安装 v17 逐项一致，源事件链在只读提取前后不变。收据为运行归档 `literature-trace-readonly-v1/acceptance.json`；没有新增调用或训练。

搜索收据、篡改拒绝、未接受响应、旧格式和实际控制器轨迹投影，以及候选前缀测试共 12 项通过。新收据传输由模拟 CLI 进程验证，尚未启动新的真实 Codex 任务验收 v2 格式。

`bash scripts/validate-core.sh` 通过公开边界与语法检查；440 项测试中 419 项通过、21 项因解释器或 OS 条件跳过。该源码变更尚未包含在 v17 安装包中。
