# 方法与来源的图关联

方案 §4.4–4.5 定义 Source 节点及 `Method —DERIVED_FROM→ Source`。此前来源只留在 MethodCard.sources 字符串中，没有来源节点；Amazon 开发图还统一把方法标为 agent_hypothesis，覆盖了方法卡声明的 origin。

启用新来源合同的通用模型任务，现在在提案准入后、候选实现前建立来源节点和关联边。Amazon 自动研究向开发图投影传递同一冻结配置，在新开发图中保留方法卡 origin，并建立来源关联。旧任务和已有开发事实不回写或补造节点。

当前仅对 `paper_claim` 建立引用来源节点；本地实验 ID 不被错误转成论文来源。Source 保存完整原始引用字符串与 hash，标记 `agent_reported_unverified`，独立核验的 source_version 为 unknown，retrieved_content_ref 为 null。即使原始字符串报告了版本号，也不自动认为版本已核验。

同一任务、协议和完全相同引用共用一个 Source ID；不同格式的引用不做未经验证的论文身份合并。边标记为 paper_claim/provisional。来源不产生 SUPPORTS，不算独立实验，不能提高 Claim 的证据等级。图关联表示方法报告的设计来源，不是论文正文已证实方法适用性。

工程测试通过实际通用模型闭环与 Amazon 开发图函数验证来源节点、原始引用、来源状态、方法 origin 和关联边；重复引用不会重复建节点，恢复不追加图版本或角色调用。使用虚构引用与合成结果，不构成论文真实性或模型效用验收。相关测试 26 项通过。

完整核心检查通过：公开边界和语法检查，以及 449 项测试（428 项通过、21 项环境条件跳过）。本次没有新增真实 Codex 调用或训练，源码变更尚未包含在 v18 安装包中。
