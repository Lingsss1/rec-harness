# 前缀审计调用恢复

每个历史案例与比较组使用固定的attempt-1，调用前提交 `prefix_replay_submitted`，绑定角色、当时上下文、源码、策略和验证合同。未知调用不再通过增加attempt编号自动重发。

主机完成响应检查和产物归档后，先记录 `prefix_replay_result_recorded`，再记录案例完成事件。两者之间中断时，恢复核对原请求摘要和CAS产物，复用同一个结果，包括未通过的结果，不追加角色费用。可修改的响应文件副本不参与恢复判定。

Evolution支持直接harness_prefix及Harness pipeline的prefix_audit恢复。外层先只读检查所有未完成调用均有已提交结果；无法证明结果、旧未绑定目录或损坏档案均停止，不启动新验证器或新增费用。可以恢复的验证器调用使用独立费用快照，沿用前一轮实现的费用累计规则。memory-prefix-replay使用相同的调用身份及结果恢复规则。

响应尚未进入结果事件的进程，即使目录中有部分输出，也不推断为调用成功。当前实现不自动恢复这一窗口，需要明确核对；这避免未经验证的响应被接受或同一请求被重发。

新增工程测试覆盖归档与完成事件之间中断、响应副本变更、未知调用重复恢复不重发，以及外层恢复的费用与执行边界。测试使用脚本角色，不提供新的Codex故障恢复或科学效用证据。变更晚于534项完整回归与v23安装包，本轮采用相关模块定向回归。
