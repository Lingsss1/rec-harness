# 工具验证案例的收据恢复

reference和shadow验证器现在在CPU调用前记录 `validation_case_submitted`，绑定案例、输入文件、执行设置、超时和固定案例费用。每个逻辑案例保留一个执行目录，不再通过递增job编号自动重跑中断作业。

同一验证器目录恢复时：

- 已提交结果保持原有缓存行为，包括失败结果。
- 结果未提交，但进程已成功结束且输入绑定、清理状态与产物收据有效时，复用原收据，并继续主机参考值/范围判定。
- 状态不明、输入改变，或存在没有提交记录的旧作业时停止，保留已发生费用，不自动重跑。

主机从CAS读取测量结果，不依赖可修改的 `results/measurement.json` 副本。费用只结算一次；被恢复程序标为interrupted的既有预留费用仍保留，不另建收费ID。

23项相关测试通过，包含两种验证器在完成事件之前中断、未知进程、输入变更、旧作业缺失绑定、修改结果副本，以及原有shadow、reference、pipeline和预检行为。这里没有重复全量519项回归；v23安装包早于本变更。

真实CPU验收位于 `rec-harness-runs/tool-validation-recovery-v1`：两个解析参考案例，首个成功进程在结果提交前模拟中断。恢复读取原CAS，继续第二个案例，总计两个CPU隔离作业、2 BCU；重复终态调用无新增作业或费用。没有Codex、GPU或Amazon训练，不提供工具科学效用结论。

上述真实CPU验收覆盖直接恢复同一个验证器目录。后续外层Evolution已接通稳定阶段目录：调用前冻结候选、命令、协议和费用前缀；报告先进入CAS和事件，再判断验证门槛。报告提交或成功进程结束后中断，恢复复用既有报告，不重启验证器。

reference/shadow及pipeline的离线、影子阶段允许在核对未完成案例收据后继续，保留原案例身份。每次实际重启验证器进程仍单独计费，已经完成的CPU案例不重新计费或执行。自定义验证器、在线验证器或旧未绑定目录不能推断为可重启；恢复请求保留为待处理状态，不写入候选科学淘汰或Evolution终态。

新增工程测试覆盖报告CAS恢复、进程成功但报告未提交、未知自定义进程重复恢复不执行，以及外层恢复与reference案例收据的组合。组合单元测试使用模拟CPU执行器；后续真实外层验收见下段。v23安装包不包含这两轮恢复变更。

外层变更全量源码回归发现527项，523项通过、4项显式OS测试跳过；独立启用并补跑的4项全部通过。验收目录 `rec-harness-runs/outer-validation-recovery-v1` 保存两份原始日志、源码/测试摘要和范围说明，另通过公开边界及diff空白检查。

## 真实外层及项目入口验收

`rec-harness-runs/outer-validation-cpu-v1` 在源码 `bffd575` 上执行真实Evolution correctness阶段：脚本作者提供解析工具；首个验证器子进程在CPU成功收据落盘后、案例事件提交前注入KeyboardInterrupt，父调用也注入中断，保留阶段待恢复状态。再次通过Evolution.validate进入，同一目录启动第二个验证器进程，复用首个案例收据并完成第二个案例。

实际共两个验证器进程、两个隔离CPU案例，首个收据摘要未变，没有job-2；再次读取已接受阶段不执行进程。控制器费用3（脚本生成1、两次验证器调用2），案例账本费用2，合计5。acceptance.json保存源码、注入脚本和收据摘要。没有Codex调用或Amazon训练。这是明确注入的中断，不是任意时刻SIGKILL，不证明六阶段晋升或在线科学效用。

项目入口另新增两项工程回归：未知验证器结果重复恢复保持项目阶段与事件链不变，不重复优化器；报告归档后中断能从项目入口复用报告，继续数值淘汰及后继模型。该模块8项测试全部通过。本轮未改变运行时代码，不重复上面的全量回归；527项全量结果不包含这两项新增项目测试。
