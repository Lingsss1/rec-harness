淘宝 CTR 双版本轨迹诊断
快照：2026-11-05 03:27:06 UTC。分析仅使用验证记录、模型源码、公开研究产物与运行器日志；未读取封闭测试分数。

核心判断
当前差距主要对应两条轨迹选择了不同的研究问题：auto 较早把目标匹配次数、近时行为与顺序直接送入预测器；强化版长期调查同一乘积归一化及反向梯度路线。额外的检索/反思未配套可执行的早期复核、分支退出及资源调度动作。另有两个已确认的运行器问题。本轮有重启和中途修复，且每版只有一条 Agent 轨迹；这些观察不能识别“记忆本身导致变差”的因果效应。

一、成绩与公平性检查
1. 故障前快照：auto 160 次训练尝试全部成功，最高验证 AUC 0.6209487955、Logloss 0.1957836803。强化版 96 次尝试中 92 次成功，最高 AUC 0.6152795937、Logloss 0.1965389628。
2. 同为前 35 次训练时，auto 的累计最佳 AUC 0.6186034709，强化版 0.6149987417。差距不只对应训练次数多少。
3. 强化版 01:24:45 UTC 停止之前，auto 已获得当前最高 AUC 0.6209487955。因此该停机损失后续探索机会，但不能解释已经出现的全部分数差。
4. 所有搜索训练使用 seed 42，独立模型种子复核尚未完成。auto 的最高分来自 control 分支；AUC 优势不等于所提复杂机制成立，更不等于研究新颖性已验证。

二、auto 的关键轨迹及对照
- r0000：在相同参数量下，目标匹配 count AUC 0.6167540723，活动 support count 0.6133185009；target match rate 为 0.6163503542。这是目标对应信息有用的局部对照，不能只归因于多加参数。
- r0001：对齐时间摘要 0.6171490323，高于活动时间和解耦时间对照。
- r0002：联合类目/品牌匹配候选 0.6183522161，support_pair 对照 0.6184566652。具体联合机制未胜出，但可用的历史表示得到改进。
- r0005：参考 QueryFormer 的上下文查询对照中，query_adaptive 0.6185595642，query_blind 0.6186034709。没有证据证明目标条件字段选择优于较简单的学习型选择。
- r0010/r0011：显式最近目标匹配和最近非匹配行为分别达到 0.6187731489、0.6193279424。
- r0012/r0013：时间相对顺序及支持条件提升至 0.6196262013、0.6198327315。
- r0023/r0026：互补较新行为量、按时间排列的匹配切换达到 0.6205084405、0.6206353961。r0026 ordered_switch 相比 exchangeable_switch 的 AUC 优势约 0.0004158061，仍是单种子证据。
- r0033：gap_factorized_symmetric 对照最高 0.6209487955。该结果不支持必须保留联合事件耦合或箭头方向的解释。
这些尝试均使用原有因果历史字段，没有额外历史商品 ID。源码明确计算类目/品牌相等条件、分行为统计、时间与切换摘要。

三、强化版的关键轨迹
- r0000：原先提出 context-query/target-query/context-readout 三方对照，但描述性真实实验 ID 被旧运行器误拒，未训练。该初始研究分支丢失，是本轮已有协议事件之一。
- r0001/r0002：按行为次数校正注意力及半强度校正，均未胜过 DIN 基线。
- r0003：同字段乘积达到 0.6144940344。
- r0005：对齐乘积归一化达到 0.6149816912；此后大部分研究围绕这个模型的梯度机制。
- r0006—r0017：分解径向投影/范数缩放、停止梯度、常数替换、历史与行为内供体重排、梯度角色分配和行尺度修改。
- r0017：half_total_magnitude 取得历史最高 0.6152795937，但 Logloss 略差于稳定对照。r0019 exact17_replay 的源码 SHA256、配置、seed 均相同，AUC 却为 0.6149279139。该最高分未稳定复现。
- r0018—r0034：共有 43 次训练；其中 r0019—r0027 有 26 次训练，主要查源码/数值/梯度重放和观察器兼容问题。r0021 四次训练因观察器对张量类型不兼容失败，属于工程执行失败。
- r0028：移除未使用观察器，AUC 保持 0.6151021885。记录训练时间从 r0027 frozen_none 的 611.82 秒降至 523.98 秒；这是移除自行引入的诊断开销，不是已经验证的全新效率建模机制，单次耗时也有波动。
- r0029—r0034：交叉字段控制、同源实现复核、推理与代理梯度的等价实现、短历史切片及闭合复现。最后 closure_half 仍为 0.6151021885，closure_full 为 0.6149816912。
- 从 r0005 到 r0034 的 30 个轮次编号内，79 次训练尝试围绕这一模型家族；没有出现与 auto 显式统计路径对应的独立候选对照。

四、为什么增强闭环没有产生更好的方向选择
观察事实：
1. 轨迹阶段串行 LLM 调用：auto 41 次、5.10 小时；强化版 103 次、8.90 小时。强化版 query+analyze 合计 4.43 小时。这些是调用阻塞时间，包含在原墙钟预算内，不是 GPU 训练时间。
2. 每个有训练的研究轮次，auto 平均投放 3.83 个模型，强化版 2.82 个；四个并行槽位的投放较少。该数字是投放宽度，不是实测 GPU 算力利用率。
3. 强化版在 r0005、r0012、r0017、r0027、r0028、r0034 的公开 next_action 中多次要求 seeds 43/44 的事前固定复核。controller.py 的研究作业却固定 seed=42，只有搜索结束后才执行多种子，没有研究中请求重复、冻结候选或结束搜索的动作接口。
4. 外层循环主要按剩余时间和失败计数终止，没有按分支投入、停滞收益或备选方向覆盖触发换方向。因而“下一步复核”会继续收到“再提交候选”的接口，反复转成同种子机制诊断。
5. host best_trial 始终取历史单次 AUC 最大值。r0017 的最高分即使被后续同源码重放质疑，仍保留为机器选择的 incumbent。记忆中的不稳定性判断没有形成候选资格或重复统计的可执行更新。
6. 两版都访问了论文和行业来源。修复后的可追踪声明中，auto 在 r0005/r0007 声明采用 QueryFormer/UniDot 思路；强化版行业方案主要标为 considered/rejected/unresolved，没有行业 used 声明，且 3 轮行业覆盖记录不完整。强化版实际多次读取 CRAFT、QueryFormer、UniDot 原文。不能由“没有 used 声明”推断它完全没有受行业知识影响，也不能把读取次数当成建模收益。

基于轨迹的解释：
- 明确的字段匹配、计数和时间条件是这个粗粒度历史任务中可检验的直接信号。auto 较早找到强对照后持续扩展表示；强化版较早转入只改变已有表示学习路径的梯度研究。
- 后续检索问题由同一局部问题生成，反思和经验回用主要帮助继续解释该分支。即使检索已按知识类别分开，也不会自动产生新的研究问题。
- 为了保护因果归因而长时间保持前向不变，本身有科学价值；但缺少分支收益/成本和退出动作时，会挤占其他机制候选的预算。这是闭环设计与资源分配问题，不能简单解释为“推理越多越差”。
上述解释有轨迹支持，尚未通过同起点、同预算、多条 Agent 轨迹的消融识别因果效应。

五、成本与贡献的边界
- auto 最高分模型约 17,147,683 参数、68,995 dense 参数；强化版模型约 17,130,275 参数、51,587 dense 参数。总参数只差约 0.10%，但 dense 参数多约 33.7%，不能笼统称完全等容量。
- auto 最佳模型记录训练约 826.88 秒、验证推理 33.52 秒；强化版最终稳定 closure_half 约 521.70 秒、16.85 秒。auto 的精度优势伴随更多统计计算和更高实际成本。两组计时来自不同执行时段，仅作成本观测。
- auto 多处对照优于拟议复杂机制，强化版也正确发现最高分不稳定；模型效果、机制证据与方案差异应分别报告。
- auto 已经发生过提前测试事件并重跑，当前受仅验证集评估限制；强化版也经历误拒和中途修复。本轮不能恢复为干净的独立测试工作流因果比较。

七、建议下一轮预先声明的改进（本轮未实施）
- 为研究循环增加 request_repetition、freeze_candidate、switch_branch、finish_search 等可执行动作，种子和预算仍由主机约束。
- 在外部运行协议中声明分支预算与停滞退出条件，给独立问题候选保留资源；有明确机制证据时允许继续深入。
- 记忆同时记录收益/成本、未探索方向、反例和退出条件。让反思改变下一步实验动作，避免只追加更长的解释。
- 对不稳定候选保存所有结果并根据事前规定的重复统计选型，避免单次历史最高分长期锁定机器 incumbent。
- 用同起点的表示分支与梯度分支对照、配对模型种子和多条独立 Agent 轨迹检验这些解释。不能用本次事后分析替代下一轮对照。
