RecHarness 迁移副本（Linux x86_64）

1. 本目录是任务文件和环境的副本，不是运行中进程的迁移。
   原实验仍在原路径运行；旧 PID、launcher 和 frozen 文件仅作为历史记录。
   不要直接恢复历史 launcher，不要覆盖已有预算或训练目录。

2. 在本目录执行：
   source portable/activate.sh
   python-controller portable/doctor.py
   所需 Python 3.10、Python 依赖、Node 和现有 Codex 程序均包含在副本内。
   不需要预先安装 Python 虚拟环境或 Codex。
   不包含账号、密钥和登录凭据。目标机必须另行提供可用的 LLM 认证和网络。
   GPU 运行需要兼容的 NVIDIA 驱动。此环境适用于 Linux x86_64，glibc >= 2.35。

3. 新数据集需要先转为现有评估器接受的格式：
   DATA/trainval/数据集名_train.txt
   DATA/trainval/数据集名_valid.txt
   DATA/test/数据集名_test.txt
   每行“用户整数ID 物品整数ID”，物品编号从 1 开始，0 用作 padding。
   训练文件按用户的时间顺序排列，train/valid/test 分开；通常为末两次交互留作验证和测试。
   DATA/trainval/dataset_stats.json 记录每个数据集的 itemnum。
   Self-EvolveRec 还需要 DATA/trainval/数据集名_text_name_dict.json.gz。
   注意这个沿用历史文件名的文件实际由 pickle.load 读取；内容包含 title、description、time 字典。
   没有文本或时间时应明确记录 unavailable/空字典，不要伪造观测。
   验证仍默认每数据集最多 200 用户、99 个负候选；最终测试最多 10000 用户。

4. 创建一份全新的 MLE-STAR / Self-EvolveRec 对比配置（不训练）：
   python-controller portable/new_comparison.py \
     --data /新数据目录 --datasets DatasetA,DatasetB \
     --model gru4rec --method mlestar --gpus 0,1,2,3 \
     --output /全新实验目录 --budget 43200

   创建并执行训练时，在同一命令最后增加 --run。
   --model 支持 gru4rec / nextitnet / bert4rec / hstu。
   --method 支持 mlestar / self_evolverec。
   每次使用不同的全新 --output；四张卡有其他任务时会等待。
   新配置会使用本副本中的环境和修正版冷启动，不复用历史搜索结果或训练权重。
   新数据集名称通过子进程环境传递，不修改历史源码和当前机器的原实验。

5. RecHarness 的六臂、联合调参、多组合 jump、memory v2 源码也已随整个任务目录保留：
   artifacts/RecHarness-sasrec-jump-v4-20261029/
   该版本的专用运行器当前约束 SASRec；不要把它当作其他模型的通用运行器。

6. 可整体复制本目录到另一台 Linux GPU 机器；portable 入口按自身所在路径定位。
   原始 .venv/bin/python 使用系统 Python 的绝对软链接，迁移后请使用 python-controller/python-worker。
   不要仅凭旧配置中的 /home/liuzhishan/... 路径执行；使用上述入口生成新配置。
