POSITIONING

一句话定位

Agent Laboratory 用角色分工而不是单个全能 Agent：PhD、Postdoc、ML Engineer 与 Professor 分别负责文献、计划、实验、解释和写作；mle-solver 维护 top-program pool，paper-solver 维护可编译的论文。

先看结论

适合把 RecHarness 拆成 Researcher / Developer / Reviewer，而不是让同一 Agent 同时提出假设、实现和验收。top-program pool 也比单一 best checkpoint 更适合保留可组合的模型分支。

SYSTEM DESIGN

设计思想：它改变了哪一层？

  1. 文献阶段迭代执行 summary/full-text/add-paper，形成精简语料；PhD 与 Postdoc 对话形成实验计划。
  2. mle-solver 用 EDIT/REPLACE 变换程序，执行后由 LLM reward model 按研究目标评分。
  3. top-program pool 随机采样父程序并批量并行修改，在保留高质量的同时增加多样性。

MATHEMATICAL CORE

数学原理

p ~ Uniform(TopKPrograms) children = {EDIT(p), REPLACE(p)}_batch reward = LLM(plan, code, observed_output) ∈ [0,1] TopK ← keep_best(TopK ∪ children)

top-K 精英保留类似进化算法：选择压力来自 reward 排序，随机抽取精英避免只围绕唯一冠军。LLM reward 是“与研究计划的对齐度”，不是任务真实指标，因此更适合评估研究完整性，却也更容易受语言表象影响。

阅读提醒：这些 Agent 多数不是在参数空间求可微最优，而是在 artifact/code space 做黑盒搜索。公式描述的是算力如何在候选之间分配，而不是替代真实实验。

MEMORY ARCHITECTURE

Memory 不是聊天记录

Write · 写什么文献摘要/full text、计划、top programs、执行输出、最近错误、self-reflection、结果解释和报告版本分别落入阶段产物。
Read · 谁在何时读每个角色只读取其职责需要的阶段上下文；mle-solver 读取 top pool 与有限错误历史，paper-solver 读取计划/结果/文献。
Forget · 如何控噪完整文献使用 history decay；错误只保留最近若干条；角色边界阻止所有上下文进入单一 prompt。

建议的数据结构

ProjectMemory { literature_bank, accepted_plan, top_programs[{code, output, reward}], recent_errors[-5:], reflections, interpretation, report_versions, reviews }

实现时应把 raw artifact 与 prompt view 分离：前者完整可追溯，后者按 operator/阶段动态裁剪。摘要只是读取视图，不应覆盖原始实验记录。

不能从论文直接推出什么

  • LLM reward 可能奖励“看起来像研究”的代码，而非真实科学价值。
  • 角色增多会产生信息损失和协调开销，阶段交接质量决定上限。
  • 论文报告的文献阶段失败率较高，长文输入和命令循环仍是明显脆弱点。

DESIGN TRANSFER

迁移到 Ling 的项目

最小复现顺序

  1. 先定义 artifact schema 与可重复的 evaluator。
  2. 只实现一种 operator 和一种 selection policy，得到可运行 baseline。
  3. 加入按作用域读取的 memory view，并记录重复试验率。
  4. 最后再增加并行、Crossover、Reviewer 或多角色，逐项做消融。
