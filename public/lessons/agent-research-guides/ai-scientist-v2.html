POSITIONING

一句话定位

v2 去掉人工代码模板，并把线性实验升级为四阶段的渐进式树搜索。Experiment Manager 在阶段边界选择 checkpoint、重复关键实验，并用专门节点管理超参、消融、复现与聚合。

先看结论

这是 RecHarness 的直接蓝图：把实验生命周期拆成 feasibility、tuning、agenda、ablation 四个 gate；阶段间只传可恢复 checkpoint，并强制 replication/aggregation 后才形成结论。

SYSTEM DESIGN

设计思想：它改变了哪一层？

  1. 四阶段：可行性原型 → 超参调优 → 核心研究议程 → 消融；每阶段有不同终止条件和节点类型。
  2. buggy 节点走 Debug，non-buggy 节点走 best-first refinement；多个节点并行执行。
  3. 性能、训练动态和图表质量共同进入 LLM/VLM 评估；阶段末最佳节点成为下一阶段 root。
01 State任务、workspace、预算与当前 artifact
02 Select选择分支、组件或阶段目标
03 Operate生成、修复、改进或组合代码
04 Evaluate执行并获得指标、错误与审阅信号
05 Remember写回持久状态并决定下一跳

MATHEMATICAL CORE

数学原理

root_{k+1} = SelectBest(Tree_k | metric, dynamics, figures) Node = {plan, code, trace, runtime, metrics, plots, LLM/VLM feedback, status} Report metric = mean(seed runs) ± std(seed runs)

它采用分阶段 best-first search，而非固定 UCT。阶段约束相当于课程：先解决可执行性，再优化性能，最后补科学证据。Replication/Aggregation 节点把随机种子重复与统计汇总编码为搜索动作，降低单次幸运结果被选中的概率。

阅读提醒：这些 Agent 多数不是在参数空间求可微最优，而是在 artifact/code space 做黑盒搜索。公式描述的是算力如何在候选之间分配，而不是替代真实实验。

MEMORY ARCHITECTURE

Memory 不是聊天记录

Write · 写什么每个 node 完整保存计划、代码、trace、runtime、指标、图路径、LLM/VLM 反馈和状态；阶段末写 checkpoint。
Read · 谁在何时读子节点继承父节点 artifact；Manager 读取整阶段候选的结构化摘要；超参/消融清单用于查重。
Forget · 如何控噪阶段切换只携带被选中的 checkpoint 作为新 root，其他分支留在档案中供审计，但不持续占用活动上下文。

建议的数据结构

ExperimentNode { plan, code, error_trace, runtime, metrics, llm_feedback, plot_code, figure_paths, vlm_feedback, status } StageCheckpoint { stage, best_node, replications, aggregate }

实现时应把 raw artifact 与 prompt view 分离：前者完整可追溯，后者按 operator/阶段动态裁剪。摘要只是读取视图，不应覆盖原始实验记录。

不能从论文直接推出什么

  • LLM best-first evaluator 不是可校准的数值价值函数，选择过程仍可能不稳定。
  • 阶段末只延续单一冠军会丢掉多样性和可组合 stepping stones。
  • workshop 级接收不等于稳定生成高影响研究；论文也明确指出新颖性与深层论证仍困难。

最小复现顺序

  1. 先定义 artifact schema 与可重复的 evaluator。
  2. 只实现一种 operator 和一种 selection policy，得到可运行 baseline。
  3. 加入按作用域读取的 memory view，并记录重复试验率。
  4. 最后再增加并行、Crossover、Reviewer 或多角色，逐项做消融。
