POSITIONING

一句话定位

The AI Scientist v1 把自动科研从“某个子任务”扩展为完整生产线：Idea → Novelty Check → Code/Experiment → Plot → Paper → Review，并把完成的 idea 与 reviewer feedback 加回档案库。

SYSTEM DESIGN

设计思想：它改变了哪一层？

  1. 初始代码模板提供一个可快速复现的 baseline，LLM 以此为可执行实验环境。
  2. idea 同时携带描述、实验计划和 interestingness/novelty/feasibility 自评分；文献检索作为 novelty gate。
  3. 每个实验完成后写实验日志，再根据结果重规划；最终论文只允许引用真实记录和图表。
01 State任务、workspace、预算与当前 artifact

MATHEMATICAL CORE

数学原理

idea_i ~ LLM(archive_{<i}) score(idea) = [interestingness, novelty, feasibility] archive_{t+1} = archive_t ∪ {paper_t, artifacts_t, review_t}

这是开放式进化而非单一标量优化：LLM 充当 mutation operator，档案库保留多样化 stepping stones。自动评审把 soundness、presentation、contribution、overall 等维度映射为选择信号，但自评与代理评审都可能产生 Goodhart 偏差。

阅读提醒：这些 Agent 多数不是在参数空间求可微最优，而是在 artifact/code space 做黑盒搜索。公式描述的是算力如何在候选之间分配，而不是替代真实实验。

MEMORY ARCHITECTURE

Memory 不是聊天记录

Write · 写什么idea JSON、检索判重结果、实验 journal、错误、结果文件、图、论文和 reviewer feedback 全部落盘。
Read · 谁在何时读下一轮 idea 读取历史 archive；实验阶段读取当前执行历史和 journal；写作阶段读取结构化 notes 与 figures。
Forget · 如何控噪主上下文不承载所有旧实验，跨项目只暴露 archive 摘要/评分；项目内依赖文件系统作为持久记忆。

建议的数据结构

ResearchArchiveItem { idea:{description, plan, self_scores}, novelty_check, experiment_journal[], artifacts:{code, results, figures}, manuscript, review }

实现时应把 raw artifact 与 prompt view 分离：前者完整可追溯，后者按 operator/阶段动态裁剪。摘要只是读取视图，不应覆盖原始实验记录。

不能从论文直接推出什么

  • 依赖人写的模板，研究方向受起始代码限制。
  • 自动 reviewer 与生成器可能共享偏差，无法替代真实同行评审。
  • 代理指标和少量实验可能产生看似完整但证据薄弱的论文叙事。

DESIGN TRANSFER

迁移到 Ling 的项目

把 RecHarness 的每次研究路线存成 archive item，而不仅是 best checkpoint；review feedback 进入下一轮路由先验。真正可复用的是 experiment journal + artifacts + negative result。

最小复现顺序

  1. 先定义 artifact schema 与可重复的 evaluator。
  2. 只实现一种 operator 和一种 selection policy，得到可运行 baseline。
  3. 加入按作用域读取的 memory view，并记录重复试验率。
  4. 最后再增加并行、Crossover、Reviewer 或多角色，逐项做消融。
