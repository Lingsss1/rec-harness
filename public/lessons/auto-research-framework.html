REC HARNESS · AUTO RESEARCH · 0d7430c

当前 Auto Research 框架

它不是重新实现一套多 Agent 平台，而是把 Codex 变成研究负责人：Harness 提供确定性的下一步、证据门禁与长期状态；Codex 按需调用原生子 Agent；GPU Controller 负责可复现执行。

一句话理解

Codex 负责提出与判断，Harness 负责约束与记忆，诊断工具负责测量，GPU 实验负责给出最终证据。

1 个根 Codex唯一研究状态写入者
5 层血缘Arm → Idea → Investigation → Hypothesis → Candidate
4 个组合槽位Commit / Exploit / Explore / Diagnose
2 × 4 实验两个数据集上的配对候选验证

MODULE BREAKDOWN

模块拆解

六个模块分别解决研究对象、下一步选择、并行认知、资源分配、实验执行与长期学习。它们通过稳定 ID、Hash 和 append-only 证据连接，而不是通过一段无限增长的对话连接。

01

Typed Research Graph

把“研究方向”和“具体改动”分开。Arm 保持宽而稳定，Idea 承载机制，只有经过调查和可证伪假设，才能进入候选实现。

STABLE DIRECTIONArm表征几何、特征信息、交互结构、监督目标等宽方向
MECHANISMIdeaArm 下的具体机制想法；有去重、状态与独立 posterior
EVIDENCE WORKInvestigation研究问题、信息缺口、预算、证据与 reconciliation
FALSIFIABLEHypothesis机制、跨数据集预测、最小测试与证伪条件
EXECUTABLECandidate明确 change、成本、风险、信息价值与预期 AUC
MEASUREDPaired Runs两个数据集的固定协议结果，反向更新 Idea 与 Arm

为什么要分层：如果把每个具体改动都当 Arm，Bandit 会随着 Idea 数量无限膨胀；现在 Bandit 在稳定方向上积累弱先验，在 Idea 层快速奖励或淘汰具体机制。

02

Harness Next Router

harness next 是只读的确定性路由器。它不代替 Codex 的科学判断，只把当前最优先的状态转移、所需命令和 State Hash 返回给 Codex。

Batch 已完成 → Ingest实验事实尚未摄取时，禁止进入任何新研究动作。
运行中 → WaitGPU 批次未结束，不产生新候选。
已 Dispatch → Reconcile先收回子 Agent 证据，不能越过门禁。
诊断到期 → Revalidate旧诊断不能无限期作为先验。
已 Plan → Decide根 Codex 明确选择 Dispatch 或 Cancel，不自动委派。
调查未完成 → Continue在硬预算内补足最小承诺与归因证据。
假设就绪 → Candidate把可证伪假设实例化为可执行改动。
四个 Idea 就绪 → Portfolio构造四槽位候选组合；方向空缺时再 Idea Burst。

04

Bandit 与四槽 Portfolio

Generator 产生 Arm 下的 Idea；Bandit 不负责无限生成，而是对经过证据门禁的 Candidate 分配昂贵 GPU 预算。

候选效用

P(win | Candidate, Idea, Arm) × conservative_gain + 0.20 × information_value − 0.15 × cost − 0.15 × risk

跨数据集预期增益取较小值，防止只优化一个数据集。实验结果强更新 Idea posterior、弱更新稳定 Arm posterior，避免一次局部失败直接否定整个方向。

SLOT 01Committed Continuation已经承诺最小调查预算的 Idea，避免每轮跳方向。
SLOT 02Exploit保守预期增益为正、已有证据最强的候选。
SLOT 03Explore信息价值高，用有限成本检验新机制。
SLOT 04Diagnose / Revalidate高风险、高歧义或需要复核的方向，用实验换取下一轮决策信息。

ONE RESEARCH ROUND

一次完整研究轮次

根 Codex 每次只推进一个明确状态转移。子 Agent 可以并行扩大调查宽度，但 GPU 训练、状态更新和最终晋升仍然由确定性边界控制。

STEP 01读取 Next读取 Runtime、Research Graph 与 Review 状态，获得决策回执。
STEP 02补充证据运行诊断、检查代码，必要时委派文献或竞争解释子任务。
STEP 03形成假设写出机制、两个数据集预测、最小测试和证伪条件。
STEP 04实现候选登记精确 Change；结构冲突时才使用独立 Worktree。
STEP 05选择组合Bandit 构建四槽 Portfolio，生成 8 个配对运行。
STEP 06GPU 验证Controller 校验协议、执行训练、解析指标与错误。
STEP 07摄取 Batch先保存 Episode、Failure 与配对结果，再确认本批证据已经处理。
STEP 08记录进化更新 Outcome、Posterior 与 Strategy；触发时 Consolidate Lessons。

THREE NESTED LOOPS

方法核心：三层循环

这套框架不是一个从 Prompt 直接跳到训练的“大 Agent”。它把开放的科学推理、可审计的执行控制和慢速的长期学习拆成三个不同时间尺度。

LOOP 01 · SCIENTIFIC REASONING

Codex 探索“为什么”

从未知量出发，优先选择最便宜且会改变决策的证据；比较竞争解释之后，才形成能够被实验推翻的假设。

信息缺口→诊断 / 论文 / 代码→竞争解释→假设
LOOP 02 · EXECUTION CONTROL

Harness 约束“现在能做什么”

next 根据 Runtime 与 Research Graph 给出唯一优先动作；State Hash 防止旧决策覆盖新状态，Receipt 保留每次转移的因果链。

State→Next→One Transition→Receipt
LOOP 03 · LONG-TERM LEARNING

Memory 学习“以后先做什么”

每轮先忠实保存事实与失败，再按触发器合并为带适用范围、反证和来源的 Lesson；慢速更新下一轮搜索策略，而不是不断增长 Prompt。

Artifact→Episode→Lesson→Strategy
三层的关系：科学循环提高单个 Idea 的质量；执行循环保证实验顺序和状态一致；学习循环把多轮证据压缩成下一次可检索的先验。三者分开，Codex 才能保持开放探索，同时避免遗忘、抢跑和无效重复。

DESIGN PRINCIPLES

四条边界

这些边界决定了框架是“增强 Codex 的研究 Skill”，而不是另一个需要维护的多 Agent 平台。

Codex 决策

Idea、论文理解、代码修改、竞争解释和最终判断保留给模型。

Harness 约束

状态转移、预算、血缘、Hash、选择和证据门禁交给确定性代码。

子 Agent 临时

没有永久角色和独立 Memory；只接收最小 Context Pack，返回 Artifact。

实验裁决

Agent 共识不是科学证据，只有诊断与受控实验能够改变 Posterior。

目标不是让 Agent 做更多实验，
而是让每一小时 GPU 带来更多可复用的信息。

当 Research Graph、证据门禁、Memory 和执行协议闭合后，Codex 才真正具备长期、可验证、可自我修正的模型优化能力。
