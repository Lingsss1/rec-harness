QUESTION 01 · MULTI-TASK

多目标任务中，梯度冲突怎么解决？

面试官在考

你是否知道“Loss 不平衡”和“梯度方向相反”不是一回事；是否能从诊断走到结构与优化方案。

30 秒推荐回答定义 → 诊断 → 分层解决

对共享参数分别计算各任务梯度。若两个梯度内积小于零，说明更新一个任务会在局部损害另一个任务；如果方向一致但 norm 差很多，则是量级失衡。我会先监控共享层的梯度 norm 和 cosine：量级问题用 Loss 权重或 GradNorm，方向问题可用 PCGrad；如果冲突长期集中在共享层，优先用 MMoE/PLE 或任务专属层减少硬共享，辅助目标则考虑 stop-gradient。

gt = ∇θsharedLt
cos(g₁,g₂) = g₁ᵀg₂ / (‖g₁‖‖g₂‖)
g₁ᵀg₂ < 0 ⇒ 局部方向冲突
01

Loss 重加权

固定权重、Uncertainty Weighting、GradNorm。主要平衡量级，不保证消除负方向。

02

PCGrad

把一个梯度中与另一个任务冲突的投影分量去掉，直接处理方向冲突。

03

MMoE / PLE

共享多个 Expert，让不同任务通过 Gate 选择不同组合，降低不合理的硬共享。

04

梯度隔离

对校正类、辅助类目标使用 stop-gradient，避免它们反向污染主任务表示。

若 gᵢᵀgⱼ < 0：　gᵢ ← gᵢ − (gᵢᵀgⱼ / ‖gⱼ‖²)gⱼ　　# PCGrad
容易答错“给各任务 Loss 调权重”不等于完整解决梯度冲突。权重能改变梯度大小，但两个方向仍可能相反；要明确什么时候用权重、什么时候做梯度投影、什么时候改网络结构。
QUESTION 02 · ATTENTION MASK

Attention 中，pos2 可以访问 pos3 吗？

面试官在考

位置编码只告诉模型“这是哪个位置”，真正决定能否访问未来位置的是 Attention Mask。

20 秒推荐回答看 Mask，不看位置编号

如果是 Transformer Encoder 的双向 Self-Attention，pos2 可以访问 pos3；如果是自回归 Decoder 的 Causal Self-Attention，pos2 不能访问未来的 pos3。Decoder 的 pos2 在 Cross-Attention 中通常可以访问全部 Encoder positions。位置编码不负责屏蔽，Mask 才负责。

Encoder：全可见

K1K2K3Q1✓✓✓Q2✓✓✓Q3✓✓✓

pos2 → pos3：可以。

Decoder：Causal

K1K2K3Q1✓××Q2✓✓×Q3✓✓✓

pos2 → pos3：不可以，防止标签泄漏。

模块pos2 能否看 pos3原因
Encoder Self-Attention能默认双向、全可见
Decoder Causal Self-Attention不能上三角位置被 Mask
Decoder → Encoder Cross-Attention通常能可读取全部有效 Encoder 状态
Padding 位置不能由 Padding Mask 屏蔽
QUESTION 03 · ONEREC

OneRec 如何处理用户序列、构建 SID？

面试官在考

不要只说“Transformer Encoder-Decoder”。应拆成物品 Tokenizer、用户 Encoder、SID Decoder 三条数据流，并区分两种 K-means。

60 秒推荐回答先离线建 SID，再在线编码用户

OneRec 先在物品侧将 caption、tag、ASR、OCR、封面和视频帧编码成多模态 token，再用 Q-Former 压缩，并通过协同相似 item pair 做语义对齐。随后 RQ-Kmeans 逐层量化残差，给每个视频生成三层 coarse-to-fine SID。用户侧则把静态、短期、正反馈和 lifelong 四路表示拼成序列，加位置 embedding 后进入全可见 Transformer Encoder；Decoder 通过因果 Self-Attention 和对用户表示的 Cross-Attention，自回归生成 [BOS,s¹,s²,s³]。

3.1 物品 Tokenizer：视频怎样变成 SID

多模态原始信息Caption · Tag · ASR · OCR · Cover · 5 Frames
→
miniCPM-V 表征1280 个 token × 512d
→
4 Query Q-Former压缩并注入协同相似性

这里的 Tokenizer 不是 BPE。它是一个离线的“物品 → 离散代码序列”映射：

rᵢ¹ = eᵢ
sᵢˡ = argmink ‖rᵢˡ − ckˡ‖²
rᵢˡ⁺¹ = rᵢˡ − csᵢˡˡ

为什么做残差量化？第一层中心解释主要语义，下一层只拟合没有解释掉的细节；原向量近似为三个中心之和。SID 保存的是中心编号，不是中心向量本身。

3.3 必须区分的两个聚类

全局 RQ-Kmeans

对象是全量视频表示，输出每个视频的三层 SID，用作生成目标和可选的视频身份表示。

用户内层次 K-means

对象是单个用户的超长历史，用于从最高约十万行为压缩出代表行为，之后再让 Q-Former 压到 128 个兴趣 token。

版本差异要说清2025 年 2 月的 OneRec 论文以 SID 历史和 session-wise 列表生成为主；2025 年 6 月技术报告给出了更完整的四路 Encoder，并使用 point-wise SID Decoder。面试时先确认对方问的是原始 OneRec 还是 Technical Report。
QUESTION 04 · NORMALIZATION

BatchNorm 和 LayerNorm 有什么区别？

面试官在考

归一化到底沿哪条轴计算；样本是否互相影响；训练和推理是否一致。

30 秒推荐回答BN 跨样本，LN 在单个 Token 内

对 X[B,T,D]，BatchNorm 通常固定 feature/channel，跨 batch 及空间或序列位置统计均值方差，因此依赖 batch，推理还要使用移动统计；LayerNorm 则对每个 (b,t) 单独沿 hidden dimension (D) 归一化，不依赖其他样本，训练推理一致，所以更适合变长序列和 Transformer。

BatchNorm： μd = meanb,t Xb,t,d
LayerNorm： μb,t = meand Xb,t,d
维度BatchNormLayerNorm
统计范围同一通道跨 batch单样本、单 token 的 hidden dimensions
样本是否互相影响是否
依赖 batch size是否
训练与推理当前统计 vs 移动统计计算方式一致
常用场景CNN、大 batchTransformer、RNN、变长序列
继续追问 RMSNormOneRec 使用 RMSNorm。它与 LN 一样按 token 处理，但不减均值，只用均方根控制尺度：x / sqrt(mean(x²)+ε)，计算更简单。

高概率继续追问

负梯度余弦一定说明两个任务不能一起训练吗？
不一定。单 batch 的负余弦可能只是采样噪声；应跨 batch、时间窗口和共享层观察稳定性，并结合任务指标是否出现跷跷板。稳定冲突才值得改结构。
PCGrad 有什么缺点？
需要分别获得任务梯度，计算和显存成本更高；任务顺序可能影响投影结果；消除局部冲突也不等于得到全局最优的 Pareto 解。
Encoder 为什么通常不需要 Causal Mask？
Encoder 的目标是理解完整输入，而不是预测下一个输入 token，因此允许任意位置双向聚合上下文。Padding 或业务结构限制仍可额外加 Mask。
为什么不直接给每个视频一个原子 ID Token？
十亿级且持续增长的物品空间会带来巨大词表和参数，冷启动物品也无法共享知识。SID 用固定小词表组合编码，让语义接近的物品共享前缀。
RQ-Kmeans 会不会出现非法 SID？
会。理论组合空间远大于真实视频集合，Decoder 可能生成不存在的视频代码组合。工程上需要合法前缀约束、Trie/受限解码或 Format Reward。
为什么小 batch 不适合 BatchNorm？
均值方差估计噪声大，且推荐任务中样本分布会随流量、场景和正负比例变化。分布式训练若各卡独立统计，单卡有效 batch 更小。
