01 · Positioning

面试官应该记住你的哪一句话

百度推荐策略看重的是能否把用户价值、模型、实验与线上系统连起来。你的差异点不是模型名最多，而是能把失败实验转化为下一轮的可验证证据。

推荐面试的价值证明顺序：真实业务问题 → 建模假设 → 最小改动 → 离线与线上验证 → 机制边界。Agent/Harness 放在第五步之后。
“我做推荐时，关注的不只是把 AUC 做高，而是判断瓶颈在哪、为什么这个改动有效，以及怎样让下一轮实验更有信息量。”
这句话能同时承接短视频 Self-Attention、货架反事实学习、RecKit 内部诊断和 RecHarness 长周期搜索。

02 · Risk Audit

先修这些，再开始背稿

下面不是措辞优化，而是可能直接影响可信度的口径问题。所有 P0 项在面试前必须形成唯一版本。

原则：不知道显著性就说“点估计为正，显著性需按具体看板确认”；不能把“未观察到依赖”说成“模块无用”。

教育经历冲突

简历写天津大学硕士；答辩第 3 页写 Georgia Institute of Technology 硕士。这是最严重的可信度风险。

修复：统一所有材料；若 PPT 是模板残留，立即删除并准备一句解释。

短视频实验流量口径

简历写“7 天 10% 流量”，答辩写“每组 11.08%”。面试官追问样本量时会暴露不一致。

修复：明确是近似表达、单组流量还是实验/对照合计，并使用同一口径。

RecHarness 对照数字

材料实际为 Ours 47.92%、Random 22.45%、LLM 21.74%；“2.1 倍”只相对随机搜索。

修复：牢记 23/48、11/49、10/46，以及平均有效增益 5.06% / 4.94% / 5.04%。

线上收益与显著性

短视频看板中只有部分站内指标显著；货架整体曝光 -1.089%，消耗 +0.975%，预期花费 +1.488%。不能笼统说“全面提升”。

修复：区分主指标、护栏指标、显著与方向性结果，并解释曝光下降但价值密度上升。

个人贡献边界

“独立提出 / Demo”“参与 Rec Agent”“第一作者”“候选结构落地”是不同贡献等级，容易被连续追问。

修复：每个项目固定说清 I owned / I collaborated / team infrastructure 三层。

广告推荐迁移到内容 Feed

你的线上经验偏 CVR/CTCVR，而百度岗位可能更关注消费时长、留存、内容质量和作者生态。

修复：主动讲可迁移部分与不可照搬部分，补齐负反馈、多样性、作者冷启动。

RecKit 的因果表述

paired shuffle 证明的是当前分布下预测对样本-表示对应关系的依赖，不等同于“模块因果决定业务收益”。

修复：用“依赖验证 / 干预证据”，避免直接说“因果证明”。

进行中项目不要冒充结论

EviSearch-RL step-100 的过程信用非零说明 credit signal 可用，不代表最终任务效果已经提升。

修复：明确 milestone、已验证结论和下一验收门槛。
03 · Scripts

可直接开口的自我介绍与项目讲稿

讲稿刻意控制术语密度。面试时不要逐字背，要背“结论句、证据数字、边界句”。

自我介绍只讲一个核心身份、两段证据和一个岗位动机。项目讲稿遵循 Situation → Diagnosis → Change → Evidence → Boundary。
60 秒

适合面试开场。重点是推荐算法身份与工业结果；不要在第一分钟塞入所有项目。

面试官您好，我叫凌浩然，目前在天津大学读硕士，主要方向是工业推荐精排和 Agentic Harness。

我在快手做过两类推荐优化：一类是发现原模型缺少行为序列内部的 item-item 交互，在六路序列的 Target Attention 前加入 Self-Attention，离线 AUC 提升 0.09pp，线上 ADVV 提升 2.084%、Revenue 提升 0.534%；另一类是针对货架 CVR 的点击选择偏差，迭代 IPS、DR、SNIPS 和梯度隔离，并通过把 batch 从 512 调到 4096 修正了早期误判。

我还把这些长期实验经验抽象成 RecHarness 和 RecKit，用 Bandit 分配试验预算、用模型内部信号判断实验为什么失败。我希望把这种“业务问题—模型诊断—受控实验—线上归因”的能力用在百度亿级 Feed、用户兴趣建模和多目标排序上。

120 秒

适合“详细介绍一下自己”。Shopee / EviSearch 只证明搜索与大模型能力，不抢推荐主线。

面试官您好，我叫凌浩然，目前在天津大学读硕士，GPA 3.9/4.0。我的核心方向是工业推荐精排，以及如何用 Agent/Harness 提高长周期模型迭代效率。

工业推荐证据

在快手短视频项目中，调参、ML-DCN 和特征接入多轮持平后，我定位到六路行为序列缺少 item-item 交互，在 Target Attention 前加入逐序列 Self-Attention，并保持 shared-bottom 和任务头不变，离线 AUC +0.09pp，线上 ADVV +2.084%、Revenue +0.534%。货架项目中，我从表征增强切换到选择偏差，完成 IPS、SNIPS、DR 与辅助塔梯度隔离，并检查 0.14% 正例率，发现 batch 512 每批只有约 0.7 个正例，扩大到 4096 后才得到稳定结论。

方法抽象

基于 40 多轮工业实验，我作为第一作者推进 RecHarness：用 Thompson Sampling 在候选编辑方向间分配有限 trial，LLM 只在选定方向内生成具体改动。公开任务上有效 trial 命中率 47.92%，随机搜索为 22.45%。我还做了 RecKit，用 activation×gradient 排名与 paired shuffle 验证模块依赖。

岗位动机

我的长期定位仍是推荐算法。百度的搜索和 Feed 行为融合、亿级用户长短期兴趣、多目标列表生成及内容生态，既需要推荐建模，也需要高质量实验和归因，和我的能力比较契合。

3 分钟

第一主项目。要听到你如何从失败实验得到新假设，以及如何控制归因。

问题与约束

目标是在现有 CTCVR 主任务模型上找到可上线增量，约束是保留 shared-bottom、任务头和线上延迟预算。

诊断

调参、ML-DCN 主塔/子塔和 a2a 特征接入多轮持平。共同点是都发生在序列已经被 Target Attention 聚合之后。结构检查发现八路行为序列中只有两路含 Self-Attention，另外六路缺少原始 item-item 交互；HSTU 接收的是主干压缩后的虚拟 Token。

改动与证据

我把搜索方向切到序列编码器升级：在六路 Target Attention 前分别加入 Self-Attention，再经 MLP 压缩接入原接口，任务头、损失和主干保持不变。离线 AUC +0.09pp；线上 ADVV +2.084%、Revenue +0.534%、Exposure +0.559%。显著性按具体指标分别陈述。

边界

结果支持“补齐原始序列交互有效”，但不能证明 Self-Attention 是唯一结构。还应比较等参数 MLP、共享/独立编码器、序列长度分桶和时延成本。

3 分钟

最能体现严谨性的项目。关键是“样本充分性改变了实验结论”。

问题

货架点击率约 2%，CTCVR 正例率约 0.14%，CVR 只在点击样本上可观察。Cross、属性 Gate 和 NISE 都没有稳定收益，因此瓶颈可能不是表示能力，而是点击选择偏差。

估计器与梯度

IPS/DR 中，pCTR 下限 0.1 让约 80% 点击样本权重被截断到 10，失去区分度；放宽又高方差，因此改用 SNIPS 在点击子集内按权重均值归一。辅助塔用于估计 CVR 训练误差，不是制造真实标签；它读取共享特征但 stop-gradient，避免 imputation 误差污染主任务。

充分性与结果

0.14% 正例率下，batch 512 每批约 0.7 个正例，4096 时约 5.7 个，实验才稳定。完整方案离线 CVR/CTCVR AUC 约 +0.29pp。线上货架整体曝光 -1.089%，但消耗 +0.975%、预期花费 +1.488%，更像价值密度提升；是否上线还需显著性、AA 和长期护栏。

3 分钟

先讲工业动机，再讲 Bandit；避免一上来介绍三层框架。

问题

RecAgent 能执行单次实验，但真实精排跨几十个版本，反馈以天计。瓶颈变成有限预算下下一步做什么、失败经验如何不丢、何时需要人切换方向。

方法

我把修改组织成 Input、Representation、Objective、Optimization、Capacity 等语义方向。trial 形成成功/失败信号，更新 Beta 后验；Thompson Sampling 选择下一轮 Top-G 方向，LLM 只在选定方向内结合日志和 Memory 生成具体改动。

结果与边界

RecHarness 有效 trial 为 23/48，即 47.92%；随机搜索 11/49，即 22.45%；LLM 路由 10/46，即 21.74%。优势主要来自方向命中率。公开 benchmark 不能等同工业上线；Arm 仍由人定义，Jump 只开放新方向，下一步还要加入资源成本、时延和 replay gate。

04 · Project Deep Dive

每个项目可能被怎样追穿

“安全边界”不是示弱，而是证明你知道实验能说明什么、不能说明什么。

每个项目至少补齐 baseline、样本、loss、参数增量、训练成本、离线指标、线上指标、显著性、消融与失败版本。
P1 / CORE

短视频广告精排 · 序列 Self-Attention

从聚合后扩容转向原始序列内部交互

第一主项目

最可能追问

  • Target Attention 与 Self-Attention 各解决什么？
  • 为什么 HSTU 不能替代这次改动？
  • 六路分别编码还是共享参数？
  • 时延、显存、参数量增加多少？

必须补齐

  • 10% vs 11.08% 流量口径。
  • 三项线上指标的显著性。
  • AUC +0.09pp 的任务与时间窗。
  • 等参数 MLP / attention pooling 消融。

安全结论

  • 支持原始序列交互是当前瓶颈。
  • 不宣称 Self-Attention 唯一最优。
  • 保持主干和任务头不变，提高归因集中度。
P2 / CORE

货架 CVR · ESCM²-DR-SNIPS

选择偏差、梯度隔离与稀疏正例充分性

第二主项目

最可能追问

  • ESMM、ESCM²、DR 分别解决什么？
  • IPS 为什么高方差？SNIPS 改了什么？
  • 为什么辅助塔要 stop-gradient？
  • 大 batch 是否只是优化器效应？

必须补齐

  • 0.14% 正例率精确定义。
  • 512→4096 时学习率、总 step 是否对齐。
  • clip “约 80%”的统计口径。
  • 曝光下降的业务解释和显著性。

安全结论

  • 大 batch 改善每批有效监督密度。
  • SNIPS 稳尺度，不修复错误 propensity。
  • 线上价值密度仍需长期护栏确认。
P3 / METHOD

RecHarness · Bandit-routed Harness

有限 trial 预算下的方向分配与轨迹记忆

差异化项目

最可能追问

  • Arm 如何定义，粒度变化怎么办？
  • 成功信号是否导致验证集过拟合？
  • 为什么 Beta-Bernoulli，不建模 gain？
  • 2.1 倍是否来自候选生成？

必须补齐

  • 23/48、11/49、10/46。
  • 跨数据集指标怎样归一化。
  • 预算与 early stop 是否公平。
  • 多 trial 相关性如何处理。

  • 主要收益是方向命中率。
  • Arm 由人定义，Bandit 不替代业务判断。
  • 公开任务不等于工业上线收益。

05 · Interviewer Lens

结合公开技术线索的重点准备

公开百度专利中，同名杨牡丹列为第一发明人，主题是利用曝光与行为估计类别偏好并调整排序，以实现精准多样化推荐。

公开专利主题

用户类别偏好 × 曝光反馈 × 精准多样性

这与百度 Feed 的用户兴趣建模、重排、多样性和负反馈天然相关。你的 ESCM²、序列建模和 RecKit 都能连接过去。

同名且方向高度吻合，但公开资料无法用员工编号完成唯一身份验证；以下只作为准备线索，不当作确定个人画像。

曝光偏差

点击少可能是不喜欢，也可能是曝光少、位置差或质量低。回答要包含 propensity、探索桶与负反馈。

多粒度兴趣

体育→篮球→NBA→球星；考虑标签层级、短期突发与长期稳定兴趣。

精准多样性

不是越多样越好，而是在主兴趣下控制重复、探索长尾并发现新兴趣。准备 MMR、DPP 与约束重排。

多目标长期价值

点击、时长、互动、负反馈、留存、质量与作者生态冲突。覆盖模型、融合、重排和实验护栏。

兴趣更新

实时行为不能让偶发点击永久污染画像。准备时间衰减、session/长期双表征与兴趣退场。
