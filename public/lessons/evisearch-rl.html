EviSearch-RL
从可验证 Search Harness
到长程信用分配

一个面向多轮证据搜索的后训练研究：把外置 Evidence State 同时作为 Policy 的观测抽象、Harness 的可验证状态，以及 GRPO 的逐步奖励来源；再探索把 27B Teacher 经 Search RL 学到的策略增量蒸馏给 9B Student。

一句话主线：Evidence State → 可验证状态转移 → 稠密过程奖励 → GRPO 搜索策略优化 → OPD² 策略增量蒸馏。研究价值不在“给 Agent 套一个 Harness”，而在于 Harness 如何改变可学习信号。
已验证：Harness + SFT严格状态机门控下，轨迹完成率 96%，非法引用率 1.62%。
进行中：Harness + GRPO已完成奖励与系统设计，正在验证长程信用分配的训练增益与稳定性。
计划：Harness + OPD²拟用 post-GRPO / pre-GRPO log-prob 差蒸馏 Search RL policy shift。

01 · END-TO-END LOGIC

项目总逻辑：九步闭环

点击任一步查看它在整条研究链路中的作用。顺序不是“先搭系统再训练模型”这么简单，而是先让搜索过程可观测、可验证、可归因，随后才有条件进行稳定的长程后训练。

Step 0 · 先固定任务，而不是先训练

统一构建语料与索引；gold answer / supporting facts 只供奖励和评测使用，绝不进入 Policy observation。否则搜索 Agent 会退化成读取隐藏答案的分类器。

02 · HARNESS-COUPLED POST-TRAINING

“结合 Harness 的后训练”到底结合在哪里？

Harness 不是一个包在模型外面的调用壳。它承担环境状态、合法动作、轨迹记录和奖励仪器四个角色，训练信号直接来自它维护的状态变化。

一次模型交互如何进入训练

① Harness / Environment
  • 维护 Evidence State
  • 执行 SEARCH / OPEN / KEEP
  • 校验预算与引用
  • 记录状态转移 sₜ→sₜ₊₁
→
② Policy / Agent
  • 只观察当前必要状态
  • 输出下一个合法动作
  • 不看到 gold evidence
  • 生成 on-policy trajectory
→
③ Trainer / Learner
  • 终局多目标奖励
  • 状态增量过程奖励
  • GRPO/PPO 更新
  • 权重同步回 rollout
闭环：Policy 的动作改变 Harness 状态；Harness 的状态变化产生 reward；reward 更新 Policy；新 Policy 再进入同一 Harness。真正的耦合点是 state transition → training credit。

当前完成边界

Harness + SFT：已结合SFT 轨迹必须通过同一状态机与引用门控，已证明模型能稳定学习外置证据协议。
Harness + GRPO：方法已设计，实验进行中状态增量已定义为过程奖励；仍需通过 terminal-only vs ABC 的同预算消融证明独立增益。
Harness + OPD²：计划验证项目拟将 OPD² 的 delta 从“reasoning tuning shift”改写为“Search RL shift”，这是一项待验证的迁移假设。
不能声称不能把 ABC、GRPO、AReaL 或 OPD² 本身包装成原创；项目贡献是状态设计、确定性归因适配、系统接入与消融结论。

0冻结任务定义、语料和评测边界先把“搜索环境”变成稳定实验对象已完成

输入

多跳问答问题、统一网页/文档语料、gold answer、gold supporting facts。

具体操作

  • 统一去重、分句、切块
  • 稳定 doc_id / sent_id
  • manifest 固定 revision 与 SHA256
  • 训练集与外测集污染检查

输出

冻结 corpus、索引输入、训练/验证/外测 split，以及可审计的数据版本。

解决问题

避免每道题自带候选段落造成“伪搜索”；避免 Retriever 或语料在 Policy RL 期间漂移。

核心不变量

Gold answer 与 supporting facts 只进入 Reward/Eval，不进入 Policy observation。这是后续“逐步奖励不泄漏答案”的前提。

参考

Search-R1、ReSearch 的多轮搜索训练范式；本项目进一步强调统一语料与可审计索引。

数据处理流水线：从 benchmark record 到统一搜索语料

固定源数据 revision→Unicode/HTML 规范化→标题与正文去重→分句 + 滑窗切块→稳定 doc_id/sent_id→gold 映射→BM25/Dense 索引→manifest + 污染审计

HotpotQA、2WikiMultiHopQA、MuSiQue 等数据原本常把每道题的候选 context 放在样本内部。这里先对训练语料中的 context 取并集、规范化、去重并建成全局 corpus；推理时 Agent 面对统一索引，而不是只在该题自带的少量候选中挑答案。

1构建 Search Harness 与外置 Evidence State把对话历史变成结构化、可验证的状态已完成

状态内容

  • 历史 query 与去重集合
  • 候选 doc_id
  • 已 OPEN 的句子
  • 已 KEEP 的证据
  • SEARCH / OPEN / token 预算

动作协议

核心训练回路：SEARCH → OPEN → KEEP → ANSWER。扩展协议可加入 VERIFY，但不改变“先打开、再保留、后引用”的证据链。

Policy 看到什么

问题、当前决策所需状态、可行动作与预算；不反复塞入全部历史文本。

解决问题

  • 上下文随轮数膨胀
  • 模型伪造来源
  • 证据不可回放
  • 过程 reward 无状态锚点

关键约束

KEEP 只能引用已 OPEN 的 doc_id/sent_id；ANSWER 只能引用已 KEEP 的证据；重复 query 直接短路且不消耗 Retriever 预算。

项目自己的设计价值

外置状态不只是“省 token 的 memory”，而是同时成为 observation abstraction、protocol verifier、replay log、reward instrumentation。

Harness 怎么搭：七个确定性模块

Action Schema / Parser→Protocol Validator→Transition Engine→Tool Adapter→State Store→Observation Builder→Trace + Reward Hooks
  • Action Schema：把模型输出解析成 SEARCH(query)、OPEN(doc_id)、KEEP(doc_id, sent_ids)、ANSWER(text, citations)，拒绝自然语言中夹杂不可执行命令。
  • Validator：检查动作是否在当前状态可执行，例如未 OPEN 的文档不能 KEEP，预算耗尽后不能继续 SEARCH。
  • Transition Engine：以纯函数语义执行 (state, action, tool_result) → new_state，让同一轨迹可确定性重放。
  • Tool Adapter：只有 SEARCH 调 Retriever；OPEN 按 doc_id 从冻结 corpus 取内容；KEEP 只更新状态，不重新检索。
  • Observation Builder：从完整状态中裁剪“下一步决策需要的信息”，而不是把 State Store 原样塞回 prompt。
  • Trace/Reward Hook：记录 action 前后 state diff、response_id、合法性和成本，供离线审计与过程奖励使用。

Observation Builder 的裁剪原则

完整 State Store 可以保留全部历史用于 replay，但每轮只返回：当前问题、剩余预算、最近 SEARCH 结果的 doc_id/title/短摘要、当前 OPEN 内容、已 KEEP 证据目录和上一步错误。较早的无关候选、完整历史 tool response、gold 标注均不进入 observation。这样减少 token，同时保持决策所需的 Markov 信息尽可能完整。

2建立并冻结混合 RetrieverBM25 + Dense + RRF；先隔离检索变量已完成

方案

BM25 负责词项精确匹配，Dense 负责语义召回，RRF 融合两个排序；索引和权重在 SFT/RL 期间冻结。

LRAT 实验

参考 LRAT 用 agent trajectories 训练 Dense Retriever，但在本任务观察到负迁移。

项目结论

现成轨迹监督不必然适配当前 Policy 的 query/state 分布；不能把 Retriever 与 Policy 同时改动后只看最终答案。

解决问题

冻结 Retriever 后，后续 GRPO 的变化更能归因于 Policy 学习，而不是搜索引擎本身改变。

需要的对照

R0–R4 应覆盖 BM25、通用 Dense、混合检索、LRAT-style Dense 等，并报告 Recall@5/20/100、nDCG@10 与 end-to-end 指标。

面试表达

这是一个有价值的负结果：不是“LRAT 无效”，而是证明 agent trajectory supervision 存在任务与状态分布依赖，因此先解耦 Retriever 和 Policy 学习目标。

Retriever 与 Agent 的实际交互链

Policy 输出 SEARCH(query)→Harness 校验/去重/扣预算→Retriever HTTP API→BM25 Top-K+Dense Top-K→RRF 融合→候选写回 Evidence State→紧凑 observation

只有 SEARCH 会访问 Retriever。OPEN 使用检索结果里的稳定 doc_id 从 corpus store 读取句子；KEEP 只是把已打开句子写入 Evidence State；ANSWER 读取 kept evidence 生成带引用答案。这一拆分保证 Retriever 不负责“决定证据”，Policy 也不能绕过 Harness 直接访问索引。

混合排序怎么做

两个 Retriever 返回不同排序
query = "人物丙 机构乙 负责人"

BM25 ranks:
  1. d_3c20  机构乙
  2. d_71ab  人物丙

Dense ranks:
  1. d_71ab  人物丙
  2. d_3c20  机构乙
RRF 只依赖 rank，减少分数尺度问题
RRF(d) = Σ_r 1 / (k + rank_r(d))

score(d_3c20) = 1/(k+1) + 1/(k+2)
score(d_71ab) = 1/(k+2) + 1/(k+1)

固定 k、Top-K、tie-break 与随机种子，
相同 query + 相同 index 必须得到相同结果。

3开放轨迹 SFT：建立可达策略支持先学会合法操作，再进入 RL已验证

输入

包含 SEARCH / OPEN / KEEP / ANSWER 的开放搜索轨迹，以及 Harness 返回的真实状态 observation。

学习目标

学习动作语法、何时检索、如何打开与保留证据、如何在 ANSWER 中引用，不以最终 benchmark SOTA 为首要目标。

已有结果

轨迹完成率 96%，非法引用率 1.62%；说明外置证据协议对 Policy 是可学习的。

解决问题

没有 SFT 支持时，早期 RL 会被 JSON 错误、非法引用和不完成 ANSWER 淹没，终局奖励几乎不可用。

与 OPD 研究的共同 insight

SFT 先把目标行为带入 Student/Policy 的可达分布；on-policy 监督再在模型自身访问的状态上修正。弱初始化直接做 OPD/GRPO 往往得不到稳定能力增益。

门控

只有完成率、联合合法率、引用合法率达到预设门槛，才启动昂贵的 27B GRPO。

SFT 数据如何合成：公开轨迹不能直接拿来训练

训练集问题+公开/强 Teacher 搜索轨迹→在本项目 Harness 中 replay→动作与 doc_id 重映射→协议/引用过滤→按 turn 展开监督样本→动作 token loss mask
  1. 生成或收集种子轨迹：使用训练 split 的问题，让强 Teacher 或公开搜索 Agent 产生 SEARCH/OPEN/KEEP/ANSWER 轨迹；公开轨迹主要提供搜索意图与动作顺序，不直接信任其中的文档编号。
  2. Harness 重放：所有 SEARCH 必须重新查询当前冻结 Retriever；OPEN/KEEP 必须重映射到本项目 corpus 的 doc_id/sent_id，消除不同语料和工具协议造成的错位。
  3. 质量过滤：剔除泄漏 gold、无法完成 ANSWER、引用未 KEEP、状态不可重放或答案完全无支持的轨迹；保留动作多样性，避免 SFT 只学会固定搜索模板。
  4. 按交互展开：同一条 episode 可产生多个监督 interaction；每个 interaction 的输入是“此前合法对话 + 当前 Harness observation”，标签是下一个 assistant action。
  5. Loss mask：system、user、tool observation 和检索正文只参与前向上下文，不计入 loss；只监督 assistant 生成的 action/query/answer token。

进入 GRPO 的一句门控

只有当 held-out 严格 Harness 评测达到轨迹完成率 ≥95%、非法引用率 ≤2%，且答案质量不低于冻结 SFT 基线时，才允许启动 27B GRPO；当前 pre-RL 基线为完成率 96%、非法引用率 1.62%。

4在 Harness 中生成 on-policy 多轮轨迹AReaL 编排，vLLM rollout，冻结 Retriever 服务进行中

Rollout

每个 prompt 采样 G=4 条轨迹；示例配置为 8 prompts × 4 samples = 32 episodes，每条最多 16 轮交互。

框架

  • AReaL：RL 编排与训练
  • vLLM：高吞吐生成
  • FSDP：27B Actor 分布式更新
  • LoRA：低成本参数更新

版本约束

稳定性阶段保持严格同策略版本轨迹，不跨版本预取；否则 rollout staleness 会干扰小步实验判断。

解决问题

让训练数据来自当前 Policy 的真实错误状态，而不是固定 Teacher 轨迹；这正是 on-policy 后训练的价值。

系统结构

Actor：8×A800 FSDP DP8；Rollout：H800 vLLM TP4；Retriever：独立冻结 HTTP 服务。三者分离，避免 rollout worker 重复加载 Dense 模型与索引。

工程风险

多轮 episode 展开成不等长 action sequences，可能导致跨 rank micro-batch 数不可行；冷启动、checkpoint recovery 和异常 teardown 也必须纳入实验吞吐评估。

Rollout prompt 从哪里来

一个 rollout prompt 由三部分动态拼成，而不是从 SFT 文件中复制完整答案轨迹：

  1. 固定 System Protocol：人工定义动作 schema、合法性约束、引用规则、预算含义和“只输出一个 JSON action”。同一实验配置中保持冻结。
  2. Question：从 RL train split 采样原始问题文本；同一个 question 复制为 G=4 个 group members，以相同初始状态、不同采样随机性生成四条轨迹。
  3. Current Observation：每轮由 Observation Builder 根据最新 Evidence State 生成，包括剩余预算、候选目录、当前打开句子、已 KEEP 证据与上一步错误；它随工具动作动态变化。
绝不能进入 prompt：gold answer、gold supporting facts、目标 doc_id/sent_id，以及只供 reward 使用的 evidence stage。它们与 prompt 通过 question_id 在服务端 sidecar 对齐。

G=4 的组是怎么形成的

prompt q_001 + empty_state + policy_version v_k
  ├─ rollout 0: SEARCH("机构乙 负责人") → ... → ANSWER
  ├─ rollout 1: SEARCH("研究者 导师")   → ... → ANSWER
  ├─ rollout 2: SEARCH("人物丙 履历")   → ... → invalid/repair → ANSWER
  └─ rollout 3: SEARCH("机构乙 人物丙") → ... → ANSWER

四条轨迹共享 question_id 和 gold sidecar，但各自拥有独立 session_id、Evidence State、预算和 action 序列。

轨迹结束条件包括合法 ANSWER、达到最大 16 轮、预算耗尽后仍无法回答、连续不可恢复协议错误。每次 assistant response 都保留 token ids、old log-prob、response_id、policy version 和对应 state diff，供后续 recompute 与训练对齐。

5把 Evidence State 变化转成 ABC 式过程奖励失败轨迹中的正确搜索前缀也能得到信用进行中

参考

ABSeeker 的 Answer-Backtracked Credit Assignment：从答案回溯线索，并对有用步骤做细粒度评分。

本项目适配

数据已有 gold supporting facts，因此首版不调用 LLM judge，直接在 SearchState 中确定性匹配每条 evidence 的阶段。

阶段势能

未出现 0.0；SEARCH 首次召回 0.1；OPEN 首次展示 0.3；KEEP 首次保留 1.0。

Φ(sₜ)=mean_g stage_score(g,sₜ)
r_process,t=α·[Φ(sₜ₊₁)−Φ(sₜ)]

防刷约束

重复动作过程分为 0；不因“格式合法”给正奖励；正向证据奖励与非法动作惩罚分别限幅。

解决的两个稀疏性问题

  • 最终答案失败，不再意味着此前所有 SEARCH/OPEN/KEEP 都获得相同负信号。
  • 同一个问题的四条 rollout 终局奖励完全相同时，局部 evidence 增量仍可提供非零训练信号。

理论注意

这是受 ABC 启发的任务特定 reward shaping。加入裁剪、局部优势和协议惩罚后，不能直接宣称满足经典 potential-based shaping 的策略不变性；必须靠消融验证是否改变了最优行为。

第一步：把 gold supporting facts 对齐到 Evidence State

数据预处理阶段已经把每条 supporting fact 映射成稳定的 (doc_id, sent_id)。rollout 时 scorer 不读取模型文字中的“我找到了证据”，而是检查 Harness 的真实状态集合：

  • SEARCH covered：该 gold sentence 所属 doc/chunk 首次出现在 Retriever 返回的 candidates 中。
  • OPEN covered：该 gold sentence 首次包含在 OPEN tool response 中，意味着 Policy 实际看到了它。
  • KEEP covered：Policy 合法执行 KEEP(doc_id, sent_id)，该句首次进入 kept_evidence。

对每条 gold evidence 只记录到达过的最高阶段，阶段单调不减；重新搜索相同文档、重复 OPEN 或重复 KEEP 都不会再次得分。

第二步：完整数值例子（两条 gold evidence，α=0.25）

动作证据 A 阶段证据 B 阶段Φ(s)ΔΦr_process
初始未见 0.0未见 0.00.000—0
SEARCH 命中 ASEARCH 0.1未见 0.0(0.1+0)/2 = 0.050+0.050+0.0125
OPEN AOPEN 0.3未见 0.00.150+0.100+0.0250
KEEP AKEEP 1.0未见 0.00.500+0.350+0.0875
SEARCH 命中 BKEEP 1.0SEARCH 0.10.550+0.050+0.0125
OPEN BKEEP 1.0OPEN 0.30.650+0.100+0.0250
KEEP BKEEP 1.0KEEP 1.01.000+0.350+0.0875

整条轨迹把全部 gold evidence 从未见推进到 KEEP 时，正过程奖励累计正好为 α=0.25，因此天然满足首版 +0.25 上限。可恢复非法动作的负过程奖励单独累计并限制到 −0.10，避免一次早期错误吃掉后续纠错获得的正信用。

第三步：奖励究竟写到哪个 interaction

状态与动作审计记录
{
  "response_id": "resp_open_A",
  "action": {"type":"OPEN","doc_id":"d_91af…"},
  "phi_before": 0.05,
  "phi_after": 0.15,
  "process_reward": 0.025,
  "new_gold_stage": ["A: SEARCH→OPEN"]
}
进入训练的数据语义
episode_reward     = terminal quality score
episode_advantage  = group_normalize(episode_reward)
process_reward_t   = 0.025
training_advantage = episode_advantage
                   + beta * process_reward_t

loss_mask = assistant OPEN action tokens only

reward 归因给产生状态变化的 assistant action，而不是随后由环境返回的 tool text。tool observation 没有可训练 token；actor 对该 action 的生成 token 做 sequence mean，再乘该 interaction 的 training advantage。

第四步：为什么终局全失败时仍有信号

同一 prompt 的四条轨迹 terminal reward 都为 -1：
  group mean = -1, group std ≈ 0
  A_episode = [0, 0, 0, 0]

但轨迹 2 曾正确 SEARCH→OPEN→KEEP 证据 A：
  A_step(SEARCH_A) = beta * 0.0125
  A_step(OPEN_A)   = beta * 0.0250
  A_step(KEEP_A)   = beta * 0.0875
  A_step(错误 ANSWER) 仍受显著终局协议/质量惩罚约束

这不会把失败轨迹整体变成成功轨迹，而是把“正确前缀”和“最终错误动作”拆开。β 必须较小，保证终局答案质量仍主导策略排序。

标注不完整时的风险与处理

  • 真实有用证据若不在 gold supporting facts 中，会得到 0 而不是正奖励；因此不能对“未命中 gold”直接给负奖励。
  • gold 映射失败样本应关闭 evidence process reward，只保留 terminal reward，不能按零覆盖训练。
  • 阶段权重 0.1/0.3/1.0、α、β 与裁剪必须做消融；否则提升可能只是 KEEP 偏好变强，而不是搜索能力提高。
  • ABC 稳定后可把 TRACE 作为可选对照，用参考模型答案 log-prob 的状态增量覆盖未标注但有用的证据，同时报告额外 forward 成本。
6合成 GRPO 训练优势并更新 27B Teacher终局质量保持主导，过程信用只修正局部动作进行中

终局奖励

R = 2.0·AnswerF1 + 0.8·SupportRecall
+ 0.4·CitationPrecision − 0.15·DuplicateRate
− ProtocolPenalty

组内优势

A_episode,j=(R_j−mean_group)/(std_group+ε)

只对同 prompt 的终局奖励做组内归一化。

局部训练优势

A_j,t=A_episode,j + β·clip(r_process,j,t,−c,c)

终局质量给轨迹排序，过程分在 interaction 层定位有用动作。

成本课程

只有 AnswerF1≥0.8 的质量达标轨迹才施加 SEARCH/OPEN/token 成本，避免“不搜索、早回答”的 reward hacking。

AReaL 接入关键点

默认 grouped rollout 逻辑可能把最后一个 interaction 的归一化 reward 覆盖到整条轨迹。项目需要显式拆分 episode_reward / process_reward / training_advantage，否则“逐步奖励”只存在于日志而没有进入梯度。

Loss 语义

只对模型生成动作 token 计算 loss；先在单个 action 内做 sequence mean，再对 actions 求均值。这样更长的 query 或 JSON 不会天然获得更大梯度权重，也不对检索文档与 tool response 反向传播。

7用 OPD² 蒸馏 Search RL policy shift把 27B Teacher 的强化学习增量迁移到 9B Student计划

参考

OPD² 不直接拟合 Teacher 完整分布，而用 Teacher 与其 base model 的 log-prob 差提取后训练带来的 delta signal。

本项目假设

Δ_search,t = log π_post-GRPO(yₜ|sₜ)
− log π_pre-GRPO(yₜ|sₜ)

把原论文的 reasoning-tuning shift 迁移为 Search-RL shift。

On-policy 状态

让 9B Student 在同一 Harness 中访问自己的状态分布，再由 pre/post Teacher 对这些 token 打分，减少只在 Teacher 轨迹上蒸馏的 exposure bias。

解决问题

避免 Student 无差别复制 27B Teacher 的基础知识、表达风格和已有 SFT 分布，聚焦迁移 GRPO 新学到的搜索动作偏好。

必须做的等预算对照

9B SFT、标准 OPD、OPD²，保持数据量、rollout token、训练步数和推理预算一致；否则无法区分 delta signal、额外训练算力和更长输出的贡献。

主要风险

Student 状态可能远离 Teacher 的有效支持；固定 delta 可能在 Student 已学会后仍持续推动；需要方向一致性门控、KL/anchor 或动态缩放，并审计输出长度、循环率与截断率。

8分层门控、消融和外部评测证明“哪一层真正带来增益”部分完成

Agent 指标

ANSWER 完成率、联合合法率、Answer F1、Supporting Recall、Citation Precision、重复率、平均工具轮数与搜索成本。

RL 健康度

全同 reward group 比例、非零 process reward 比例、分动作优势、KL、entropy、gradient norm、长度分布与 step wall time。

关键消融

  • SFT vs terminal-only GRPO vs ABC-GRPO
  • 冻结 RRF vs LRAT-style Retriever
  • 9B SFT vs OPD vs OPD²

外部评测

多跳 QA、BrowseComp-Plus、中文零样本；测试题不得进入 Retriever/Policy 训练。

停止条件

合法率或 ANSWER 完成率持续下降；局部奖励主要来自重复/无效操作；ABC 未减少全同 reward group；成本下降但答案质量倒退；OPD² 只增加长度而没有 matched-compute 增益。

最终要回答的研究问题

外置 Evidence State 是否不仅让 Agent 更可控，还能成为有效的 credit-assignment substrate，并把这种 Search RL 增量迁移到更小模型？

06 · PAPER MAP

参考论文地图：借鉴了什么，又改了什么

每张卡片区分“论文原本解决的问题”和“EviSearch-RL 的使用方式”，避免把参考方法误说成自己的原创。

SEARCH RL BASELINE

Search-R1

用纯 RL 训练 LLM 在推理中自主发起多轮搜索，并对检索 token 做 masking，主要依赖 outcome reward。

本项目借鉴：多轮 search rollout 与端到端 RL。
本项目增加：外置 Evidence State、引用协议与逐步信用分配。

SEARCH RL BASELINE

ReSearch

将 search 操作嵌入 reasoning chain，用 RL 学习何时搜、搜什么，并观察反思与自纠错行为。

本项目借鉴：reasoning-search interleaving。
本项目不同：Policy 不机械维护完整历史，证据由 Harness 管理。

LONG-HORIZON CREDIT

ABSeeker / ABC

从答案回溯必要线索，对长程搜索中的有用步骤分配细粒度信用，包括失败轨迹中的有效动作。

本项目借鉴：Answer-Backtracked Credit Assignment。
本项目适配：利用 gold supporting facts 与 Evidence State 做确定性阶段势能，不依赖 LLM judge。

OPTIONAL CREDIT SIGNAL

TRACE

用冻结参考模型评估 gold answer 在相邻状态下的 log-prob 变化，形成 turn-level TD reward。

本项目定位：ABC 稳定后再做可选增强，用于覆盖“有帮助但未标成 gold evidence”的文档；代价是每个状态都要额外 scoring。

AGENT-AWARE RETRIEVER

LRAT

从 Agent trajectory 中挖掘检索监督，利用浏览、拒绝与后续推理信号训练 Dense Retriever。

本项目结果：在当前语料与 Policy 状态分布上观察到负迁移，形成“先冻结 Retriever、独立优化 Policy”的实验结论。

ON-POLICY DISTILLATION

GKD / Original OPD

让 Student 在自身生成的序列上接受 Teacher token-level 监督，缓解静态 Teacher 数据与 Student 推理分布不匹配。

本项目借鉴：9B Student 自己在 Harness 中访问状态，再由 Teacher 提供稠密监督。

DELTA DISTILLATION

OPD²

使用 Teacher 与其 base model 的 log-prob 差，显式提取后训练带来的能力增量，而非完整模仿 Teacher 分布。

本项目假设：把差分改为 post-GRPO − pre-GRPO，蒸馏 Search RL policy shift；该部分尚待实验验证。

DISTRIBUTED RL SYSTEM

AReaL

解耦生成和训练，提供大规模异步 RL 系统与 Agentic RL 接入能力。

本项目使用：多机 rollout、FSDP Actor、权重同步。
项目侧工作：保证 grouped rollout 不覆盖 interaction-level credit。

07 · NOVELTY BOUNDARY

项目真正的创新与不能夸大的部分

可以作为项目贡献讲

  • 把外置 Evidence State 同时用于上下文压缩、协议验证、轨迹回放和 reward instrumentation。
  • 把 SEARCH / OPEN / KEEP 的证据阶段变化转换为确定性的局部 credit，并接入 grouped GRPO。
  • 识别 AReaL 终局 group normalization 与 interaction reward 的语义冲突，并设计 episode/process/advantage 拆分。
  • 通过 LRAT-style 负迁移实验，验证 Retriever trajectory supervision 的分布依赖。
  • 提出用 OPD² 蒸馏 Search RL policy shift 的实验假设，并设计同预算验证矩阵。

不能当成原创讲

  • “用 Harness 做 Agent 后训练”本身已是常见 Agentic RL 范式。
  • 多轮搜索 RL 来自 Search-R1 / ReSearch 等工作。
  • ABC、TRACE、LRAT、GRPO、OPD² 和 AReaL 都是参考论文或现有框架。
  • 当前只能说 Harness+SFT 已验证；GRPO 的独立增益和 OPD² 的 Search 迁移效果尚未最终证明。
  • 32 条 episode 的单步诊断不能替代多 seed、held-out 和 matched-budget 评测。
08 · INTERVIEW NARRATIVE

面试时用三分钟讲清楚

“我研究的是可验证 Search Harness 如何为长程后训练提供更好的学习信号。首先，我把候选文档、已打开句子和确认依据移出对话历史，用 Evidence State 机械维护，并要求答案只能引用 KEEP 证据。这样 Harness 不只减少上下文，还能记录每个 SEARCH、OPEN、KEEP 引起的证据状态变化。其次，我先用开放轨迹 SFT 让模型学会协议，完成率达到 96%，再把状态变化转成 ABC 式过程奖励，与 GRPO 的终局组优势组合，解决失败轨迹有效前缀无信用和同组终局同分时优势归零的问题。最后，我计划参考 OPD²，用 27B Teacher 在 GRPO 前后的 log-prob 差提取 Search RL policy shift，在 9B Student 自己访问的 Harness 状态上进行逐 token 蒸馏。核心假设是：结构化、可验证的外置状态不仅让 Agent 更可控，也能成为长程信用分配和能力迁移的基础。”
  1. 先讲问题：上下文膨胀、证据不可控、终局奖励稀疏。
  2. 再讲机制：Evidence State → state transition → process reward → GRPO。
  3. 给证据：Harness+SFT 已验证；Retriever 负迁移结论；GRPO/OPD² 明确标为进行中与计划。
  4. 最后讲研究问题：这种 credit substrate 是否真正改善终局质量与样本效率，并能否迁移给小模型。
