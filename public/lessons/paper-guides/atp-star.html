AtP*: Efficient and Scalable Localization

Kramár et al.，Google DeepMind，2024｜用 2 次前向 + 1 次反向近似全量 Activation Patching，并专门修复 softmax 饱和与路径抵消造成的漏检。

1. 三层方法关系

Activation Patching：可信但 O(N)→AtP：一阶近似、O(1) passes→AtP*：修两类假阴性

这里的“因果”是模型内部干预意义：固定输入和其余计算，把某节点激活替换为 counterfactual 值，看目标 metric 改变多少。它不等于现实世界业务因果。

2. 核心公式

准备成对输入 xclean 与 xnoise，其目标行为不同。节点 n 的 clean/noise 激活分别为 nc,nn。

真实 Activation Patching：

IAP(n) = L(M(xclean | do(n←nnoise))) − L(M(xclean))

每个节点都要重新跑下游，N 个节点约 N 次前向。

Attribution Patching（AtP）：

ÎAtP(n) = (nnoise−nclean)ᵀ · ∇nL(M(xclean))

这就是 patch 方向 δn 与 metric 梯度的点积，即一阶 Taylor。一次 noise forward 缓存 counterfactual，一次 clean forward + backward 得到所有节点分数。

3. Vanilla AtP 的两类致命漏检

① Q/K softmax 饱和

Attention 概率接近 0/1 时，对 Q/K 的局部梯度接近 0，但把 Q/K 换成 noise 值可能让注意力模式大变。AtP 给低分，真实 patch 影响很大。

② 直接/间接路径抵消

同一节点到输出有多条路径，反传梯度可能正负相抵，最终点积接近 0；真实非线性 patch 却仍有显著作用，形成假阴性。

4. AtP* 的两个修复

QK fix：softmax 这一步不再线性化

对 Q/K patch，显式重算 patch 前后的 attention pattern 差 ΔA，然后只对更下游部分使用梯度：

ÎQK-fix(n) = [Apatched(n) − Aclean]ᵀ · ∂L/∂A

它越过 softmax 饱和区，论文称额外计算低于约两次完整 Transformer forward（只重算注意力相关部分）。

GradDrop：逐层切断梯度路径，暴露被抵消贡献

对每层 ℓ，把该层残差贡献处的梯度置零，再为所有上游节点算一份 AtP。不同 drop 破坏不同抵消组合，最后按多个估计的幅值聚合：

ÎGD(n) = aggregateℓ | (nn−nc)ᵀ · ∇n(drop ℓ)L |

代价约 L 次 backward（可复用前向激活），所以保留“与节点数无关”的扩展性，但并非免费。

5. 证据与论文主张

系统校准

论文不是只展示漂亮 circuit，而是把 AtP/AtP* 排名与真实 Activation Patching 效果逐节点比较，重点测“召回真正高影响节点所需验证成本”。

跨规模实验

包含 Pythia 410M、1B、2.8B、12B 等规模及多类成对 prompt/行为设置。QK fix 显著减少 query/key 漏检，GradDrop 能找回因路径抵消而漏掉的 attention/MLP 节点。

漏检风险估计

论文还提出随机子集 patch/统计检验思路，用于估计残余误差并约束仍有假阴性的概率；前提包括组合效应近似等，不能视为无条件保证。

最重要的工程结论：AtP* 仍被定位为 Activation Patching 的高召回预筛器，而不是替代真实 patch 的最终证据。

8. 边界/失败模式

  • 论文聚焦 Transformer LLM 节点；推荐稀疏特征、Cross、SENET 并非原验证对象。
  • 结论高度依赖 clean/noise 配对与 metric；counterfactual 不合理会得到无意义 circuit。
  • AtP/AtP* 仍是一阶近似，QK fix 只精确处理 softmax 这一步；下游非线性仍近似。
  • GradDrop 约 L 次 backward，层数或分支很多时成本明显。
  • 单节点方法可能漏掉只有联合 patch 才出现的冗余、自修复和交互。
  • 内部 patch 往往落在联合分布外，需要同桶配对、整组 patch 与实际指标验证。

9. Leader 尖锐问答

Q1：这和我们的 Shuffle 有什么本质区别？

Shuffle 用随机错误样本替换 activation；AtP 使用明确 clean/noise 成对 counterfactual，并先用 δ·grad 估计该 patch 的效果。AtP 更定向，Shuffle 更像总体依赖检验。

Q2：AtP 为什么比 Activation×Gradient 更适合冷启对比？

Activation×Gradient 默认方向常是 z→0；AtP 的方向可设为成熟 Base 激活与冷启/破坏激活的差，直接近似“把成熟内部状态换成冷启状态”的 metric 变化。

Q3：AtP* 是否已经解决梯度法不可靠？

没有。它针对 Q/K 饱和和路径抵消两类已知假阴性；大扰动下的其他非线性、交互与 OOD 仍存在，所以论文仍要求 Top 候选做真实 patch。

Q4：为什么不直接全量真实 patch？

N 个节点需约 N 次前向；复杂 Base 很快不可承受。AtP 用常数次 pass 扫全量，GradDrop 与层数相关，再把真实 patch 限定到 Top-K。

Q5：QK fix 能用于 HSTU 吗？

前提是 HSTU 内部确有可访问的 Q/K→attention pattern 计算，并能重算被 patch 的 pattern。如果实现是融合算子且 hook 不到，先对 attention 输出或 block 输出做普通 patch。

Q6：GradDrop 和多任务梯度冲突是一回事吗？

不是。GradDrop 处理同一 metric 的多路径梯度抵消；多任务冲突是不同 loss 梯度方向不同。Kai 上两者都可能发生，应分别报“分任务梯度”和“逐路径 drop”。

Q7：怎样选 clean/noise 才可信？

控制除目标因素外尽量相同：同用户/同场景难负例、相邻时间、同类 item；同时报告 activation 距离、特征分布与 baseline metric 差，避免 counterfactual 过远。

Q8：它能直接给出优化方案吗？

不能。它定位“哪条内部通路承载某行为”。后续才根据通路类型选择蒸馏、初始化、容量、归一化、特征或损失方案，并用训练实验归因。
