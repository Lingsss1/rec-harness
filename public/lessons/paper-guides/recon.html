架构级诊断

Recon

有些共享层不是“训练得不够好”，而是任务本身要求它往相反方向走。Recon 用层级梯度夹角找出这种位置，并把高冲突层拆成任务独享。

一句话冲突分数方法证据接入 Base复现成本边界Leader Q&A三篇对比

一句话讲给 Leader

Share-bottom 的目的，是让 CTR/CTCVR/PXR/PED 共用表示；但共享不是越多越好。Recon 逐层比较任务梯度方向，找到长期出现负余弦的层，再将这些层任务化。对当前 Base，它最适合回答：13,175→1,024 的 Share-bottom 与 HSTU，到底哪些位置不应该继续全任务共享？

它看什么同一层上任意任务对的梯度余弦相似度。
能诊断什么哪些共享层反复出现任务方向冲突，可能是负迁移源头。
动作是什么复制高冲突层为 task-specific，再从头训练修改后的架构。

核心诊断量：层级 S-conflict score

对共享层 k，任务 i、j 的梯度：

gᵢ(k) = ∇θ(k) Lᵢ cos φᵢⱼ(k) = [gᵢ(k) · gⱼ(k)] / [||gᵢ(k)||₂ ||gⱼ(k)||₂] 若 cos φᵢⱼ(k) < 0：两个任务在该层的一阶下降方向冲突

Recon 再设严重度阈值 −1 < S ≤ 0：

s_t(k) = #{(i,j) | i<j 且 cos φᵢⱼ(k) < S} s(k) = Σₜ₌₁ᴵ s_t(k)

S=0 统计所有负余弦；S=-0.1 只统计更严重冲突。对 T 个任务，每层每步最多有 C(T,2) 个冲突。

只看平均 cosine 容易掩盖问题：一次强负冲突可能被多次轻微正相似抵消。应同时报告 conflict rate、P10 cosine 与严重冲突计数。

方法：从“改梯度”转向“改共享关系”

1. 搜索阶段
训练 I 步，逐任务、逐共享层计算梯度。
→
2. 排层
累计 S-conflict score，选 top-K 高冲突层。
→
3. 拆层
为各任务复制这些层，其余层继续共享。
→
4. 重训
修改后网络从头训练，可搭配 joint/PCGrad/CAGrad。

理论直觉

把冲突坐标从共享参数空间拿走，相当于让每个任务在该子空间各自下降；剩余共享坐标上的梯度更容易对齐。论文在可微、足够小学习率及特定梯度条件下证明，一步更新后的总 loss 低于原共享模型。

拆分后：θ_fix ← θ_fix − α Σᵢ wᵢ gᵢ_fix θᵢ_conflict ← θᵢ_conflict − α gᵢ_conflict 原模型：θ_conflict ← θ_conflict − α Σᵢ wᵢ gᵢ_conflict

论文证据：架构冲突可迁移，但推荐证据为空

证据结果如何解读
Multi-Fashion+MNISTJoint-train + Recon 的平均相对指标从 −0.94% 到 −0.33%，参数体积 42.81→43.43 MB；PCGrad + Recon 达到 +0.04%。少量拆层可改善冲突，且不一定需要大幅增参。
CelebA 40 任务Joint-train 平均 error 8.33→8.22；参数 43.26→68.03 MB。任务多时收益存在，但增参可能显著。
跨方法稳定不同优化方法找到的冲突层排序差异小；作者只搜索一次再用于多种方法。层冲突可能更多来自架构/任务关系，而非具体梯度手术。
跨数据迁移同架构下，SegNet 在两个数据集有 38/40 冲突层一致；迁移层也能持续改善。存在可复用迹象，但仍是视觉架构证据。

当前 Kai V2 的具体映射

任务集合不要一步扩到全部

先用四个标签语义清晰、共同经过 Share-bottom/HSTU 的任务：CTCVR、CTR、PXR、PED。四任务每层每步只有 6 个 pair，容易解释。第二阶段再加 Global/Direct Pay、GMV、Reco；CID/CL/Interest 的 mask 与目标结构不同，宜单列。

务实改写：原论文是“复制整层”。对当前 Base，第一版应把 Recon 当作共享边界诊断器。诊断确认后，具体结构动作可以是 task adapter、MMoE/PLE、部分通道独享，而不必机械复制 13.5M 的大矩阵。

复现方案：先定位，再做可控结构实验

  1. 搜索数据：固定冷启动训练数据与随机种子，从第 0 步开始采样；同时可在成熟 Base 继续训练窗口上复测，判断冲突是早期还是长期存在。
  2. 采样：每 20–100 step 求一次 task-wise gradient；零梯度 pair 标为不可比较，不强行设 cosine=0。
  3. 报告：每层 × 任务对输出 conflict rate、P10/P50 cosine、S∈{0,−0.05,−0.1} 的排名稳定性。
  4. 选层：不直接用固定 K；在参数预算下选 Pareto 点，例如新增参数 ≤5%，并要求跨 seed 排名稳定。
  5. 结构验证：优先比较共享原版、top 冲突层 task-adapter、同参数量随机层 adapter。随机层对照是证明诊断有效性的关键。
  6. 重训：冷启动场景本来就从零训练，正好符合 Recon 的重训假设；同预算比较追平速度与最终指标。

工程成本与证据边界

阶段成本风险
搜索T 个任务梯度；每层 O(T²) pair cosine。论文明确指出任务多时明显慢于 joint training。十余任务有 45+ pair；需先缩任务集与降低采样频率。
结构修改原版复制 top-K 层，参数增加随任务数与被拆层大小增长。Share-bottom 单层约 13.5M，机械复制不可接受。
推理任务独立层会增加前向计算/显存；若只输出单一主任务，可裁掉无关分支。多目标同时 serving 时成本真实存在。
证据边界：Recon 的实验全部是视觉多任务，没有推荐、Sparse Embedding、HSTU 或流式训练证据。理论只保证特定条件下的一步总 loss，不保证长期收敛或线上核心指标。

汇报结论

Recon 对当前项目的价值，是把“是不是共享过度”变成可测量问题。我们先以四个核心任务扫描 Share-bottom/HSTU 的方向冲突；只有当 top 冲突位置稳定且优于随机层对照，才提出局部 adapter/专家化方案。
