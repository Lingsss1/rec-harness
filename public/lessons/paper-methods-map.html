汇报时只需要守住三句话

1
梯度只做粗筛，不直接决定扩容Activation × Gradient 是删除影响的一阶代理，需要扰动实验复核。
2
Shuffle 测的是当前 Base 的依赖，不是因果真理必须有 Top / Random / Bottom、重复试验和条件 Shuffle 对照。
3
第一阶段的价值是减少无效训练实验先证明诊断信号与真实扰动一致，再讨论自动产生优化方案。

Method chain

这些论文不是同一种方法，而是拼成一条诊断证据链

每一组论文回答一个不同问题：哪里可能重要、是否真的依赖、为什么共享层学不好，以及诊断能否转化为结构修改。

1

从成熟 Base 采样

冻结权重，用真实离线样本执行前向和反向。

不需要先重新训练 Base
2

梯度敏感性粗排

Taylor、MISO、TayFCS、AtP* 给所有候选模块低成本打分。

回答“先查哪里”
3

Shuffle / Patching

只扰动 Top、Random、Bottom 模块，比较 Loss、NE、AUC 变化。

回答“Base 是否真依赖”
4

多任务梯度诊断

MetaBalance 看范数，AdaTask 看长期支配，Recon 看方向冲突。

回答“为什么共享不好”
5

设计最小改动

拆分、扩容、裁剪或调权重，并用训练实验做最终归因。

诊断不是最终效果证明

梯度粗筛

\[S_i=\mathbb E\left[\left|a_i\frac{\partial L}{\partial a_i}\right|\right]\]

估计把激活 (a_i) 删除时，Loss 会发生多大局部变化。

Shuffle 验证

\[R_i=L(f(a_{-i},\pi(a_i)),y)-L(f(a),y)\]

保留数值集合，破坏“样本—激活”对应，测当前模型依赖。

任务冲突

\[C_{pq}=\frac{g_p^\top g_q}{\lVert g_p\rVert\lVert g_q\rVert}\]

长期为负说明两个任务倾向于把共享参数推向相反方向。

Evidence discipline

证据分级：我们现在能说到哪一步

这部分决定汇报是否可信。把“有理论基础”“在其他领域有效”“在当前模型有效”“能带来业务收益”严格分开。

Level 1

指标可计算能够从 Base 提取激活、梯度、归一化统计，并得到稳定数值。

Level 2

扰动一致Top 组的 Shuffle 影响稳定大于 Random 与 Bottom，跨 Batch、跨天方向一致。

Level 3

方向可操作诊断结果能明确区分扩容、拆分、裁剪、任务调权等候选方向。

Level 4

训练收益可归因按诊断修改后优于同预算随机改动或经验基线，并通过重复实验。

Level 5

线上业务收益通过线上 A/B 验证收益、成本与稳定性。当前探索尚未到这一层。

当前已有外部证据Taylor 重要性、Integrated Gradients、Permutation Importance 都有成熟理论；TayFCS 和 IR 神经元研究给出推荐/排序侧直接案例；MISO 给出工业组合案例。
当前尚缺内部证据还没有证明当前 Kai Base 的梯度排名能预测 Shuffle 影响，也没有证明按诊断扩容能提升冷启动模型。因此第一阶段结论应表述为“验证诊断信号”，而不是“用诊断直接提效”。
第一阶段成功标准

不是模型指标上涨，而是诊断具有区分度、稳定性和可复核性：高分模块显著强于随机/低分，任务冲突指标能跨样本窗口复现，并能提出少量清晰的后续实验。

Base experiment

落到当前 Kai v2 Base：先做最小可证伪实验

第一版只选两个 Hook：13,175d 最终特征拼接按语义组诊断，以及 HSTU 残差后的 1,024d 共享表示诊断。

1

冻结成熟 Base

使用离线样本，只前向/反向，不更新权重；按任务保留 CTR、CTCVR、PXR、PED Loss。

2

梯度全量粗筛

统计模块级 sum/mean Activation × Gradient，同时记录任务梯度范数和余弦相似度。

3

三组扰动

同样 K 值下执行 Top、Random、Bottom Shuffle，每组多随机种子，比较 NE/AUC/Loss。

4

判断是否继续

只有 Top 显著强于两组对照、且跨 Batch 稳定，才进入更大窗口和结构修改实验。

计算量估算器

梯度扫描200约 1 forward + 1 backward / Batch
模块级独立 Shuffle15,000Top-K × 重复 × 组 × Batch
成组 Shuffle 版本1,500每组一次扰动，成本约降 K 倍

推荐第一版先做“成组 Shuffle”验证排名是否有区分度；成立后再对 Top 模块逐个展开。时间窗口不是固定七天，关键是正样本数、分任务覆盖和置信区间。

Talk track

给 Leader 的简短汇报话术

建议控制在 60–90 秒

这周主要做了两部分工作。第一，围绕推荐模型内部诊断调研了 MISO、TayFCS 以及梯度归因、Shuffle 验证和多任务梯度冲突等相关方法。现有论文能够说明，梯度可以低成本筛选候选模块，扰动实验可以验证 Base 是否真实依赖，多任务梯度还可以进一步定位共享层中的任务支配和冲突。但 MISO 本身是单一工业案例，我们不会直接假设它对当前模型有效。第二，已经完成现有 Base 的主要结构梳理，下一步准备在成熟 Base 上冻结权重，先对最终特征拼接和 HSTU 后共享表示做梯度排名，再通过 Top、Random、Bottom Shuffle 验证信号。如果该信号稳定有效，再据此设计少量结构或训练实验，目标是减少依赖经验的大量试错。
  • 不要说“这套方法已经能提升模型”，说“先验证是否能提高定位效率”。
  • 不要说“梯度高就扩容”，说“梯度只负责缩小候选，最终由扰动与训练实验确认”。
  • 不要把 Agent 当主线；主线是推荐 Base 的诊断提效，LLM 只在后续帮助理解代码和检索方案。
