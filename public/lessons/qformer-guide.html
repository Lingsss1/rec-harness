1. 先用一句话建立直觉

Q-Former 是冻结图像编码器与冻结大语言模型之间的可训练适配器：它用少量可学习 Query 主动从大量视觉 patch 中“查询”与语言最相关的信息，再压缩为固定长度的视觉前缀。

01

对齐

让视觉信息在训练中靠近对应文本语义，而不只是保留像素层细节。

02

压缩

无论 ViT 产生多少 patch token，都输出固定数量 Query 表征，控制送入 LLM 的长度。

03

适配

用 FC 将 Q-Former 的隐藏维度投影到 LLM embedding 维度，作为 soft visual prompt。

最重要的概念边界Query Token 不是图像里的 32 个真实物体，也不是挑出 32 个原始 patch。它们是 32 个共享、可学习的参数槽位；看到具体图像后，通过 Cross-Attention 变成图像条件化的 32 个输出。

3. Cross-Attention 中 Q、K、V 从哪里来？

名字 Q-Former 的核心就是“查询”：当前层的 Query 隐状态做 Q；冻结视觉编码器输出的全部 patch features 做 K 和 V。WQ、WK、WV 是层内共享参数，不是每个位置各学一套。

Q = Hquery WQ　　　K = Zvision WK　　　V = Zvision WV
A = softmax(QKᵀ / √dk + Mvision)
H′query = AV
ViT 输出Zvision: [B, Nᵥ, Dᵥ]

例如 ViT-L/14 可产生 257×1024 的视觉特征。

→
32 个 QueryHquery: [B, 32, 768]

训练前是共享参数，按 batch 扩展。

→
固定长度输出Z: [B, 32, 768]

每个输出是对全部视觉 token 的加权汇总。

同一 Query 怎么“看”图像？

它与所有 patch 的 Key 计算相似度，softmax 后得到权重，再对 Value 加权求和。不同 Query 可以形成不同注意力分布。

每个 Query 固定负责一个物体吗？

没有这种硬约束。某些 Query 可能偏向物体、关系或场景，但语义通常是分布式且会重叠，需用 attention map 实证，而不能只凭编号命名。

原始论文中，Cross-Attention 插在每隔一个 Transformer block 中；Query 之间还会通过共享的 Self-Attention 交换信息。因此它不是一次单独的池化，而是多层、迭代式的信息提取。

4. 三种 Attention Mask 到底遮住什么？

这里最容易误解：论文中的三种 Mask 主要控制 Query Token 与 Text Token 在 Q-Former Self-Attention 中能否互相看见，不是把 Query 到图像 patch 的 Cross-Attention 关掉。

允许关注屏蔽仅历史可见
Image-Text Contrastive

Query 与文本完全隔离

Query 只从图像提取视觉表示；文本独立编码。这样两侧不能提前交换答案，随后才能用相似度做可信的对比学习。

业务意义像双塔召回：图像和文本可分别编码，再比较是否语义接近。
矩阵如何读行表示“谁在发起查询”，列表示“它能看谁”。示意图只画 3 个 Query 与 3 个文本 token；真实模型是 32 个 Query 和一段完整文本。

5. 第一阶段的三个目标，各自逼它学什么？

ITC

Image-Text Contrastive

目标：正确图文对更近，错误配对更远。

s(I,T)=maxj∈queries cos(zjI, tCLS) / τ

32 个 Query 分别与文本 CLS 比较，取最高相似度，允许不同 Query 捕捉不同对齐线索。

ITM

Image-Text Matching

目标：判断图文是否真的匹配。

p(match | I,T)
= meanj Head(zj)

Query 与文本双向交互；对每个 Query 做二分类，再平均。训练还采用 hard negative mining。

ITG

Image-grounded Generation

目标：只靠 Query 搬运的视觉信息逐词生成文本。

LITG=−Σk log p(tk|t<k,Q(I))

Query 看不到文本，文本能看全部 Query 与过去文本，迫使视觉信息先进入 Query。

Lstage 1 = LITC + LITM + LITG
三个目标为什么要一起用？ITC 擅长全局对齐，ITM 强化细粒度融合，ITG 检验视觉信息是否足以支持语言生成。它们共享参数，却用不同 Mask 改变信息流，形成互补约束。

6. 为什么必须先对齐，再接 LLM？

阶段 1：从冻结 ViT 学“语言相关的视觉表示”

使用图文对训练 Q-Former，联合 ITC、ITM、ITG。此时 Q-Former 先学会忽略与文字无关的视觉噪声，并建立图文语义对齐。

阶段 2：把 32 个输出翻译成 LLM embedding

增加可训练 FC：[B,32,768] → [B,32,D_LLM]，然后把它们放到文本 embedding 前面，成为 soft visual prompts。

冻结 LLM，用生成损失训练桥接模块

LLM 负责语言生成，但只更新 Q-Former 与 FC。它们逐渐学会生成一种 LLM 已能“读懂”的连续向量前缀。

Einput = Concat(FC(Zquery), Embed(prompt))
Lstage 2 = −Σk log pfrozen LLM(tk | Einput, t<k)
为什么不只做阶段 2？论文消融显示，没有第一阶段的表征学习，Q-Former 仅靠生成目标跨越模态鸿沟时，零样本 VQA 明显变差；作者还观察到 OPT 训练中的灾难性遗忘现象。第一阶段是在降低第二阶段的对齐难度。

8. 它和 Pooling、普通 Cross-Attention 有什么不同？

方法输出长度是否由可学习查询主动取信息是否专门做图文对齐预训练主要特点
Mean / Max Pooling通常 1 个向量否否便宜，但容易把关键局部信息平均掉
一次 Cross-Attention由 Query 数决定是不一定完成一次条件聚合，能力取决于 Query 与训练目标
Q-Former固定 32 个是，多层迭代是：ITC + ITM + ITG既是压缩器，也是经过两阶段训练的模态桥
与推荐模型 Target Attention 的类比Target Attention 通常用候选商品作 Query，从用户行为序列取回“与当前候选相关”的兴趣；Q-Former 用共享的 Learnable Queries，从图像 patch 取回“对语言任务有用”的视觉信息。两者都是条件聚合，但 Query 来源和训练目标不同。

9. 面试与学习中的高频追问

Q1：为什么恰好是 32 个 Query？
32 是 BLIP-2 实验采用的超参数，不是理论最优值。更多 Query 提高视觉容量，也会增加 Q-Former 与 LLM 的计算；更少则强化压缩但可能丢细节。实际应根据任务、分辨率、LLM 成本做消融。
Q2：Query Token 是每张图都重新学习的吗？
不是。训练维护同一组 [1,32,768] 参数，前向时扩展到 batch。参数在所有图片间共享；经过 Cross-Attention 后的输出才随每张图变化。
Q3：WQ、WK、WV 是每个 patch / Query 位置各一套吗？
不是。同一个 attention layer 的投影矩阵在位置之间共享；不同层、不同 head 有各自参数。位置差异来自输入表征与位置编码，而不是每个位置单独存一套 W。
Q4：Query 和文本能否互相看见？
取决于训练目标：ITC 互相隔离；ITM 双向可见；ITG 中 Query 看不到文本，而每个文本 token 能看全部 Query 和此前文本。
Q5：32 个 Query 最后是相加还是 Concat 到 LLM？
不是把 32 个向量相加成 1 个。它们经过 FC 后仍保留 32 个 token，在序列维度上放到文本 embedding 前，即 [visual token 1…32, text token 1…T]。
Q6：LLM 冻结后，怎么学会看图？
LLM 本身并未新增视觉能力参数；Q-Former 与 FC 学会把图像编码成 LLM 已能响应的连续 embedding 前缀。生成损失经过冻结 LLM 反传，以更新桥接模块。
Q7：为什么不是简单 Mean Pooling？
Mean Pooling 对所有 patch 使用固定均匀权重，只产生单一摘要。多个 Query 能学习不同的条件注意力分布，并通过多层 Self/Cross-Attention 协同提取多类信息。
Q8：Q-Former 等于一个完整多模态 LLM 吗？
不等于。它是视觉与语言模型之间的桥接模块。BLIP-2 的整体能力来自冻结视觉编码器、Q-Former/FC 和冻结 LLM 三者组合。
Q9：视觉 mask 和三种 self-attention mask 是同一个吗？
不是。encoder_attention_mask 告诉 Cross-Attention 哪些视觉位置有效；ITC/ITM/ITG 的 mask 控制 Q-Former 内 Query/Text 的自注意力可见关系。
Q10：它的主要局限是什么？
固定数量 Query 是信息瓶颈：它提高效率，也可能损失 OCR、小目标和密集空间细节。并且原始共享 Query 不直接由用户指令生成，对“应该看哪里”的任务条件利用有限。
