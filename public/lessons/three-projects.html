1

RecHarness：有限试验预算下的推荐模型长程优化

核心贡献不是“LLM 会改代码”，而是把方向分配、代码生成、验证晋升和跨轮记忆拆开。

一句话：Bandit 决定“下一轮把预算投向哪里”，LLM + Experiment Skill 决定“在该方向内具体怎么改”，验证指标决定“候选能否晋升”，Memory 决定“失败是否会被下一轮真正消费”。

1.1 为什么需要 Harness

单轮能力已经具备

Agent 能完成读资料、改代码、提交训练、查看指标；真正瓶颈变成跨几十个版本时如何避免反复试错。

试验昂贵且反馈慢

每个 trial 都消耗训练和验证预算，工业单轮反馈可能以天计，自由搜索的错误探索成本很高。

失败需要结构化归因

持平可能来自方向错误，也可能来自特征未接入、编号混淆或实现偏差；若不先验证有效性，Memory 会沉淀错误结论。

1.2 三层结构与闭环

Level 1 · Human Context人定义目标、验证指标、编辑方向、预算与上线风险。保留路径切换和副作用授权。
Level 2 · Bandit Router按历史成功/失败更新 arm 后验，用 Thompson Sampling 分配有限 trial。
Level 3 · Skill + LLM在被选方向内读取 incumbent、执行日志、成功经验和 avoid rules，提出假设与代码 patch。
Human Context→Bandit 选 arm→LLM 生成候选→训练与验证→Promotion / Reject→Memory + 后验更新→下一轮
θₐ ~ Beta(αₐ, βₐ)；每轮采样各 arm 的 θ̃ₐ，选择 Top-G 并行试验。
trial success = 可执行 ∧ 组内标准化增益 > 0 ∧ 不低于历史 incumbent。

工业迭代应沉淀的五条规则

1. 有效性先于解释性

先证明特征接入和代码路径生效，再看梯度、权重或指标变化。

2. 变体簇才能证伪方向

单个版本失败只能否定该实现；多个正交变体一致失败，才支持方向级结论。

3. 模块名不等于作用对象

HSTU 存在不代表原始序列 item-item 交互已被覆盖。

4. Memory 必须在环

误判和失败规则需在下一轮被读取并改变动作，否则只是事后文档。

5. 人保留关键授权

Agent 适合路径延伸；结构切换、昂贵实验和上线决策仍需人工判断。

不是给 Search Agent 套一个工具壳，而是让 Harness 的状态变化直接进入训练信用。

2.1 Harness 为什么是训练接口

Environment

维护 Evidence State、合法动作、预算、引用不变量和可回放 trace。

Policy

只观察当前决策所需状态，生成 SEARCH / OPEN / KEEP / ANSWER，不接触 gold answer。

Learner

读取终局质量与 state diff，把状态转移归因给产生它的 assistant action。

SEARCH 召回候选→OPEN 读取句子→KEEP 写入证据→ANSWER 只引用 KEEP
三个机械不变量：未 OPEN 的文档不能 KEEP；ANSWER 不能引用未 KEEP 的证据；重复 query 短路且不重复消耗 Retriever 预算。

阶段数据从哪里来如何构造这一阶段学什么计数单位
0. 开放轨迹冷启动OpenSeeker-v1 11,677 条；OpenResearcher 12,000 个 8K window。统一转成 chat template，长样本切 window 后 packing；仅 assistant token 参与 loss。先获得通用搜索、工具调用与长上下文行为，减少从纯 Base 学协议的难度。source record / packed window
1. Protocol GoldRL-train 的 3 个数据集，各取前 500 个问题；总计 1,500 个。held-out 不参与。SEARCH(query=question)；把 gold 文档构造成候选；对每个有效 gold doc 依次 OPEN→KEEP；最后 ANSWER。每个决策点单独写成一条监督记录。JSON schema、SEARCH→OPEN→KEEP→ANSWER 顺序，以及“引用来自已保留证据”的理想路径。1,500 个 episode skeleton；展开后是更多 interaction
2. Frozen-R4 Recovery同一 RL-train 中每个数据集 offset=500 后再取 500 个，与 Protocol 题目区间错开。SEARCH 必须走冻结 R4，取 top-5 并最多 OPEN top-4；显式加入重复 SEARCH、重复 OPEN、打开无关文档后继续 OPEN，以及召回到 gold 时 KEEP 等状态。理想路径之外的恢复：重复请求、无关召回、预算变化和真实 doc_id/sent_id。目标 1,500 个 recovery episode；按状态展开 interaction
3. Legal-space + Balance以上一阶段的 recovery interaction 为输入。按当前 state、opened_doc_ids、remaining_turns、last_tool_result 重新计算 legal_action_space；固定 seed=36 分层抽样。让训练时可选动作与推理时 Harness 完全同构，并抑制动作分布塌缩。SEARCH 750 + OPEN 1,500 + KEEP 1,500 + ANSWER 1,500 = 5,250 interactions

一条 interaction 长什么样

xᵢ = System Protocol
　 + 当前 Evidence State
　 + opened_doc_ids / remaining_turns
　 + last_tool_result / legal_action_space
yᵢ = 下一个且仅一个 assistant JSON action

同一 episode 会在 SEARCH、OPEN、KEEP、ANSWER 等多个决策点产生多条 (xᵢ, yᵢ)。因此 interaction 数通常大于 episode 数。

Loss 与泄漏控制

L_SFT = − Σₜ mₜ log πθ(yₜ | x, y<t)
mₜ = 1：assistant action/query/answer token
mₜ = 0：system/user/state/tool/retrieved text

Gold answer/evidence 可以用于构造或校验 label；但不能出现在 Policy observation。尤其 ANSWER 的 gold 文本是监督目标，不是输入提示。评测时 gold 只在服务端 sidecar 中用于打分。

为什么不能只训练 Gold：Protocol 数据中的候选由 gold 文档直接构造，适合教“正确协议”，却高估了检索环境的理想程度；Recovery 再用冻结 R4 产生真实候选和困难状态，Legal-space 阶段则消除训练动作与推理动作的分布错位。三者分别解决“会不会做”“失败后怎么走”“训练与上线是否同一套规则”。

2.4 SFT 如何评测：协议门禁与任务质量分开

严格闭环 rollout，不做 Teacher Forcing

从 held-out prompt 文件按数据集轮转取样；默认最多 16 个 tool turns、temperature=0。每一轮由当前 Policy 生成一个动作，冻结 R4 返回真实结果，Harness 更新状态，再把新 observation 交回 Policy，直至合法 ANSWER 或预算/轮数耗尽。

这测的是模型能否在自己的错误状态中继续走，而不是“给定正确前缀预测下一步”。

当前代码强制的四项 Go-Gate

四项必须同时通过，任何一项失败都禁止启动 RL。当前配置阈值：valid tool JSON ≥98%；non-empty SEARCH ≥99%；completion ≥90%；invalid doc reference ≤2%。

报告值：completion 96%，invalid doc reference 1.62%，因此通过协议门禁；这两个数字都不是答案准确率。

指标精确定义 / 分母回答什么问题不能推出什么
Valid Tool JSON能被 action schema 成功解析的 action 数 ÷ 全部生成 action 数。格式和字段是否学会。动作在当前状态一定合法。
Non-empty SEARCHquery 非空的 SEARCH 数 ÷ 全部可解析 SEARCH 数。是否避免空检索。query 能召回正确证据。
Completionharness.finished=true 的 episode 数 ÷ 全部评测 episode 数；只有 ANSWER 被 Harness 接受才算完成。能否在预算内走到合法终态。答案正确；所以 96% 不能说成 96% accuracy。
Invalid Doc Reference非法 doc 引用数 ÷ OPEN、KEEP、ANSWER 中全部 doc reference 数。非法包括：OPEN 不可见 doc、KEEP 未打开 doc、ANSWER 引用未打开 doc。协议级文档引用错误是否收敛；当前口语“非法引用率 1.62%”严格应称“非法文档引用率”。引用内容正确，或 98.38% 引用命中 gold。
Citation Validity属于 Harness legal evidence 的 citation 数 ÷ 全部 citation 数。引用是否来自机械维护的合法证据集。证据支持正确答案。
Citation Precision与 gold evidence 重合的 citation 数 ÷ 全部 citation 数；同时报告 macro / micro。引用是否正确。答案文本本身完全正确。
Answer / Evidence QualityAnswer EM/F1；Evidence Precision、Support Recall/F1，均与 held-out gold 对齐。搜索最终有没有找到并回答对。协议稳定或成本可接受。
Efficiency平均 SEARCH、OPEN、input/generated/total tokens。同质量下是否更省工具和上下文。单独优化越低越好；过度压成本会诱导早答。
答辩时按漏斗汇报：先报协议门禁（格式→动作引用→完成），再报任务质量（答案→证据→引用正确性），最后报效率（搜索/打开/token）。当前 96% / 1.62% 只证明“已经具备进入 RL 的可执行策略支持”；是否真正提升搜索能力，要看 held-out Answer F1、Support Recall、Citation Precision 与同预算基线。

证据阶段：未出现 0.0 → SEARCH 0.1 → OPEN 0.3 → KEEP 1.0

r_process,t = α · [Φ(sₜ₊₁) − Φ(sₜ)]
A_episode,j = (Rⱼ − mean_group) / (std_group + ε)
Aⱼ,ₜ = A_episode,j + β · clip(r_process,j,t, −c, c)

防止刷长度

重复 SEARCH / OPEN / KEEP 不改变势能，因此过程奖励为 0；“格式合法”本身不产生正奖励。

防止成本奖励投机

只有答案质量达标的轨迹才施加搜索/token 成本，避免策略学习“不搜、早答”。

结论边界

已证明协议可学、局部信用可产生；尚未证明 ABC-GRPO 相对 terminal-only 的最终独立增益。

OPD：从局部效用假设到能力增量蒸馏

这部分要同时讲清负结果与正结果：UA-OPD 收敛了方法边界，OPD² 提供了新的有效信号假设。

UA-OPD：局部效用加权

“Teacher 的每个局部监督都值得学吗？”

把 Student trajectory 切成 256-token segment，用 Anchor gradient 与 segment OPD loss gradient 的内积衡量局部效用，再做 Hard / Soft / SoftTraj 加权。

当前协议下无可测增益

OPD²：能力增量蒸馏

“Teacher 相对 Teacher Base 新学到的变化，是否才是有效监督？”

显式使用 post-trained Teacher 与 Teacher Base 的 log-prob 差，减少基础知识、风格和长度偏好的无差别迁移。

3.1 UA-OPD 方法与门禁

gᵢ = ∇L_OPD,segment i；g_A = ∇L_anchor
θ′ = θ − ηgᵢ
L_anchor(θ′) ≈ L_anchor(θ) − η · ⟨g_A, gᵢ⟩
Utilityᵢ = ⟨g_A, gᵢ⟩：只是一阶局部估计，不保证多步全局收益。

门禁 1 · 错误稳定性阈值

0.118

即使 192 样本，split-half cosine 仍仅 0.118；旧 0.5 门槛原理上不可达。

门禁 2 · bf16 有限差分

99.99%

ε=3e-4 时参数扰动几乎全为 no-op；ε≥0.03 后排序才恢复，正式使用 0.1。

门禁 3 · Anchor Size

≥24

8 prompts 的 utility 排名会退化为随机；24 prompts 后 Spearman≥0.94、Top-50% 重合 0.92。

高压问答

每个答案用“结论—证据—边界—下一步”组织。

Q1：RecHarness 不就是 AutoML / HPO 吗？

结论：不是固定超参空间中的标量搜索，而是代码级、结构级的预算控制系统。证据：arm 表示可解释方向，LLM 在 arm 内生成不可枚举的 patch；Bandit 只负责方向预算，Memory 负责跨轮经验。边界：仍需人定义目标和搜索边界。

Q2：为什么工业收益能归因于 Harness？

最终收益来自逐序列 Self-Attention 结构，不是 Agent 本身直接在线。Harness 的价值是让多方向证伪、Memory 和路径切换形成证据链，提高候选发现效率；归因最终仍由离线 AUC 和线上 A/B 完成。

Q3：十余个失败版本是不是浪费算力？

若失败没有改变下一轮动作，就是浪费；本轮失败簇帮助否定训练旋钮和同质 cross 两个方向，并发现特征静默失败与 HSTU 输入层级误判，最终支撑切到原始序列 item-item 交互。它们被写入 Memory 并被后续轮次消费。

Q4：EviSearch 为什么不能只把历史对话塞回 Prompt？

因为 opened/kept 若只存在自然语言中，模型可以声称看过不存在的证据，Harness 无法机械验证，也无法计算哪个动作提高了证据覆盖。外置状态把事实维护权从生成模型手中拿走，同时形成 reward instrumentation。

Q5：96% 完成率能说明 Search Agent 已经有效吗？

不能。分子是被 Harness 接受 ANSWER 的 episode，分母是全部 held-out episode；它说明协议能力达到进入 RL 的工程门槛。最终搜索能力要看 Answer F1、Support Recall、Citation Precision 和成本，并通过 terminal-only vs ABC 的同预算消融验证。

Q6：1,500 + 1,500 与 5,250 到底是什么关系？

前两个 1,500 是两个互相错开题目区间的 episode skeleton：Gold Protocol 教理想动作链，Frozen-R4 Recovery 教困难状态恢复。episode 再按每个决策点展开成 interaction，最后重算 legal_action_space 并按 SEARCH 750、OPEN/KEEP/ANSWER 各 1,500 做平衡，得到 5,250 条最终监督 interaction；不能把三个数字直接相加。

Q7：非法引用率 1.62% 的分母是什么？它等于引用错误率吗？

不等于。当前 gate 代码的指标名是 invalid_doc_reference：分子是 OPEN 不可见 doc、KEEP 未打开 doc、ANSWER 引用未打开 doc 的次数；分母是这三类动作中的全部 doc reference。它测协议引用合法性，不测是否命中 gold。后者要看 Citation Precision；ANSWER 引用未 KEEP 的句子还会被 Harness 直接拒绝，导致该 episode 不完成。

Q8：ABC 会不会让模型为了奖励一直 KEEP？

重复动作不增加势能，过程奖励为 0；只对 gold evidence 首次达到更高阶段计分，而且“格式合法”不奖励。仍需对阶段权重、α、β 和 KEEP 偏好做消融，因为任务特定 shaping 不自动保证策略不变性。

Q9：UA-OPD 为什么失败？

Base-init Student 的 on-policy 轨迹主要是错路或循环，局部加权只能重分配已有信号，不能凭空创造可学习轨迹。Wave 3 五臂在噪声带内不可区分，Wave 4 则显示 SFT/Cold-start 才显著改变 Student 分布。

Q10：负结果的研究价值是什么？

一是修正了错误 split-half 门槛和 bf16 FD 舍入；二是用 avg@48、多臂和轨迹审计否定“局部加权足以修复失败对”；三是把控制变量定位到数据分布和可恢复轨迹支持。

Q11：OPD² 提升这么大，为什么还不能下强结论？

提升覆盖五个任务，是很强的正向证据；但输出长度从约 1.7K 增到 8.8K，额外推理计算可能贡献部分收益，而且缺少同预算 Vanilla 与跨 seed 对照。因此当前支持“能力增量蒸馏假设”，尚未完成因果证明。

Q12：三个项目里你最核心的能力是什么？

不是会堆模块，而是把模糊现象变成可判定实验：RecHarness 把自由搜索拆成方向路由和 arm 内生成；EviSearch 把对话历史改成可验证状态转移；OPD 把“Teacher 更强”拆成局部效用、Cold-start 与能力增量三个控制变量。
