# 实验方案与设计目标

## 1. 研究问题与贡献边界

自主实验循环通常依据当前验证结果提出下一次修改。本研究检验：让 agent 在阶段开始前
写清实验及条件分支，在阶段中后期依据证据复盘，并按需执行归因验证，是否能改善有限
实验预算的使用。重点是**最终成果和额外归因调用的预算价值**。

三个可检验假设：

| 假设 | 对比 | 支持证据 | 不能据此断言 |
|---|---|---|---|
| H1：阶段规划与复盘改善搜索 | B−A | 相同任务上最终测试指标改善，跨独立运行报告分布 | 规划本身的独立效应；B 也增加了复盘 |
| H2：根据证据重新建立评审上下文有价值 | C−B | 相同评审节点和记录条件下，C 的成果改善 | 清空上下文在所有任务上都有效 |
| H3：按需归因值得占用优化预算 | D−C | 诊断占用同一预算后，D 的成果仍改善 | 每个归因解释正确，或每次诊断都有益 |

创新主张聚焦于可核查的事前方案、证据评审与归因预算价值的联合研究设计。
规划、外部记忆、清空上下文本身不宣称为新机制；也不预设现有方法全部属于贪心搜索。
与 Fork-and-Flush、Arbor 的关系是研究机制上的对照定位，本轮四组不包含它们的直接运行。

## 2. 任务、实验单位与预算

| 任务 | 选择目的 | 验证目标 |
|---|---|---|
| ColoredMNIST | 按研究方案作为改善机会稀疏任务 | 稀疏反馈下规划与方向评审的价值 |
| OpenOOD | 按研究方案作为改善机会稀疏任务 | 在另一个问题域检查现象是否重复 |
| Opacus | 按研究方案作为改善机会密集对照 | 持续局部优化仍有收益时，额外复盘是否浪费预算 |

这里的稀疏/密集是选题依据，不是本实验已经证明的任务性质，也不等同于已证明存在
“idea basin”。正式冻结时需核对所用 FML commit、任务版本和原论文的分类口径，
在运行前记录证据；不能根据本研究的成绩事后重分组或只保留有利任务。

- 实验单位：一条独立 agent 搜索轨迹，而非单次训练或单个阶段。
- 3 个任务 × 4 个方法 × 5 次独立运行 = **60 条轨迹**。
- 每轨迹 100 次训练/验证调用，合计 **6000 次调用上限**；正常完成时用满。
- 每轨迹结束后对验证集选中的最佳版本做一次隐藏测试，最多另有 60 次测试。
- 每轨迹 10 个阶段，每阶段 10 次调用；训练随机设置沿用任务协议。
- “5 次重复”是独立 agent 搜索，不自动等同于配对训练种子或多种子因果验证。

基线准备、数据准备、镜像构建及最终测试的成本单列。所有训练尝试，包括失败、
修复重跑、消融和重复验证，均扣除 100 次预算；原生 agent 调用失败但尚未启动训练时，
不虚构一次训练，仍计入 agent 成本。不可恢复的轨迹保留为失败单元，不补成有利样本。

## 3. 四组设计与控制变量

| 组 | 规划 | 第 8、10 次后的评审 | 第 9、10 次调用 |
|---|---|---|---|
| A：Karpathy 受控适配 | 无强制阶段计划 | 无额外阶段评审指令，持续原生会话 | 原生循环自主优化 |
| B：阶段规划 | 事前完整条件方案 | 保留历史对话，同时提供结构化证据 | 根据记录分析，执行后续优化 |
| C：规划＋清空评审 | 同 B | 两个评审节点均建立新会话，只保留研究证据 | 同 B |
| D：完整方法 | 同 B | 同 C | 解释不清且可能改变决策时验证原因，否则继续优化 |

B/C/D 在相同节点复盘；B 获得与 C/D 相同的结构化记录。A 的完整记录由框架保存，
不额外向 A 注入新方法的阶段规划和评审指令。D 以外的组仍可能在日志分析中讨论原因；
D−C 衡量的是**显式受控归因实验**，不是“有思考”与“无思考”的差别。

冻结并共享：模型明确版本、原生编码工具版本、任务起点、可编辑文件、训练协议、
固定数据划分、验证指标方向、资源与超时限制、评估后端/环境及接受规则。运行顺序按固定
种子 20261015 在各任务/重复块内打乱，减少顺序混淆。各组不能中途替换模型或调整提示。

原生 agent 负责修改文件，控制器负责执行、记账与 keep/discard；不用程序化贪心优化器
代替唯一基线。当前实现统一采用指标严格改善才接受；原 Karpathy 的“同分但更简单”
例外未自动化。因此 A 的准确名称是“Karpathy 原生 agent 循环的受控任务适配”，
不是上游仓库逐行为零修改复现。上游指令、版本和差异见 [README](README.md)。

## 4. 每阶段的完整协议

1. **事前规划。**登记瓶颈假设、主要干预机制、阶段起点、前八次实验及条件分支、
   预期观察、证伪条件和最后两次实验的条件安排。完整方案包含十个槽位，允许根据
   预先写明的观察条件选择分支，不要求忽略中间结果执行固定列表。
2. **执行前八次。**记录实际代码、精确父版本、指标、有效性和成本。方案修订保留
   旧版本、修订时间和理由，只影响尚未观察的实验。
3. **第八次后复盘。**分开记录观测事实、解释和不确定性；检查实现错误、条件漂移和
   评估波动等竞争解释。B 使用原会话；C/D 建立新会话。
4. **分配尾部两次。**D 仅在不确定解释可能影响方向决策时，安排回退、消融或配对验证。
   不能在两次调用内解决的解释标记为不确定。B/C 使用这两次调用继续优化。
5. **最终方向评审。**第十次后引用证据，决定继续、开启或重访方向，并据此制定下一
   阶段方案。B 保留会话；C/D 再次建立新会话。固定复盘节点不强迫换方向。

方向定义为“瓶颈假设＋主要干预机制”。同一机制内调整参数范围不计为方向切换。
当前方向身份依赖结构化字段，语义是否相同仍需独立盲审。

清空移除历史对话、工具讨论和旧会话目录；保留任务约束、预算、历次方案、实验事实、
明确标为解释的评审、当前最佳成果以及代码/日志引用。必要原始材料可按引用查阅，
但隐藏测试和旧会话不可见。它检验的是“以证据重建上下文”，不是抹去研究记忆。

归因候选从指定精确版本在独立副本运行；配对比较固定任务条件，repeat 不改代码。
候选仅通过统一接受规则才更新最佳版本。配对父版本一致不自动证明只改变一个因素，
仍需审查真实差异和实现正确性；两次结果也不自动排除随机波动。

## 5. 终点、机制指标与统计

**主要终点：**每条轨迹仅通过验证反馈选优，再报告该版本一次隐藏测试的任务原始指标。
隐藏测试不参与方向选择、提示词调整或实验筛选。报告全部五次运行、均值、分布与
B−A、C−B、D−C、D−A 差值；保留不利和失败单元。

跨任务汇总使用代码中明确登记的指标尺度归一化：

```text
normalized_improvement = max(0, sign × (score − baseline) / |metric_best − metric_worst|)
sign = +1（越高越好），−1（越低越好）
macro = 三个任务、全部已完成重复的归一化收益均值
```

汇总将负收益截为零，所以必须同时展示原始指标与有符号组间差值，避免隐藏退化。
这是当前报告器的显式口径；在与特定 FML 版本对齐前，不声称已完成官方评分一致性验收。
只有某组全部 15 条轨迹及其最终测试齐备时才发布该组完整宏平均。5 次重复的 bootstrap
区间用于探索性描述，不据此自动给出显著性结论；最终统计检验如需增补，必须在运行前登记。

机制与成本指标包括：

- 同次数验证改善曲线及其离散平均值（报告字段 `validation_auc`）。
- 第 51–100 次调用带来的收益及其占最终验证收益的比例；总收益为零时比例缺失。
- 每次方向决策后下一阶段的实际收益，不以切换次数代表成功。
- 无效比例、重复尝试比例、归因调用比例，以及归因前后方向决策是否改变。
- 当前重复检测只识别“同父版本＋同代码差异”的非诊断重复，不声称识别语义重复。
- 训练执行时间、整体耗时、模型输入/输出及缓存 tokens；缺失成本不填为零。

相同调用次数不等于相同 FLOPs、tokens、耗时或金额。若只有等次数优势，结论只针对
实验调用预算。不能用本设计声称同总成本更优，除非额外完成相应成本匹配分析。

## 6. 执行前验收与故障处理

- 确认新会话无法读取旧会话，却能追溯保留证据；A 不受到新方法指令污染。
- 检查训练调用启动前扣款；失败、超时、中断和诊断不返还预算。
- 检查方案、修订、归因和决策有不可覆盖的版本；证据不引用未来实验。
- 检查归因的父版本、任务条件、代码差异及独立副本；冻结 Opacus 隐私目标和数据划分。
- 验证训练/agent 无隐藏测试访问权限；最终测试使用验证选中的源码与对应检查点。
- 测试中断或状态不明时不自动重复，以免多次接触隐藏测试；保留失败状态并审计。
- 绑定数据、后端环境、源码、基线和控制器哈希；实际隔离需独立审核，配置声明不充当证明。

完整矩阵保留缺失和失败。失败率本身属于方法可靠性的结果，不能静默删除后仅比较成功
轨迹。若最后不足计划样本量，应如实报告，不能把部分结果称为完成了原定验证。

## 7. 可以写出的结论与当前状态

C 稳定优于 B，支持重新建立评审上下文的价值；D 优于 C，支持按需归因值得占用优化
预算；D 仅优于 A，支持整套流程，但不足以单独归功于归因。四组没有完整覆盖
“清空×归因”的析因设计，不估计其完整交互效应。任务间差异或无稳定收益同样保留。

**当前实现完成控制框架与离线协议测试，尚无真实 FML 实验结论。**
真实运行前仍需完成三个任务的本地评估器或验证/测试镜像适配、数据与基线绑定、原生 CLI
及执行后端集成验收和登记冻结。普通进程后端不证明文件隔离，边界见 [SERVER](SERVER.md)。
本次不启动训练。实现入口见 [README](README.md)，
评估环境见 [EVALUATORS](EVALUATORS.md)，实际检查边界见 [VERIFICATION](VERIFICATION.md)。
