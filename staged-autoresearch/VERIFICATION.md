## 已验证

- 2026-10-16，Python 3.9.6：`python3 -m unittest discover -s tests -v`，52 项全部通过（38 项协议测试＋14 项本地后端/一键入口测试）。
- A 组提示词隔离回归通过：不包含新方法的阶段规划/评审章节。
- 四组各 100 次调用的完整离线调度；所有测试响应、指标和检查点均为合成夹具。
- 阶段计划覆盖十个槽位，修订仅影响未观察实验，历史版本保留。
- C/D 评审建立新 session 和新 HOME；Docker/bubblewrap 构造仅挂载当前会话。普通进程模式不证明旧会话不可读。
- 归因只在 D 的尾部两次调用中按需安排，配对父版本一致；刻意的诊断重复不计为重复搜索浪费。
- 调用启动前持久化预扣；失败、超时和中断不退还次数；清理遗留容器的命令路径已离线验证。
- 原生 agent 失败不启动训练；源码越界和划分变更在验证前拒绝。
- 隐藏测试只接受验证选中的精确源码与检查点，失败或中断不自动重跑。
- 事件、方案、incumbent、源码与检查点篡改检查；报告不丢弃缺失/失败单元。
- 原始 program.md 与本地原仓库逐字一致，SHA256：
  `86cf987a5c381e46eefe0d0a82765223fd766d8d7acdc2afacfbbce15ecacece`。
- 本地准备检查已生成草案和矩阵：60 条轨迹、6000 次验证调用；这些带本机路径的生成文件不入库，可用 README 中的命令重建。
- 无 Docker 的真实本地子进程集成：合成原生 CLI、计划/评审、D 组 100 次调用、10 次归因、21 个会话 HOME、一次最终测试和完整报告接口。
- 同一完成轨迹再次执行，不启动任何 agent/训练/测试子进程；修改已登记评估脚本会拒绝运行。
- 进程启动门控：先持久化 PID 身份再允许执行；登记失败不开始训练。超时停止进程组与子进程，PID 复用拒绝误杀。
- CLI 的 SIGTERM/SIGINT 会进入清理路径并返回非零；SIGTERM 实际子进程终止与原信号处理器恢复已验证。
- 训练子进程不继承模型 API 密钥和 PYTHONPATH；隐藏数据/检查点未传入验证命令。
- 一键预检不冻结或调用后端；配置漂移拒绝覆盖，失败后继续保留缺失单元和逐次失败记录。

- 本机未安装 Docker，未配置 FML 源码、数据、受信任验证/测试镜像或原生 agent 镜像。
- 三个 FML 任务的可信本地评估器或评估镜像适配及隔离验收仍需在实际环境完成；接口见 EVALUATORS.md。
- 真实原生 CLI 的会话续接、结构化响应、权限和 usage 仍需固定版本的集成检查；合成 CLI 只检验接口。
- Linux GPU/bubblewrap 未做真实集成验收；当前仅离线验证隔离参数构造。普通进程模式不能声称强制文件/网络隔离。
- 草案未冻结，模型版本和环境绑定仍为空；预检按设计返回 ready=false。

因此当前交付是**经离线协议测试的研究控制框架**，不是已完成真实环境验收的实验系统。
不应把离线测试中的合成分数、耗时或调用数当成研究结果。
